# 절차적 식물 모듈 검증 기록

## 2026-10-12 · Refined 메시 추가 검증

환경: Windows, .NET SDK 10.0.401, Unity 6000.3.24f1 / URP 17.3.0.
데이터는 합성 식별자와 합성 활동 카운트만 사용했다.

- 생성기·기하·저장·성장 계약 **56,253개 통과**, 최대 **4,684 triangles**.
  12종 × 기본 변이 16개, 혼합/경계 활동 240개, 7개 목표 × 12종 성장 과정을 포함한다.
- 새 잎·꽃잎의 닫힌 외곽, 양의 부피, 법선, 수직·아래 방향에서의 유효성을 확인했다.
- `MeshVersion=2` 저장·복원 및 동일 환경에서 정확히 같은 정점·색 재생성을 확인했다.
- 메시 버전 없는 기존 v1/v2 저장본은 이전 형태를 유지한다. 변경 전 소스를
  별도 보관·실행하여 기준값을 확보했고, 기존 생성기 경로와 비교했다.
- 원래의 Linux double 바이트 해시는 변경 전 원본도 Windows .NET에서 불일치했다.
  구버전 형태의 고정 회귀 기준은 좌표·색을 1e-8 정밀도의 정수로 양자화해 비교한다.
  이 기준은 Windows .NET과 Unity Mono 모두 통과했다. 동일 런타임의 저장 복원은
  기존처럼 정점·색의 정확한 바이트 일치를 별도로 검사한다.
- 사용자가 열어 둔 편집기를 유지하기 위해 `Assets`, `Packages`, `ProjectSettings`
  사본에서 전체 프로젝트를 컴파일했다. EditMode의 식물 계약·렌더러 수명·실제 URP
  시각 검사 **3/3 통과**. 검사한 기하 소스와 현재 파일의 해시 일치도 확인했다.
- 12종 모음, 캐모마일 4/6/9/12 단계, 이전/개선/원본 Chamomile 비교를 실제 Unity로
  렌더링해 검사했다. 셰이더 지원·비어 있지 않은 화면·오류 셰이더 색상 검사도 통과했다.
  이미지는 ignored `artifacts/plant-mesh/`에만 보관한다.

이번 검증에는 Android 설치·IL2CPP 빌드·실기기 성능 측정은 포함하지 않았다.
독립 생성기와 미리보기 개선이며 기존 정원 서비스·화면 연결 범위는 바뀌지 않았다.

## 이전 v2 검증 기록

프로젝트 기준 커밋: `01d72572c2f5377404768681701ffd14ed221236`.
v2 업데이트 기준: v1 구현 `4a3339598a5cbc704d6847c7c5d8388d570171af`.
검사 환경: Linux, .NET SDK 8.0.425 / runtime 8.0.31, C# 8 컴파일러.
검사 데이터: 전부 `synthetic-*` 식별자와 합성 활동 카운트.

```text
53735 assertions passed;
baseline + 240 boundary profiles + 7 schedules x 12 species + mission transactions;
max 3130 triangles.
```

실행: `DOTNET_BIN=/path/to/dotnet python3 scripts/test-procedural-plants.py`.
Unity 런타임에서도 사용하는 `PlantGenerator`와 `PlantGeometry` 소스를 그대로
컴파일했다. Unity API를 가짜로 구현한 stub을 사용한 결과가 아니다.

통과 항목:

- 독립 Python 구현으로 확인한 길이 접두어 SHA-256 golden vector.
- 12종 모두 목표 활동 이력으로 도달 가능; ID·이력과 무관한 공통 초기 메시.
- 각 성장 단계에서 수량 단조 증가, 종 확정, 기존 잎·꽃의 목표값과 앵커 보존.
- XML 재직렬화 일치, 복원한 개체의 정점·색 데이터 일치.
- 열매 허용 종·평가 시점, 첫 꽃자리 보존, 성공·실패 결과 재추첨 방지.
- 모든 생성 메시의 실제 정점 bounds와 8,000 triangles 상한; 표본 최대 3,130.
- 한 분류 10,000회 편중 및 다양한 혼합 이력 240개가 성숙까지 진행.
- 저장 실패 시 보상·집계·성장·차감 미반영, 일일 집계 상한과 보상 분리.
- 재실행·동시 재전송 시 한 번만 차감; 요청 payload 충돌 거부.
- 성숙 식물 보존, 다음 씨앗 생성, 외부 snapshot 수정 차단, 손상·미지원 버전 거부.
- 임시 XML 파일 교체와 재로드 확인.
- 목표 6 / 7 / 12 / 28 / 48 / 56 / 91회와 12종 조합에서 정확한 목표 단계 성숙.
- 목표 1000회에서도 첫 새싹 줄기가 떡잎 부착점을 지지함.
- 목표 6 / 12 / 28 / 48 / 56회에서 인정 미션 자동 성장, 중복·하루 상한·재시작 처리.
- 여섯 번째 인정 이전 분화 대기와 누적 진행 복구; 저장 실패 후 원자적 롤백 및 재시도.
- 미션 모드 성장 비용 없음, 구매 성장 거부; 28회 구매 모드의 차감·성숙 검증.
- v2 첫 봉오리가 주 줄기 끝을 따라 이동하고, 개화 전 모든 축의 길이 성장이 종료됨.
- 진행률 50% 이후 줄기 끝·기존 꽃 위치 고정, 곁가지가 주 꽃 위로 뻗지 않음.
- 새 필드 없는 v1 XML 복원 및 v1 성숙 메시의 기존 golden fingerprint 일치.

v1 메시 SHA-256 기준값:
`9292bbabe9e73a4d2205b868fe4b5d82447de084c98ce049c778bf49c02246de`.
캐모마일 합성 개체의 정점·삼각형·색 데이터를 이전 구현과 비교한다.

캐모마일·수국·장미의 실제 생성 삼각형을 별도 도표로 렌더링하여 v1 성숙 단계와
v2 4 / 6 / 9 / 12단계를 비교했다. 이 도표는 Unity의 렌더링 결과가 아니다.

검사 과정에서 큰 종의 미래 가지가 최대 높이를 넘는 경우와 프리지아 군집의
예약 공간 부족을 수정했다. 가지의 최종 길이를 제약하고 꽃 크기를 고려한 예약
반경·높이를 사용한다. v2는 끝 꽃 배치를 위해 실제 꽃 템플릿의 외곽을 검사하며,
종별 형상과 열매의 최종 크기를 반영한다. 기존 기관을 재추첨하여 해결하지 않는다.

아직 실행하지 않은 항목:

- Unity 6000.3.24f1에서 프로젝트 전체 컴파일 및 EditMode 테스트.
- URP 셰이더 컴파일과 실제 미리보기 렌더링.
- IL2CPP, Android 저장 API·메모리 수명·프레임 시간 및 기기 화면 확인.
- Windows PowerShell 설치 스크립트 실행. patch 자체는 별도 Git 작업 트리에
  적용 전 검사와 적용 후 파일 일치 검사를 수행한다.

따라서 위 결과는 생성기·기하·상태 전이 검증이며, Unity/Android 빌드 성공이나
실측 모바일 성능을 의미하지 않는다. 기존 런타임 화면 연결은 이번 독립 구현의
범위에 포함하지 않았다.
