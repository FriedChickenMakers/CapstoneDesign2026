# 실기기 QA 전 점검 및 측정 보완 검토 — 2026-11-13

이 문서는 2026-11-13 당시의 QA 진입 조건과 추가 telemetry 제안이다. 당시 제안한 새 필드·이벤트는 미구현 상태였다. 이후 구현과 검증 결과는 [디버그 모드와 확장 측정](DEBUG_TELEMETRY_20261114.md), [A7 실기기 검증](A7_UI_TELEMETRY_REVIEW_20261114.md)을 참조한다. 개인 기기의 ID, 원시 사건, 사용 기록은 저장소에 포함하지 않는다.

## 현재 확인한 범위

- 최신 main에 병합된 guided 타이머 레이아웃은 세 버튼을 포함한 높이 146을 확보한다. 과거 높이 86 예약 방식은 작은 화면에서 `Focus.TooLong`을 가렸다. 최신 코드는 `MinimumAnswerHeight=ContentHeight`와 `KeepAnswersVisible`로 그림 공간을 조정한다.
- 기존 검사 대상 P01 / 360×640·390×844를 P01–P07 / 320×568·360×600·360×640·390×844로 확장했다. 360×600은 사용 가능한 세로 공간이 줄어든 조건이며 Android 시스템 inset 자체를 흉내 낸 것은 아니다.
- 정상·저장 실패 56조건에서 초기 scroll 위치, 세 버튼의 전체 bounds, 48 디자인 단위 높이, 중심·네 가장자리 raycast, 그림/본문 분리, 오류 안내와의 분리를 검사했다. 클릭 helper가 자동 scroll로 문제를 숨기지 않도록 별도의 초기 hit-area 검사를 사용한다. 구버전 공간 계산을 복원하면 검사가 잘림을 탐지함을 확인했다.
- 격리된 Unity Editor 통합 검사 17항목 통과. 이 검사는 실제 Android pixel density, safe area, 접근성 글꼴, OS 화면꺼짐 동작의 증거는 아니다.
- 측정 큐 계약 검사 PASS, 추천 측정 도메인 40 assertions PASS, 서버 measurement/focus measurement/app session 단위 검사 35개 PASS. 실제 APK·기기·운영 서버를 잇는 검증을 대체하지 않는다.
- 기존 20261113.1 QA APK에는 최신 레이아웃과 타이머 실행 중 화면 유지 수정이 포함된다. 이번 추가 변경은 Editor 회귀 검사와 문서이며 새로운 runtime 수정은 없다.

## 실기기 QA에 들어가기 전에

| 우선 | 점검 | 통과 기준 |
| --- | --- | --- |
| 필수 | 빌드와 데이터 기준 고정 | APK 버전·해시·소스 commit 및 미커밋 patch를 기록한다. 설치 앱 버전이 대상과 같은지 확인한다. 업데이트 전 기존 저장/등록/큐 백업, 정상 업데이트 후 기존 상태 보존을 확인한다. |
| 필수 | 검증 데이터 구분 | `live`는 전송 경로이며 실제 연구 참여를 뜻하지 않는다. 운영자 QA identity와 참여자 자료를 구분한다. 분석은 지정 설치 ID와 명시적 as-of/완료 관측 경계를 사용한다. |
| 필수 | 미션·보상 계약 | 일반 완료, 잠시 쉬기/재개, 너무 길어요 취소/확정, 미션 넘기기, 사진 선택/건너뛰기, 저장 실패/재시도를 대조한다. 필수 단계 우회·중복 보상·잘못된 추가 활동 횟수 차감이 없어야 한다. |
| 필수 | 화면 검사 방법 | 중앙 버튼 클릭만 통과 조건으로 삼지 않는다. 첫 진입의 전체 버튼 하단, 마스크 영역, footer 겹침, 모든 버튼의 실제 터치 가능 영역을 확인한다. |
| 필수 | 측정 계약 | 새 이벤트가 필요하면 수집 위치→native 큐→서버 allowlist/저장→분석기를 함께 설계한다. 현재 서버는 정확한 필드 집합을 검사하므로 임의 필드 추가는 batch 거절을 일으킬 수 있다. |

## 실기기에서 반드시 확인할 시나리오

1. P01–P07 타이머 세 버튼: 실제 기기의 gesture/3버튼 navigation, 상태 표시줄·cutout, 지원하는 글꼴/표시 크기, 저장 오류 안내에서 잘림과 터치 영역을 확인한다. 확대 글꼴이 Unity UI에 반영되는지부터 확인하고, 미지원이면 지원한 것으로 표시하지 않는다.
2. 자동 화면꺼짐: 원래 timeout보다 긴 타이머 수행 중 화면 유지, 일시정지·완료·나가기 후 복원, 수동 잠금/HOME/복귀 시 시간·실행 상태 보존을 확인한다. 타이머 테스트 동안 운영자의 임시 30분 timeout이 오류를 가리지 않도록 별도 검증 단계에서 기록한 원래 값을 사용하고 복원을 기록한다.
3. 끊김과 재시작: 오프라인 상태의 선택/시작/완료 후 연결 복구, 프로세스 종료·재시작, 서버 오류 뒤 재전송에서도 동일 event ID가 한 번만 저장되고 완료 상태·보상이 보존되어야 한다.
4. 최초 자동 등록과 기존 등록 업데이트: non-debuggable 대상 APK로 확인한다. 과거 debug probe 성공을 새 배포 APK의 성공으로 대체하지 않는다.
5. 알림: 권한 허용/차단, 실제 게시·클릭, 오래 지난 알림 클릭, 중복 클릭, 재부팅/시간대 변경, 절전 상태를 구분한다. OS 게시 수락은 사람이 실제 알림을 본 증거가 아니다.
6. 기기↔서버 대조: 알려진 시나리오별 세션 ID와 사건 순서를 확인하고, 로컬 종료 상태·대기열과 서버 수신을 대조한다. 시작만 있는 세션은 확인 전 이탈이나 누락으로 분류하지 않는다. 품질 카운터 0만으로 모든 경로가 계측되었다고 결론내리지 않는다.
7. 추천: 실제 추천 카드 노출→선택→시작→완료를 의도적으로 수행한다. 라이브러리에서 직접 시작한 미션을 추천 수락으로 세지 않는다. 추천 사건 0건은 먼저 노출 경로와 조건을 확인할 대상이다.

## 추가 telemetry 우선순위 제안

| 우선 | 최소 추가 정보 | 판단할 수 있는 것 |
| --- | --- | --- |
| 높음 | 단계/세션의 실제 누적 수행 초, 추천 초, 완료 방식(normal/too_long), 종료 이유의 제한된 enum | 짧게 수행한 것과 일시정지·백그라운드 시간을 구분하고, 사용자가 선택한 미션 축소가 어떻게 쓰이는지 분석 |
| 높음 | 미션 콘텐츠 버전, 기본/추가 역할, 진입 경로(코스/추천/직접/복습/대체) | 같은 미션 ID라도 내용·목적·노출 경로가 다른 기록을 섞지 않음 |
| 높음 | 명시적 QA/참여 데이터 구분과 필요한 경우 동의 범위 안의 가명 참여 코드 | 운영자 테스트 제외 및 설치 재등록/다기기와 사람 수 구분. 하드웨어 serial·광고 ID는 사용하지 않음 |
| 중간 | 기존 가명 방문 키와 활동 세션·알림 ticket의 명시적 연결 | 시간상 인접했다는 추정과 실제 진입 경로 연결을 구분. 연결되어도 인과 효과를 입증하지는 않음 |
| 중간 | 서버 최초 수신 시각, 대기열 나이/잔여 건수, 마지막 전송 오류 범주 | 사건 발생 시각과 전송 지연을 구분하고, 미관측과 아직 전송 중인 상태를 구분 |
| QA 전용 | 화면 ID, 사용 가능 viewport·inset, UI 배율, 잘린 control ID/bounds, OS 버전, 빌드 해시 | 화면 잘림의 재현 조건 확보. 전체 화면 이미지·일기·입력 원문을 자동 업로드하지 않음 |

기존에 있는 앱 버전, 설치별 가명, 미션 ID·선택/시작/완료 시각, 알림 예정/게시/클릭·정책, 손실/만료/저장 오류 정보는 중복 추가하지 않는다. 타이머 매초 사건은 필요하지 않으며 상태 전환 및 종료 시 요약부터 검토한다.

추가 항목을 도입할 때는 의미·허용값·deduplication 키·동의 범위·보관 기간을 먼저 정하고, native/server/분석기 호환성과 구버전 업로드를 함께 검증한다. 기능 QA 목적이면 현재 측정으로도 시작할 수 있지만, 미션 변형의 사용 양상을 발표할 계획이면 실제 수행 초와 완료 방식부터 보완하는 것이 우선이다.
