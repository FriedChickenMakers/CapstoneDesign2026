# 활동 화면의 읽기 흐름과 고정 조작부

정적인 스크린샷만으로 버튼이 스크롤 중 고정되는지는 알 수 없다. **본문과 조작부의 분리는 사용자의 명시적 요구에 따른 이 프로젝트의 구현 결정**이다. 참고 앱의 고정 스크롤 동작을 확인했다고 주장하지 않는다. 큰 영웅 이미지나 홍보 화면의 넓은 빈칸은 가져오지 않았다. 짧은 한국어 안내에서도 읽기 영역을 낭비하지 않는 것이 이번 목표다.

## 원인과 변경 구조

기존 소개·실습은 최소 1,600 단위인 전체 스크롤 페이지에 설명과 버튼을 비율로 배치했다. 실제 설명 길이와 상관없이 빈칸이 늘고, 버튼도 본문과 함께 움직였다. 실습 중 코스 보상 요약과 비슷한 의미의 목록·일시정지·종료 버튼이 경쟁했다.

새 집중 화면은 고정 제목, 본문 ScrollRect, 고정 하단 조작부를 형제 영역으로 나눈다. 본문은 글자의 실제 선호 높이로 배치하고, 안내 카드·선택지·입력 사이에 일정한 간격을 둔다. 소개·MBCT 단계·걷기·돌아보기·경험 입력·계획 입력·완료 화면에 같은 구조를 적용한다. 하단 조작부는 공통 탭 메뉴 위에 놓이며 내용의 스크롤 위치와 무관하다. 코스·복습 목록과 계획 목록도 같은 틀로 정돈하고, 긴 답변·경험 상세는 중첩 스크롤 없이 본문에서 읽는다.

[Unity 6.3의 공식 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/TouchScreenKeyboard-area.html)에 따르면 Android의 `TouchScreenKeyboard.area`는 빈 영역을 반환한다. 따라서 키보드가 열린 동안만 Android 창의 실제 가시 영역을 읽어 조작부를 올리고 선택한 입력을 본문에 드러내도록 구현했다. Editor 캡처로는 기기 키보드를 검증할 수 없으므로 실제 Android IME 검증은 별도로 기록한다.

| 상태 | 주요 동작 | 보조 동작과 의미 |
| --- | --- | --- |
| 시작 전 소개 | 시작 | 선택 취소: 시작하지 않은 선택만 취소하고 활동 목록으로 돌아간다. 참여·완료 기록을 남기지 않으며, 다른 활동을 선택할 수 있다. 저장 실패 시 소개 화면을 유지한다. |
| 실습 중 | 다음 / 실습 마치기 | 입력 단계의 건너뛰기, 이전 단계, 잠시 쉬기. 건너뛰기는 이번 활동에 자동 저장된 해당 답을 제거하고 예전 완료 활동의 선호는 유지한다. 쉬기는 입력과 진행을 저장한 뒤 쉬는 상태로 전환한다. |
| 잠시 쉬는 중 | 이어서 하기 | 오늘은 여기까지: 완료 보상 없이 참여를 종료한다. 종료 의미는 이 상태의 설명에서 분명히 안내한다. |
| 돌아보기 | 이 기록으로 완료 | 기록 건너뛰고 완료. 둘 다 완료이며 기록 여부만 다르다. |
| 경험/계획 입력 | 다음 / 기록 저장 / 저장 | 건너뛰기, 이전, 취소/돌아가기. 입력 초안과 기존 저장 실패 처리를 유지한다. |

Android 뒤로가기는 기존 단계 이동·입력 보존 정책을 유지한다. 저장 실패 시 진행하거나 종료하지 않고 입력과 오류를 남긴다. 세션 목표·보상·건강 조회의 계산은 레이아웃과 분리하며, 개인화 목표는 시작 시 고정한 도메인 값을 표시한다.

## 검증

900×1950, 900×1600, 1200×800의 합성 상태 114장을 촬영했다. 가장 긴 한국어 선택지는 최초 검토에서 잘림을 발견해, 버튼 높이를 문장의 실제 높이로 계산하도록 수정했다. 재촬영한 114장의 텍스트 오버플로는 0건이다. 소개·실습·돌아보기·코스의 스크롤 전후 하단 영역 12쌍을 원본 픽셀로 비교했으며 모두 동일했다. 확인에 사용한 상태는 MOCK·메모리 저장소로 실제 사용자 건강 기록이나 입력을 포함하지 않는다.

선택 취소를 연결한 소개·실습 15장, 실습 답변 상세 9장, 긴 경험 상세 6장을 추가 촬영했다. 30장 모두 텍스트 오버플로가 없었다. 이 추가 캡처에서는 실제 렌더 좌표로 고정 제목·본문·하단 조작부의 경계와 화면에 드러난 입력·버튼의 겹침도 검사해 통과했다.

Vision으로 원본 화면을 열어 소개·입력·긴 선택지·가로 화면·완료·설정과 정원 미리보기를 검토했다. 자동 텍스트 검사는 보이지 않는 마스킹 영역을 제외하므로 가림·위계·여백은 이 시각 검토와 함께 판단했다. 캡처와 상세 측정 자료는 무시되는 `artifacts/evolution-20261012/ui/`에만 보관한다. 기기 키보드와 최종 동작 검증 결과는 통합 검증에서 추가한다.

Unity 합성 로컬 루프 검증은 최종 31/31 통과했다. 고정 버튼의 스크롤 계층 분리, 소개 선택 취소의 실패/재시도와 다른 미션 선택, 입력→쉬기→재개 초안 유지, 종료 저장 실패, 선택 답의 건너뛰기와 과거 선호 유지, 기존 뒤로가기·완료·기록 동작을 포함한다. 추가 검토에서 발견한 백그라운드 화면 갱신의 입력 유실도 수정했다. 현재 입력을 저장한 뒤 새 상태를 읽어 렌더하며 저장 실패 시 기존 입력창을 유지한다. 자동 걷기 완료와 회고의 원자 저장 검증도 포함한다. 이는 실제 기기의 키보드·터치 검증을 대신하지 않는다.

Play mode의 fresh/restore 두 프로세스도 통과했다. 실제 EventSystem raycast로 소개의 시작·선택 취소와 본문을 아래로 스크롤한 뒤의 다음·잠시 쉬기 버튼을 검사했고, 완료·정원 성장·경험 기록·개인 계획의 저장 및 재시작 복원을 확인했다. 창이 없는 Editor에서는 정원 카메라를 중지한 뒤 새 overlay Graphic의 depth가 생성되지 않아, 캡처와 같은 명시적 RenderTexture 경로로 UI를 렌더한 후 raycast를 검사한다. 따라서 이 결과는 Unity의 버튼 입력 경로 검증이며 Android의 실제 overlay·키보드 정렬을 검증한 것은 아니다. backbuffer를 직접 렌더한 시도는 Intel Vulkan 드라이버에서 중단되어 이 경로를 사용하지 않는다. 기기 연결이 끊긴 상태에서는 실제 IME 확인을 완료했다고 판정하지 않는다.

## 최종 설정 화면 재확인

최종 앱 소스로 설정만 다시 촬영했다. 900×1950, 900×1600, 1200×800에서 기본 화면·상세 진단·심박 차트 실행 피드백의 상단/하단 18장을 확인했고, 텍스트 오버플로는 0건이다. `활동 추천 알림` 카드가 맨 위에 있으며 가속도 수집 실험은 상세 진단 안에 있다. 원본 이미지 시각 검토에서 카드 간격·글자 크기·설명과 버튼의 위계가 일관되고, 긴 진단 문장과 차트 사용 불가 안내도 다른 조작부와 겹치지 않았다. 이 결과의 기준 경로는 비공개 `artifacts/evolution-20261012/settings-final/`이며, 이전 설정 캡처 대신 사용한다.

시간 설정을 펼친 상태도 동일한 세 크기에서 상단/하단 6장을 추가 촬영해 오버플로 0건을 확인했다. 오전 9시·오후 1시·오후 8시와 확인 시간에 맞추기 옵션이 읽기 쉬운 높이로 정렬된다. MOCK의 알림 버튼 비활성은 의도된 동작이다. 임시 Editor 하네스가 비활성 버튼의 실제 펼침 콜백만 호출해 모양을 확인했으며, 실제 알림 설정·예약·권한 동작을 검증한 것으로 보지 않는다. 제품 코드에 합성 상태 진입점을 추가하지 않았고 임시 소스·메타는 촬영 후 제거했다. 하네스와 결과는 비공개 `settings-timing-final/`에 보관한다.

가로 이미지 미리보기에서 로고가 잘린 것처럼 보여 원본 픽셀과 Unity 기하를 추가 확인했다. 기본 상단/하단·진단 하단의 1200×800 이미지 상단 60px은 픽셀까지 동일하고, 시간 설정 하단도 로고 위치가 같다. 모든 로고의 픽셀 범위는 x407–480, y24–39였다. TMP rect·글리프·투영 좌표도 스크롤 전후 같아 제품 배치 문제로 판단하지 않았으며 런타임 수정은 하지 않았다. 측정 근거는 비공개 `settings-header-check/header-pixel-verification.json`에 남겼다.

## 실제 Android 키보드와 시스템 바

A7의 1200×2000 화면에서 별도 MOCK 저장 영역을 사용해 입력·본문 스크롤·고정 버튼·쉬기/재개를 확인했다. 실제 키보드 위에 입력과 다음·잠시 쉬기 버튼이 보이고, Back 한 번으로 키보드를 닫은 뒤에도 입력이 유지됐다. 쉬기/재개도 같은 초안을 유지했다. 최신 설정 카드와 상세 진단은 기기에서 검토했다. 시간 선택은 MOCK 정책상 비활성이어서 펼침 모양은 위의 Editor 검사로만 확인했다. 앱은 세로 방향으로 고정되어 가로 레이아웃 역시 Editor에서만 검증했다.

이 과정에서 키보드를 닫은 뒤 시스템 내비게이션 바가 계속 남아 앱 탭 카드 아래쪽을 가리는 실제 결함을 발견했다. `Screen.safeArea`에 해당 바가 반영되지 않아, 공통 프레임에 현재 Android 시스템 바 영역을 보완하도록 수정했다. [Android의 systemBars](https://developer.android.com/reference/android/view/WindowInsets.Type#systemBars())는 IME를 제외한다. [Unity safeArea의 Player 창 좌표](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Screen-safeArea.html)에 맞춰 window/surface 위치·렌더 스케일을 변환하고, 기존 안전 영역과 교집합을 사용하여 이미 적용된 여백이나 키보드 높이를 중복 차감하지 않는다.

Android View 조회는 UI 스레드에서 최대 초당 5회 수행하고 기존 inset listener는 유지한다. 두 Canvas는 같은 프레임의 결과를 공유하며, 포커스 복귀·회전 중 오래된 표본은 버린다. 좌표·공통 프레임 회귀 25/25, Kotlin 컴파일, Android 전용 C# 분기 컴파일을 통과했고 독립 코드 검토를 마쳤다. 수정 APK의 실기기 재검증 결과는 아래에 별도로 기록한다.

수정 APK를 A7에 데이터 유지 설치하고 APK 해시와 실행 전 환경설정·센서 기록·정원 저장 보존을 확인했다. 실제 키보드에서 Back으로 닫은 뒤에도 앱 탭 카드 전체가 시스템 바 위에 보였고, 키보드 재열기에서 여백 중복 없이 초안이 유지됐다. 홈·설정 이동과 백그라운드 복귀도 정상이다. 원본 캡처는 비공개 `artifacts/evolution-20261012/a7/ui-device-insets/`에 보존했다. 합성 MOCK 저장을 정리한 뒤 LIVE 정원 저장의 바이트 일치를 확인했으며, 화면 꺼짐·밝기·밝기 모드는 원래 값으로 복구하고 검증했다.

## 홈·정원 전체 화면 배경

후속 사용자 요청에 따라 정원 렌더를 둥근 미리보기 카드에서 홈 Canvas 전체 배경으로 확장했다. 하늘은 안전 프레임 바깥과 화면 가장자리까지 이어진다. 기존 글꼴·제목 위치·탭 정렬을 유지하고, 제목·날짜·안내와 성장 상태에는 밝은 표면을 놓아 낮과 밤 모두 읽을 수 있게 했다. 활동 안내 카드·정원 가꾸기·하단 탭도 배경 위에 남으며 설명 문구는 추가하지 않았다. 성장 표면과 활동 카드 사이에는 별도 간격을 확보했다.

섬은 상단 안내와 하단 상태 사이의 노출 영역에 맞추고, 전체 배경에는 해당 위치를 유지하는 비대칭 직교 투영을 적용한다. 태양·달도 그 노출 영역 안에 배치한다. 렌더 텍스처는 화면 비율을 따르되 긴 변을 최대 1600px로 제한하고 크기가 바뀔 때만 교체한다. 활동·설정에서는 배경과 드래그 대상을 끄고 정원 렌더를 중지한다. 구매 미리보기에서는 투영을 초기화하고 첫 렌더 전에 하늘 위치·비율을 갱신하여 홈 구도가 남지 않게 했다.

900×1950, 900×1600, 1200×800에서 낮·밤 홈, 활동·설정, 성장·환경 구매 미리보기, 구매 취소 후 홈 복귀를 합성 상태로 총 21장 촬영했다. Vision과 독립 검토에서 화면 가장자리 연결, 태양·달 노출, 섬과 UI의 분리, 밤의 글자 대비, 구매 화면과 복귀 구도를 확인했다. 캡처의 15개 검사 묶음과 레이아웃 단위 검사 20/20이 통과했다. 배경과 Canvas 네 모서리 일치, 카메라 비율, 텍스트 맞춤, 다른 탭의 비활성 배경·카메라와 수동 렌더 0회, 미리보기 취소의 미차감 상태를 포함한다.

Editor의 실제 `GraphicRaycaster`로 정원 가꾸기·세 탭의 우선순위, 밝은 표면의 드래그 차단, 노출 배경의 드래그 수신도 검사했다. EditMode에서는 EventSystem에 raycaster가 자동 등록되지 않아 각 활성 Canvas의 GraphicRaycaster를 직접 호출하고 Canvas 순서·깊이로 판정했다. 따라서 이 검사는 실제 Android 터치나 Play의 EventSystem 입력 전달을 대신하지 않는다. 원본·검사 기록·제거한 임시 하네스는 비공개 `artifacts/evolution-20261012/home-background/`에 보관하며 제품 코드에 합성 진입점을 남기지 않았다. 이 후속 배경 변경 APK의 실제 기기 검증은 별도로 기록한다.

첫 전체 배경 APK의 A7 검사에서 `Canvas.preWillRenderCanvases → Apply → Camera.Render`가 이미 실행 중인 정원 렌더에 재진입하는 오류를 발견했다. [Unity 6.3의 URP 렌더 요청 지침](https://docs.unity.com/en-us/engine/6000.3/manual/cameras/urp/multiple/user-render-requests)에 맞춰 이 콜백 연결과 배치 함수의 즉시 렌더 호출을 제거했다. 카메라 투영·렌더 텍스처 준비는 정원 하늘보다 먼저 실행되는 `LateUpdate` 및 명시적 화면 전환 갱신에서 수행한다. 렌더링 중인 텍스처를 배치 콜백에서 교체하지 않는다.

후속 Play 검사는 실제 EventSystem과 클릭·드래그 이벤트 전달을 사용하여 16/16 통과했다. SRP 렌더 도중 Canvas 크기와 경계를 강제로 바꿔도 투영·텍스처 변경이나 중첩 렌더가 발생하지 않았고 제품·SRP 오류는 없었다. 세 탭·정원 가꾸기·두 안내 표면의 드래그 차단·배경 드래그, 다른 탭의 정원 렌더 중지, 성장/환경 미리보기 취소와 홈 복귀를 포함한다. Editor 검색 인덱서의 시작 예외는 프로젝트 코드가 없는 정확한 호출 경로만 분리해 보존했으며 제품 오류 검사는 유지했다. 근거는 비공개 `artifacts/evolution-20261012/home-play/run2/`에 있다.

수정 Android APK 빌드도 통과했다. A7로 APK를 전송하던 중 무선 연결이 끊어져 수정본의 설치·기기 검증은 아직 완료하지 못했다. 설치 이전 단계에서 전송을 중단했으므로 기기에는 직전 전체 배경 빌드가 남아 있다. 이번 세션은 앱을 실행하지 않았고 사전 백업은 완료했다. 화면 꺼짐·밝기 원복도 연결 복구를 기다리며, 원래 값과 미복구 상태를 비공개 저널에 보존한다. 앞서 복구한 세션과 구분하여 재연결 후 설치·검증·설정 원복을 마친다.
