# 활동 화면의 읽기 흐름과 고정 조작부

## 공개 앱 화면 조사

2026-10-12에 공식 게시자가 공개한 실제 앱 화면을 열어 시각적으로 비교했다. App Store 이미지는 해당 게시 시점의 홍보용 화면이므로 설치된 모든 버전의 동작을 대표한다고 보지 않는다. 이미지는 저장소에 복사하지 않고 출처를 링크한다.

정적인 스크린샷만으로 버튼이 스크롤 중 고정되는지는 알 수 없다. **본문과 조작부의 분리는 사용자의 명시적 요구에 따른 이 프로젝트의 구현 결정**이다. 참고 앱의 고정 스크롤 동작을 확인했다고 주장하지 않는다. 큰 영웅 이미지나 홍보 화면의 넓은 빈칸은 가져오지 않았다. 짧은 한국어 안내에서도 읽기 영역을 낭비하지 않는 것이 이번 목표다.

## 원인과 변경 구조

기존 소개·실습은 최소 1,600 단위인 전체 스크롤 페이지에 설명과 버튼을 비율로 배치했다. 실제 설명 길이와 상관없이 빈칸이 늘고, 버튼도 본문과 함께 움직였다. 실습 중 코스 보상 요약과 비슷한 의미의 목록·일시정지·종료 버튼이 경쟁했다.

새 집중 화면은 고정 제목, 본문 ScrollRect, 고정 하단 조작부를 형제 영역으로 나눈다. 본문은 글자의 실제 선호 높이로 배치하고, 안내 카드·선택지·입력 사이에 일정한 간격을 둔다. 소개·MBCT 단계·걷기·돌아보기·경험 입력·계획 입력·완료 화면에 같은 구조를 적용한다. 하단 조작부는 공통 탭 메뉴 위에 놓이며 내용의 스크롤 위치와 무관하다. 코스·복습 목록과 계획 목록도 같은 틀로 정돈하고, 긴 답변·경험 상세는 중첩 스크롤 없이 본문에서 읽는다.

[Unity 6.3의 공식 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/TouchScreenKeyboard-area.html)에 따르면 Android의 `TouchScreenKeyboard.area`는 빈 영역을 반환한다. 따라서 키보드가 열린 동안만 Android 창의 실제 가시 영역을 읽어 조작부를 올리고 선택한 입력을 본문에 드러내도록 구현했다. Editor 캡처로는 기기 키보드를 검증할 수 없으므로 실제 Android IME 검증은 별도로 기록한다.

| 상태 | 주요 동작 | 보조 동작과 의미 |
| --- | --- | --- |
| 시작 전 소개 | 시작 | 선택 취소: 시작하지 않은 선택만 취소하고 활동 목록으로 돌아간다. 참여·완료 기록을 남기지 않으며, 다른 활동을 선택할 수 있다. 저장 실패 시 소개 화면을 유지한다. |
| 실습 중 | 다음 / 실습 마치기 | 입력 단계의 건너뛰기, 이전 단계, 잠시 쉬기. 건너뛰기는 이번 활동에 자동 저장된 해당 답을 제거하고 예전 완료 활동의 선호는 유지한다. 쉬기는 입력과 진행을 저장한 뒤 쉬는 상태로 전환한다. |
| 잠시 쉬는 중 | 이어서 하기 | 오늘은 여기까지: 완료 보상 없이 참여를 종료한다. 종료 의미는 이 상태의 설명에서 분명히 안내한다. |
| 돌아보기 | 이 기록으로 완료 | 기록 건너뛰고 완료. 둘 다 완료이며 기록 여부만 다르다. |
| 경험/계획 입력 | 다음 / 기록 저장 / 저장 | 건너뛰기, 이전, 취소/돌아가기. 입력 초안과 기존 저장 실패 처리를 유지한다. |

Android 뒤로가기는 기존 단계 이동·입력 보존 정책을 유지한다. 저장 실패 시 진행하거나 종료하지 않고 입력과 오류를 남긴다. 세션 목표·보상·건강 조회의 계산은 레이아웃과 분리하며, 개인화 목표는 시작 시 고정한 도메인 값을 표시한다.

## 검증

900×1950, 900×1600, 1200×800의 합성 상태 114장을 촬영했다. 가장 긴 한국어 선택지는 최초 검토에서 잘림을 발견해, 버튼 높이를 문장의 실제 높이로 계산하도록 수정했다. 재촬영한 114장의 텍스트 오버플로는 0건이다. 소개·실습·돌아보기·코스의 스크롤 전후 하단 영역 12쌍을 원본 픽셀로 비교했으며 모두 동일했다. 확인에 사용한 상태는 MOCK·메모리 저장소로 실제 사용자 건강 기록이나 입력을 포함하지 않는다.

선택 취소를 연결한 소개·실습 15장, 실습 답변 상세 9장, 긴 경험 상세 6장을 추가 촬영했다. 30장 모두 텍스트 오버플로가 없었다. 이 추가 캡처에서는 실제 렌더 좌표로 고정 제목·본문·하단 조작부의 경계와 화면에 드러난 입력·버튼의 겹침도 검사해 통과했다.

Vision으로 원본 화면을 열어 소개·입력·긴 선택지·가로 화면·완료·설정과 정원 미리보기를 검토했다. 자동 텍스트 검사는 보이지 않는 마스킹 영역을 제외하므로 가림·위계·여백은 이 시각 검토와 함께 판단했다. 캡처와 상세 측정 자료는 무시되는 `artifacts/evolution-20261012/ui/`에만 보관한다. 기기 키보드와 최종 동작 검증 결과는 통합 검증에서 추가한다.

Unity 합성 로컬 루프 검증은 최종 31/31 통과했다. 고정 버튼의 스크롤 계층 분리, 소개 선택 취소의 실패/재시도와 다른 미션 선택, 입력→쉬기→재개 초안 유지, 종료 저장 실패, 선택 답의 건너뛰기와 과거 선호 유지, 기존 뒤로가기·완료·기록 동작을 포함한다. 추가 검토에서 발견한 백그라운드 화면 갱신의 입력 유실도 수정했다. 현재 입력을 저장한 뒤 새 상태를 읽어 렌더하며 저장 실패 시 기존 입력창을 유지한다. 자동 걷기 완료와 회고의 원자 저장 검증도 포함한다. 이는 실제 기기의 키보드·터치 검증을 대신하지 않는다.

Play mode의 fresh/restore 두 프로세스도 통과했다. 실제 EventSystem raycast로 소개의 시작·선택 취소와 본문을 아래로 스크롤한 뒤의 다음·잠시 쉬기 버튼을 검사했고, 완료·정원 성장·경험 기록·개인 계획의 저장 및 재시작 복원을 확인했다. 창이 없는 Editor에서는 정원 카메라를 중지한 뒤 새 overlay Graphic의 depth가 생성되지 않아, 캡처와 같은 명시적 RenderTexture 경로로 UI를 렌더한 후 raycast를 검사한다. 따라서 이 결과는 Unity의 버튼 입력 경로 검증이며 Android의 실제 overlay·키보드 정렬을 검증한 것은 아니다. backbuffer를 직접 렌더한 시도는 Intel Vulkan 드라이버에서 중단되어 이 경로를 사용하지 않는다. 기기 연결이 끊긴 상태에서는 실제 IME 확인을 완료했다고 판정하지 않는다.
