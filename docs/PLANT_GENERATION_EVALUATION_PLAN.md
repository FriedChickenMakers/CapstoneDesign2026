# 식물 생성 알고리즘 평가 계획

작성일: 2026-10-14. 연구 보강: 2026-10-15. 상태: 실험 설계안. 구현 기준: `3f3eb8dff9d0fc95d48f3c0c66535af21daaba8a`; 문서 보강 시 `bf1a1b8`의 생성기와 검증 코드를 대조했다. 평가 하네스와 비교 생성기는 이 계획에 따라 별도로 구현한다.

이 계획은 활동 이력을 반영하는 절차적 식물 생성기가 사용 가능한 식물을 안정적으로 만들면서, 같은 종 안에서도 구별되는 외형을 제공하는지 검증한다. PCG Benchmark의 품질·다양성·제어 가능성을 기본 평가 축으로 채택하고, 성장 일관성·재현성·성능·지각적 품질을 추가한다. 외부 비교는 L-system을 우선하며, 활동 반영과 난수의 기여는 내부 제거 실험으로 분리한다.

기본 생성 원리는 [알고리즘 설명서](PLANT_GENERATION_ALGORITHM.md), 앱 연결 방식은 [정원 연결 문서](PROCEDURAL_GARDEN_INTEGRATION.md)를 따른다. 이하 표본 수와 계산식은 이 프로젝트의 제안이며, 인용 논문의 실험 설정과 구분한다.

## 0 중간발표에서 말할 수 있는 범위

현재는 **종별 형태 규칙과 활동 이력·고정 난수를 결합하는 생성기를 구현하고 회귀 검증한 상태**다. 저장소에 L-system 비교 생성기, 식물학적 타당성 판정 결과, 사용자 선호 비교 결과는 없다. 따라서 아래 설계를 완료한 실험이나 확인된 우수성으로 발표하지 않는다.

| 현재 근거 | 정확한 설명 | 피해야 할 해석 |
|---|---|---|
| 카탈로그 12종 | `PlantCatalog.All`의 12개 식물 모델과 대표 입력 도달 검증 | 모든 식물 종의 생물학적 생육을 재현함 |
| 설명서의 18개 제어 요소 | 종·높이·잎 배열·꽃·열매 등을 묶은 설계 요소; 상호 의존하며 종에 따라 고정되거나 적용되지 않는 요소도 있음 | 서로 독립적인 연속 변수 18개, 조합 수만큼 눈으로 구별되는 식물 보장 |
| 기존 56,253개 계약 검사 통과 기록 | [검증 기록](PROCEDURAL_PLANTS_VALIDATION.md)의 assertion 수; 같은 식물·단계·기관을 여러 번 검사함 | 서로 독립적인 식물 56,253개에서 오류율 0%, L-system 대비 성능 우수 |
| 활동 비율과 저장된 Recipe | 같은 입력·시드·버전의 재현성과 활동에 따른 형질 반응을 검사 가능 | 생체 신호로 정서 상태를 진단함, 개인화로 치료 효과가 입증됨 |

**발표용 검증 계획 한 문장:** “동일한 식물 형태와 렌더링 조건에서 L-system과 비교하여 생성 실패·형태 위반 비율, 유효한 개체의 다양성, 모바일 생성 지연을 측정하고, 방법을 가린 무작위 짝 비교로 자연스러움과 선호를 별도로 평가할 예정입니다.”

10분 발표의 본문에는 이 계획과 현재 검증 범위를 짧게 제시하고, Q&A용 보조 자료에 4·8·9절의 지표와 비교 조건을 둔다. 모든 지표를 중간발표 전에 구현하거나 결과 수치로 채울 필요는 없다. 다음 실험은 공통 형태 3개에서 baseline 실행 가능성을 먼저 확인한 뒤 확대한다.

## 1 연구 질문과 평가 범위

| 질문 | 주요 근거 | 비교 대상 |
|---|---|---|
| 정상적으로 표시할 수 있는 식물을 안정적으로 만드는가 | 품질 통과율, 오류 종류 | 전체 방식, 내부 비교군, 외부 생성기 |
| 같은 종과 같은 활동에서도 구별되는 개체가 나오는가 | 종 내부 형상 거리, 시각적 중복률 | 전체 방식 대 고정 템플릿·난수 제거 |
| 활동 구성이 외형에 영향을 주는가 | 같은 시드의 반사실적 입력 비교, 형질 방향 일치율 | 전체 방식 대 활동 항 제거 |
| 성장하면서 같은 식물의 정체성과 구조를 유지하는가 | 종·기관 보존, 부착 오차, 줄기 안정화 | 전체 방식 및 성장 지원 비교군 |
| 입체 메시 개선이 사용자에게 도움이 되는가 | 동일 Recipe의 선호·입체감과 렌더링 비용 | MeshVersion 2 대 1 |
| 실제 앱과 목표 기기에서도 유효한가 | 실제 성장 매핑, 종 분포, 지연·메모리 | 앱 연결 평가 |

활동과 식물 형질의 대응은 게임 설계 규칙이다. 이 실험은 사용자의 심리·건강 상태 추정이나 치료 효과를 검증하지 않는다. 생물학적으로 정확한 생육 시뮬레이션이라는 주장도 평가 범위에 포함하지 않는다.

### 생성기와 앱의 구분

- 생성기 평가: 합성 카운트, 시드, 성장 단계와 목표를 직접 제공한다. 현재 새 개체의 GeneratorVersion 2, MeshVersion 2, CatalogVersion 1, ProfileVersion 1을 고정한다.
- 서비스 평가: 독립 PlantGrowthService의 구매·미션 모드, 하루 집계 상한과 저장 처리를 평가한다. 생성기를 직접 진행한 결과로 서비스 규칙 통과를 주장하지 않는다.
- 앱 평가: 기존 GardenState와 GardenPlantVisuals를 사용한다. 호환용 기본 카운트 `[4,0,0,0,0,2]`와 성장 단계 `0→3→4→12`를 유지한다. 현재 앱에 개발용 목표 선택 기능이 모두 연결되어 있다고 가정하지 않는다.

앱의 호환 카운트는 실제 활동 6회가 아니다. 종별 균형 입력에서 12종에 도달하는 결과와 실제 앱의 합성 사용 시나리오에서 관측한 종 분포를 별도로 보고한다.

## 2 논문에서 채택하는 평가 원칙

Khalifa 등의 PCG Benchmark [R1]은 문제별로 품질, 다양성, 제어 가능성 함수를 정의하고, 조건 통과 비율과 개별 결과의 0~1 점수를 반환한다. 식물 문제는 기본 제공되지 않으므로 본 계획의 거리·임계값·연결 검사는 새로 정의하는 식물용 기준이다.

논문 본문 실험은 12개 문제, 10회 반복, 세대당 100개 개체, 200세대를 사용한다. Random은 새 무작위 후보와 이전 후보 중 좋은 100개를 유지하는 탐색이며, 단순 1회 샘플링과 다르다. ES와 GA도 비교하며 Q, QT, QTD는 품질, 품질 이후 제어, 품질·제어 이후 다양성을 우선하는 최적화 목적이다. 본 계획은 세 점수를 별도로 보고하며 이를 임의 가중치로 합쳐 단일 순위를 만들지 않는다.

PCG Benchmark의 새로운 문제 인터페이스는 info, quality, diversity, controllability, render 및 콘텐츠·제어 공간 정의를 요구한다 [R2]. 식물 전용 평가기는 먼저 독립적으로 구현할 수 있다. 프레임워크에 등록할 경우 입력 Recipe를 특정 생성기 전용 정답으로 삼지 않고, 공통 기관 그래프·기하 정보와 외부 생성기 어댑터를 정의한다. 문서에서 제안하는 다양성 집계는 논문 구현과 동일하다고 표시하지 않는다.

## 3 공통 기호와 결과 단위

| 기호 | 정의 |
|---|---|
| a | 생성 방식 또는 baseline |
| x | 6분류 활동 이력과 사건 순서 |
| s | 합성 개체 시드 |
| M, j, g | 목표 단계, 현재 단계, 정규화 단계 j/M |
| P | 생성된 Recipe 또는 비교 생성기의 구조 출력 |
| V | 식물 로컬 좌표의 메시 정점 집합 |
| n | 요청한 생성 시도 수 |
| F | 품질 조건을 통과한 출력 집합 |
| m | 비교 집합 F의 크기 |

시도 한 건은 `(방식, 입력 이력, 시드, 성장 설정)`으로 지정한 식물 한 개의 생성 과정이다. 전체 과정이 중간에 실패하면 이후 단계를 다른 시드로 대체하지 않는다. 단계별 결과와 식물 전체 과정 결과를 모두 보관한다. 잘못된 API 입력을 의도한 음성 테스트는 유효 입력 생성 성공률의 분모에 섞지 않는다.

공통 구조 정보에는 기관 ID, 부모 ID, 부착점, 현재 위치, 목표값, 기관 종류를 포함한다. 외부 생성기가 제공하지 못하는 필드는 N/A로 표시하고 비교 적용률을 보고한다. 서로 다른 엔진에서 얻은 원시 파일 해시나 정점 순서를 형상 다양성으로 사용하지 않는다.

## 4 품질 지표 계산

### 필수 품질 조건

| 코드 | 조건 | 계산과 판정 |
|---|---|---|
| Q1 | 생성·렌더링 성공 | 예외·시간 초과·빈 필수 출력·오류 셰이더 없이 완료 |
| Q2 | 유효 기하 | 위치·법선에 NaN/Infinity 없음, 인덱스 유효, 퇴화 삼각형 수 기록 |
| Q3 | 공간 한도 | 모든 v에 대해 sqrt(v.x²+v.z²) ≤ 0.60+ε, v.y ≤ 1.30+ε, v.y ≥ -0.001-ε |
| Q4 | 메시 예산 | 식물 전체를 삼각형으로 변환한 수 T ≤ 8,000 |
| Q5 | 기관 연결 | 뿌리를 제외한 기관의 의도된 부모 또는 명시적 밑동 지지점 존재, 부착 오차 ≤ εattach |
| Q6 | 단계 적합성 | 씨앗·분화·개화의 사전 정의 상태에 맞는 기관 존재; 완성 식물에 열린 꽃자리 최소 1개 |

좌표 단위는 프로젝트의 로컬 단위이며 미터로 해석하지 않는다. 초기 수치 여유 ε는 1e-6, 부착 오차 εattach는 1e-4 로컬 단위로 제안한다. 허용 오차는 예비 실험에서 수치 정밀도만 확인한 뒤 고정한다. 종별 외형이 좋은지 보고 완화하지 않는다.

부착 오차는 기관의 렌더링 기준점과 부모의 현재 지지점 사이 거리다. 꽃머리 중심과 줄기 사이의 의도된 꽃자루 길이를 오류로 세지 않는다. 부모·자식이 겹쳐 접합되는 메시 구조에서는 전체 식물의 단일 watertight 표면을 요구하지 않는다. 잎 조각의 닫힘 같은 템플릿 검증은 해당 조각에 한정한다.

품질 통과율과 조건별 실패율은 다음과 같다.

```text
pass_i = 1 if Q1..Q6 all pass else 0
Qpass = sum(pass_i) / n
FailureRate_k = count(attempts failing Qk) / n
TrajectoryPass = count(plants passing every required stage) / n
```

한 시도가 여러 조건을 위반하면 각 실패 항목에 중복 기록한다. 예외로 검사를 못 한 조건은 unknown으로 기록하고 Qpass에서는 실패 처리한다. 생성기 내부에서 배치 실패를 감지해 거부한 경우도 유효 입력 생성 실패다. 재시도 횟수와 비용을 숨기지 않는다.

외부 비교의 Q6은 특정 구현의 정확한 기관 수를 요구하지 않는다. 동일한 과제의 봉오리·개화 조건만 사용한다. Q5를 자동 추출할 수 없는 방식은 일부만 통과한 것처럼 집계하지 않고, 공통 자동 조건 Q1~Q4와 별도 연결 검토 결과를 나누어 보고한다.

### 교차와 시각적 결함

기관별 메시에 공간 가속 구조를 만든 뒤 비인접 기관 쌍의 삼각형 교차를 검사한다. 부모 접합부, 꽃 중심과 꽃잎의 의도된 접합, 동일 기관 내부의 허용 겹침은 고정된 제외 규칙으로 처리한다. 기관 수가 많은 식물의 단순 교차 개수는 직접 비교하지 않는다.

```text
IntersectionRate = intersecting eligible organ pairs / eligible organ pairs
VisualDefectRate = plants judged to have a severe defect / reviewed plants
```

검사 대상 쌍이 0이면 IntersectionRate는 N/A다. 단순 교차는 자연스러운 배치에서도 발생하므로 보조 지표로 사용한다. 심각한 관통·분리·잘림의 예시 판정표를 예비 실험에서 만들고, 방식 정보를 가린 두 평가자가 독립 판정한다. 이진 판정의 Cohen's kappa와 불일치 조정 전후 결과를 보관한다.

### “실존하지 않는 식물”을 측정 가능한 항목으로 바꾸기

관찰한 적 없는 외형이라는 이유만으로 생물학적으로 불가능하다고 판정할 수는 없다. 현재 생성기는 스타일화된 정원 식물이므로 다음 세 축을 섞지 않는다. 이 구분과 아래 판정 절차는 프로젝트의 평가 제안이며, PCG Benchmark가 제공하는 식물학 판정기가 아니다.

| 축 | 질문과 근거 | 보고 지표 |
|---|---|---|
| 기하·표시 유효성 | 메시가 깨지거나 공간 밖으로 나가고, 잎·꽃이 지지점 없이 떠 있는가 | Q1~Q6, 심각한 시각 결함률 |
| 종별 형태 개연성 | 지정한 식물 형태·성장 단계와 양립하기 어려운 잎 배열, 꽃 구조, 기관 연결이 있는가 | 사전에 정한 종별 형태 규칙 위반률 및 판단 불가율 |
| 지각적 자연스러움·선호 | 사람이 자연스럽다고 느끼며 자신의 정원에 두고 싶은가 | 눈가림 평정, A/B/차이 없음 선택 분포 |

형태 개연성을 평가하려면 공통 과제의 각 식물에 대해 식물학 자료와 전문가 검토로 허용 변이·성장 단계·스타일화 허용 범위를 먼저 정한다. 현재 코드의 카탈로그 범위를 그대로 정답으로 삼으면 우리 방식에 유리한 순환 평가가 된다. 판정표는 생성기와 독립적으로 작성하며, 새싹에 꽃이 없는 것처럼 정상적인 단계 차이를 위반으로 세지 않는다. 전문가 확인이 없는 경우에는 “종별 설계 규칙 위반” 또는 “비전문가가 느낀 부자연스러움”까지만 주장한다.

고정된 평가 표본의 각 식물을 두 평가자가 독립적으로 `적합 / 위반 / 판단 불가`로 판정한다. 식물마다 여러 카메라 뷰를 제공하되 한 식물은 한 관측 단위다. 위반 사유, 평가자 일치도, 조정 전후 판정을 함께 보관한다.

```text
MorphologyViolationRate = 위반으로 판정된 식물 수 / 형태 판정이 가능한 식물 수
UnassessableRate = 형태 판정 불가 식물 수 / 검토 대상으로 고정한 식물 수
```

렌더링 실패는 형태 판정에서 적합으로 처리하지 않는다. Q1 실패와 형태 판단 불가로 따로 기록하며, 형태 위반률에는 그 분모와 전체 시도 대비 평가 가능 비율을 붙인다. 생성 실패가 많아 불량 식물이 판정 대상에서 빠진 방식이 더 좋아 보이지 않도록 Qpass와 반드시 함께 제시한다. 품질 실패와 형태 위반을 합친 운영상 사용 불가율을 추가한다면 식물 단위 합집합으로 세어 중복을 제거하고, 남은 판단 불가 건도 공개한다.

## 5 다양성 지표 계산

### 비교 집합

주 다양성 결과는 같은 종, 같은 활동 카운트, 같은 목표 M, 같은 성장 단계에서 시드만 다른 집합으로 계산한다. 초기 공통 씨앗·새싹의 낮은 다양성은 설계 의도이므로 결함으로 해석하지 않는다. 기본 보고 단계는 성숙 j=M이며 분화와 중간 단계는 별도 표시한다.

종 사이 다양성은 종 도달 수와 종별 빈도로 보고한다. 종별 대표 입력을 동일 개수 제공한 표본에서의 균등 분포를 실제 앱의 다양성으로 해석하지 않는다. 평균 거리는 전체 출력과 품질 통과 출력에 대해 나누어 계산하고, 주 결과는 품질 통과 집합과 해당 Qpass를 함께 제시한다.

### 구조 거리

공통 특징은 실제 메시 높이·최대 수평 반경, 보이는 구조 축 수, 잎 단위 수, 꽃머리 수, 열린 작은 꽃자리 수, 평균 잎 표시 길이, 평균 꽃머리 표시 직경, 평균 가지 벌어짐이다. 꽃잎 조각 수를 잎 단위 수와 섞지 않는다. 외부 방식도 동일 기관 정의로 변환한다.

각 특징 k의 범위 [Lk, Uk]는 공통 과제의 허용 범위로 사전 고정한다. 카탈로그의 기관별 범위를 공통 특징으로 환산할 수 없으면 별도 교정 표본에서 범위를 정한다. 본 실험에서 방식별 최솟값·최댓값으로 따로 정규화하지 않는다. 범위를 벗어난 값과 빈 기관으로 인한 결측을 별도 기록한다.

```text
z_ik = clip((f_ik - Lk) / (Uk - Lk), 0, 1)
dfeature(i,j) = mean_k(abs(z_ik - z_jk))
Dmean = 2 * sum_{i<j}(dfeature(i,j)) / (m*(m-1))
```

상수 특징 Uk=Lk는 전체 비교에서 제외한다. 공통 측정 가능한 특징 집합을 모든 방식에 동일하게 사용한다. m<2이면 Dmean은 N/A다. 평균뿐 아니라 거리 중앙값·10/90백분위와 특징별 분포를 제시한다. 기관 수 증가만으로 다양성이 높아지는지 확인하기 위해 크기·개수·각도 특징군의 결과도 분리한다.

### 시각 거리와 중복률

512×512 정사영, 일정한 카메라 크기와 뿌리 위치, 고정 배경에서 45도 간격 방위각 8개와 고도각 20도로 이진 실루엣을 렌더링한다. 카메라는 모든 허용 형상을 담도록 한 번 설정하고 개체마다 자동 확대하지 않는다. 화분·섬·그림자는 실루엣에서 제외한다.

```text
IoU(A,B) = area(A intersection B) / area(A union B)
dsilhouette(i,j) = 1 - max_{r=0..7} mean_{v=0..7}(IoU(S_iv, S_j,((v+r) mod 8)))
```

최대값은 전역 수평 회전으로 생기는 차이를 줄인다. 45도보다 작은 회전 오차는 남으므로, 예비 실험에서 같은 식물을 0~45도 회전시킨 대조군으로 민감도를 확인하고 필요하면 모든 방식의 뷰 수를 동일하게 늘린다. 양쪽 마스크가 비면 IoU=1, 한쪽만 비면 0으로 정의한다. 정상 성숙 식물의 빈 마스크는 Q1 실패다.

```text
similar(i,j) = [dfeature(i,j) <= τfeature AND dsilhouette(i,j) <= τsilhouette]
DuplicatePairRate = 2 * sum_{i<j}(similar(i,j)) / (m*(m-1))
IsolatedFraction = count(i with no similar neighbor) / m
```

IsolatedFraction은 모든 다른 표본과 충분히 다른 개체 비율이며, 중복 제거 후 개체 수와는 다르다. m≥2이고 모든 개체가 동일한 경우 0이며, m<2이면 중복률과 IsolatedFraction 모두 N/A다. 임계값 τfeature, τsilhouette는 사람의 같은/다른 개체 판단을 이용한 교정 표본에서 선택하고 별도 검증 표본으로 확인한다. 선택 절차와 오분류율을 보고하며 본 실험 결과를 보고 조정하지 않는다. 임계값별 민감도 곡선도 함께 제공한다.

형상 다양성에는 색·카메라 회전·개체 ID를 넣지 않는다. 색 차이는 같은 조명에서의 색 통계나 사람 평가로 별도 보고한다. 품질 통과 개체가 적으면 다양성 수치와 표본 수를 함께 표시하며, 2개만 서로 다른 경우를 100개가 모두 다른 경우와 동등하게 해석하지 않는다.

## 6 제어 가능성과 활동 반영

### 성장 목표 준수

독립 서비스의 M=6,7,12,28,48,56,91,1000 및 두 성장 모드를 검사한다. 구매 모드에서는 구매 전후 단계와 정확한 1단계 증가를, 미션 모드에서는 인정 활동 수 N에 따른 목표 단계를 검사한다.

```text
expectedMissionStep = N < 6 ? min(min(M,N), ceil(M/3)-1) : min(M,N)
StepError = abs(observedStep - expectedStep)
StepPass = count(StepError == 0) / checked transitions
MaturityPass = count(Mature == (j == M)) / checked states
```

M=6에서는 여섯 번째 인정 완료가 여러 단계를 진행시키는 것이 정상이다. 하루 3회 초과, 같은 회차·미션 중복, 저장 실패, 모드에 맞지 않는 구매 요청은 성장하지 않아야 한다. 의도적으로 거부한 요청을 품질 생성 실패와 혼합하지 않는다.

### 활동에 대한 반응

종별 대표 카운트 c에서 같은 시드로 c' = c + δeA - δeB를 만든다. 총 활동 수 80은 고정한다. δ는 -8~8의 정수이며 카운트가 음수가 되는 입력은 제외한다. 15개 비순서 분류쌍을 모두 만들고, 기준 종이 유지되는 입력과 종 경계를 넘는 입력을 분리한다. 이 입력 집합은 생성 결과를 보기 전에 고정한다.

형질의 예상 방향은 다음 대응표를 따른다. 표의 A를 늘리고 B를 줄이는 δ>0은 목표값 증가 방향이다. 단일 활동 이동이 여러 대비에 영향을 주므로 다른 모든 형질이 고정된다고 가정하지 않는다.

| 평가 형질 | A | B | 비교 값 |
|---|---|---|---|
| 목표 높이 | MV | BR | Height |
| 목표 잎 수 | BD | RF | TargetLeaves |
| 목표 꽃머리 수 | SC | BR | TargetHeads |
| 상대 잎 길이 | BD | MV | 새 잎의 Length/Height |
| 상대 꽃 크기 | SC | MV | 새 꽃의 Diameter/Height |

다른 분류쌍의 경우 이 대응표의 pA-pB가 변하는 방향으로 expectedSign을 정한다. 대비가 변하지 않는 쌍과 δ=0은 방향 점수에서 제외하고 무변화 대조로 사용한다. 높이와 비율이 함께 바뀌는 절대 잎·꽃 크기에 단순 증가를 요구하지 않는다. 분모의 eligible pairs는 비교 가능한 출력 쌍이며, 생성 실패·종 변경·측정 불가로 제외한 비율을 함께 보고한다.

```text
Δf_s = f(c',s) - f(c,s)
DirectionalPass = count(expectedSign*Δf_s >= -εf) / eligible pairs
StrictResponse = count(expectedSign*Δf_s > εf) / eligible pairs
EffectMagnitude = median_s(abs(Δf_s) / (Uk-Lk))
```

εf는 부동소수 특징의 수치 허용치이며 예비 실험에서 고정한다. 정수 특징의 변화 없음은 방향 위반은 아니지만 StrictResponse에는 포함하지 않는다. 클램프나 정수화에 의한 포화 비율을 보고한다. 목표 Recipe 값과 최종 메시의 측정값에 각각 적용하여 배치 축소나 겹침 때문에 효과가 사라지는지 확인한다.

시각적 효과는 같은 시드의 활동 변경 거리와 같은 활동의 시드 변경 거리로 비교한다.

```text
ActivityEffect = median_s(dsilhouette(P(c,s), P(c',s)))
SeedEffect = median_{s<t}(dsilhouette(P(c,s), P(c,t)))
EffectRatio = ActivityEffect / SeedEffect
```

SeedEffect=0이면 비율은 N/A로 두고 두 원래 값을 보고한다. 비율이 크다는 이유만으로 우수하다고 판정하지 않는다. 활동 반응이 없거나 난수가 활동 효과를 가리는 현상을 설명하는 보조 지표다. 활동 항 제거군과 같은 입력 쌍으로 비교한다.

종 선택은 대표 입력의 기대 종 일치율과 경계 입력의 종 전이표를 보고한다. 카탈로그 거리 공식을 다시 계산한 일치는 구현 정확성 지표이며, 시각적 종 인지나 개인화의 증거로 대체하지 않는다. 분화 후 활동을 변경한 실험은 새 기관의 변화와 기존 종·기관의 보존을 평가하며 이미 확정된 높이에 반응을 요구하지 않는다.

## 7 성장 일관성과 재현성

| 지표 | 계산 | 목표 |
|---|---|---|
| 종 보존율 | 분화 이후 SpeciesId가 유지된 전이 / 해당 전이 | 100% |
| 기관 목표 보존율 | 이전 기관의 부모·목표값·앵커가 유지된 비교 / 이전 기관 비교 | 100% |
| 열매 재평가 위반율 | 이미 평가한 자리의 결과가 바뀐 횟수 / 재확인 자리 수 | 0% |
| 부착 오차 | 기관 기준점과 현재 지지점 거리의 중앙값·최대값 | εattach 이하 |
| 줄기 안정화 오차 | g≥0.5인 단계의 축 끝과 기준 단계 끝의 최대 거리 | 수치 허용치 이하 |
| 저장 복원 일치율 | 동일 환경에서 Recipe와 메시가 복원된 사례 / 복원 사례 | 100% |

줄기 안정화의 기준 단계는 ceil(M/2)다. 해당 단계 이후 같은 축의 표시 길이·끝 위치를 비교하며, 이후 줄기 두께 변화는 허용한다. 꽃의 열매 전환은 기관 소실 오류로 세지 않고 같은 꽃자리의 상태 전이로 기록한다. 분모가 없는 경우는 N/A다.

기존 기관의 구조값과 화면 좌표는 구분한다. 성장하는 부모를 따라 이동하는 것은 정상이며, 저장된 목표값 재추첨과 다르다. 급격한 변화는 연속 단계의 실루엣 거리 J_j=d(P_j,P_(j-1))로 기록한다. Δg=1/M도 함께 기록하고 목표 M별로 보고한다. 새 기관의 등장 때문에 J_j가 0일 필요는 없다. 실제 앱의 4→12 전환은 생성기의 단일 단계와 별도 평가한다.

재현성은 같은 입력 이력·시드·설정·버전에서 3회 생성, 저장 후 재실행 복원, 동작 중 무관한 다른 식물 생성 후 재생성으로 검사한다. 동일 환경에서는 정점·색·법선 순서까지 비교하고, 환경 간에는 공통 좌표 허용치와 기관 의미를 비교한다. 다른 GPU의 픽셀 해시 완전 일치를 요구하지 않는다. 저장 실패·요청 재전송은 자원과 Recipe 불변까지 별도 검증한다.

## 8 성능과 지각적 품질

### 성능 측정

목표 기기는 프로젝트에서 사용하는 Android 기기로 지정하되 공개 결과에는 모델·OS·그래픽 API만 기록한다. 시리얼과 연결 주소는 기록하지 않는다. Unity와 패키지 버전, 빌드 방식, CPU/GPU, 해상도, 품질 설정, 프레임 제한을 manifest에 고정한다.

- 콜드 실행 10회에서 초기화 포함 첫 생성 시간을 측정한다.
- 각 측정 세션에서 워밍업 20개 후 합성 개체 100개를 측정하며 독립 세션 10회를 수행한다. 순서는 방식별로 교차 배치한다.
- Recipe 계산, 메시 생성, Unity 객체 적용, 파일 저장을 각각 계측한다. 실제 사용자 요청 전체 지연도 별도 측정한다. 내부 검증이 메시를 다시 만드는 경우 포함 여부를 표시하여 중복 비용을 숨기지 않는다.
- 중앙값·p95·최대 지연, 할당 바이트, GC 횟수, 최대 메모리, 삼각형 수, draw call과 프레임 시간의 CPU/GPU 값을 보고한다. p95는 정렬 표본의 ceil(0.95n)번째 값으로 정의한다.
- 렌더링은 식물 수 1·10·50개에서 동일 장면 조건으로 10초 워밍업 후 30초씩 3회 측정한다. 추가 개체 실험은 확장성 평가이며 현재 앱이 그 수를 표시한다는 의미가 아니다.

생성 시간의 합격 예산은 예비 측정 후 목표 FPS와 UI 응답 요구에 맞춰 사전 확정한다. 60 FPS를 목표로 할 경우 전체 프레임 예산은 약 16.67ms지만 이를 생성기 단독 예산으로 사용하지 않는다. 열·전력 상태와 실행 순서를 통제한다. 자동 화면 밝기 등 기기 변경은 AGENTS.md의 원상복구 절차를 따른다.

Python L-Py와 C# 생성기의 실행 시간을 그대로 알고리즘 우열로 해석하지 않는다. 원래 실행 환경의 전체 비용을 보고하고, 공통 Unity 렌더링 비용은 출력 메시만 같은 장면에 넣어 따로 비교한다.

### 사람 평가

예비 평가 참여자 8~12명은 설문 문항과 거리 임계값 교정용이다. 본 평가 참여자는 교정 표본과 분리하고, 예비 효과 크기·참여자 간 변동을 이용해 필요한 수를 정한다. 예비 인원수를 최종 통계적 검정력의 근거로 사용하지 않는다.

| 과제 | 제시 방식 | 계산 |
|---|---|---|
| 자연스러움·형태 완성도 | 같은 종·단계, 방식 이름을 가린 정지 화면 | 1~7점 분포와 방식 간 짝차이 |
| 개체 구별 | 같은 종의 두 개체, 동일 렌더링과 동일 개체 대조 포함 | 다른 개체 탐지율·동일 개체 오탐률 |
| 성장 인지 | 시작·중간·완성 순서 또는 동일 길이 성장 영상 | 순서 정답률, 같은 식물로 느끼는 정도 |
| 입체 메시 효과 | 동일 Recipe의 MeshVersion 1/2 쌍 | 입체감·선호, 무승부를 포함한 선택 비율 |
| 활동 반영 인지 | 규칙을 동일하게 설명한 뒤 활동 이력과 결과 비교 | 대응 정답률과 이해도; 시각 선호와 분리 |

방법 이름과 좌우 위치는 무작위화하고, 순서 효과를 상쇄한다. 모든 조합을 한 사람에게 보여주지 않고 균형 잡힌 부분집합을 배정한다. 종 인지는 필요한 경우 공통 참고 이미지를 제공하며, 비전문가의 식물 지식을 생성 품질과 혼동하지 않는다. 실패 결과를 사람 평가에서 제외하면 제외율을 Qpass와 함께 보고한다. 극단적으로 나쁜 표본만 임의로 숨기지 않는다.

L-system과의 시각 선호 주 비교도 위 절차를 적용한다. 같은 과제·성장 단계의 출력 쌍을 참가자 안에서 비교하고, “더 자연스러운가”와 “정원에 두고 싶은가”를 별도 문항으로 묻는다. A/B/차이 없음은 모두 응답 수를 분모로 보고하며, 차이 없음을 빼고 계산한 승률만 제시하지 않는다. 개발자가 고른 예쁜 표본 대신 미리 고정한 평가용 시드에서 표본을 추출하고, 방법 이름·활동 이력 설명 등 선호를 유도할 정보는 가린다. 참가자가 시각적 특징으로 방법을 추측할 가능성은 남으므로 완전한 눈가림을 보장한다고 표현하지 않는다.

참가자 내 짝 비교는 개인별 취향 차이를 줄이고 적은 표본으로 외형 차이를 평가하기 좋지만 비교 자체가 주의를 유도한다. 실제 앱에서 애착·재방문·활동 수행이 달라지는지를 주장하려면 참가자를 방식별로 무작위 배정하는 독립군 실험을 별도로 계획한다. 독립군은 일상 사용에 가깝지만 더 많은 참가자와 관찰 기간이 필요하다. 단시간 선호 결과를 지속 사용이나 증상 개선의 증거로 바꾸지 않는다. 편의 표본의 결과는 그 표본에 한정하며, “대중” 또는 주 사용자층 전체의 선호로 일반화하지 않는다.

본 실험 표본 수는 예비 효과 크기만 그대로 믿고 정하지 않는다. 검출하려는 최소 선호 차이와 참가자·식물 간 변동을 사전에 정하고 표본 수 민감도를 확인한다. 실험 종료 시점, 제외 기준, 주요 문항을 결과 확인 전에 고정한다.

## 9 Baseline 구성

### 내부 비교군

| 이름 | 정확한 변경 | 유지하는 요소 | 해석 |
|---|---|---|---|
| Full | 현행 전체 알고리즘 | 전체 | 주 평가 대상 |
| Fixed | 종별 고정 합성 시드와 대표 카운트로 만든 한 성장 궤적을 재사용 | 종별 형태, M별 성장 일정, 메시 버전 | 같은 종 내부의 고정 외형 기준 |
| NoActivityTraits | Z 식의 0.6(pA-pB)만 0으로 변경 | 종 선택, 성장 집계, 모든 U, 형질 범위·배치·검증 | 종 내부 활동 항의 효과 |
| NoMorphRandom | 형질·기관 구조·색·열매에 쓰는 U를 0.5로 고정 | 활동 항, 종 선택의 원래 동률 처리, 성장·검증 | 종 내부 난수 변이의 효과 |
| Mesh1 | 동일한 유효 Recipe 복사본의 MeshVersion만 1로 렌더링 | 성장·종·기관·시드·카메라 | 기하 표현만 비교 |

현재 Z = clip(0.5 + 0.6(pA-pB) + 0.2(2U-1))다. NoActivityTraits는 활동을 전부 삭제하는 방식이 아니다. 활동은 종과 성장에 계속 사용되므로 종 내부 비교로 한정한다. NoMorphRandom은 Z 내부뿐 아니라 가지 길이·방위 편차·잎 배열·색 편차·열매 추첨 등 직접 U 호출도 포함한다. 전역 U 함수를 무조건 바꾸어 종 동률 처리까지 바꾸지 않는다.

NoMorphRandom의 열매 결과는 확률적 분포를 재현하지 않는다. 해당 비교는 난수가 외형 다양성에 미치는 영향으로 해석한다. Fixed는 시드별로 다른 템플릿을 고르면 안 된다. 종 선택 과제에서는 동일한 공통 종 선택기를 사용하고 종 내부 외형만 고정한다. Mesh1의 구버전 성격을 유지하기 위해 성장 버전을 변경하지 않는다.

실험용 옵션은 별도 하네스 또는 실험 구현에 두며 실제 앱의 기본 동작이나 기존 저장 버전을 바꾸지 않는다. 각 비교군이 예정된 항목만 바꾸는 단위 검사를 먼저 작성한다. NoActivityTraits의 입력 변경 불변성은 종·성장 일정을 고정한 형질에 대해서만 요구한다.

### 외부 비교군

L-system 역시 절차적 생성 방식이다. 비교 이름은 “L-system 대 procedural generation”보다 **“매개변수·확률적 L-system 구현 대 종별 형태 규칙·활동 이력 기반 생성기”**가 정확하다. L-system은 규칙의 병렬 재작성과 기하 해석을 사용하는 모델링 형식이며 [R8], L-Py는 매개변수·확률 규칙과 별도의 기관 기하를 지원한다 [R4]. L-system이라는 이름만으로 자연스러움·다양성·속도를 결정할 수 없으므로 사용한 문법, 매개변수, 메시 생성 방식이 실제 비교 대상이다.

| 우선순위 | 후보 | 구성과 비교 범위 | 제약과 근거 |
|---|---|---|---|
| 1 | 매개변수·확률적 L-system / L-Py | 공통 대상의 문법·종료 규칙·기관 매개변수를 고정하고 성장 단계·시드별 결과 생성 | L-Py는 프레임워크이므로 문법 자체를 baseline과 함께 공개 [R4] |
| 2 | ngPlant | 공통 식물 모델·가지 계층·매개변수 범위를 고정하고 시드별 완성 형상 생성 | 성장 궤적을 제공하지 않으면 성숙 외형·제어·성능만 비교 [R5] |
| 3 | Space Colonization / tree-gen | 동일 공간의 유인점 배치, 영향·제거 거리와 길이 제한으로 구조 생성 | 나무 중심이므로 가지 배치·공간 충족 평가가 주 목적 [R6] |
| 선택 | Weber–Penn / Sapling | 나무 형태 과제를 별도 구성할 때 사용 | 초본·꽃의 주 비교군으로 강제하지 않음 [R7] |

외부 주 실험의 초기 대상은 캐모마일형 방사상 꽃, 라벤더형 꽃이삭, 캄파눌라형 종꽃의 세 형태로 제안한다. 해당 공개 구현에 이 세 종의 완성 모델이 이미 있다고 가정하지 않는다. 예비 구현에서 동일 과제를 지원하는지 확인하고, 지원하지 못하는 형태는 본 실험 전에 제외 이유와 최종 공통 과제를 고정한다. 공간·기관 예산·모델 조정 시간은 모든 방식에 동일한 규칙을 적용한다.

구조 비교에서는 같은 잎·꽃 기하와 재질을 공유하고 구조 생성만 바꾼다. 전체 파이프라인 비교에서는 각 방식의 원래 기하를 허용하되 같은 렌더링 조건과 8,000개 예산을 적용한다. 초과 후 단순화가 필요하면 모든 방식에 적용 가능한 동일 후처리 조건을 정하고 원래·후처리 결과와 비용을 모두 기록한다.

활동 입력이 없는 외부 방식에 활동 제어 점수 0을 주지 않는다. 고유 기능은 N/A로 보고한다. 활동 입력 비교를 추가하려면 공통 활동→목표 형질 변환기를 제공한 별도 실험으로 정의하고, 변환기 학습·조정 데이터와 비용을 공개한다. 공통 목표 높이·꽃 수를 직접 받는 실험도 현행 앱 기능 평가와 별도로 구분한다.

### 선택적인 탐색 baseline

PCG Benchmark의 Random Search·ES·GA [R3]는 식물 매개변수 또는 문법 매개변수를 탐색하도록 추가할 수 있다. 비교하려면 동일 표현 공간, 동일 품질·제어 평가 함수, 고정된 목표 집합이 필요하다. 개인별 목표를 더 쉬운 것으로 바꾸며 생존시키지 않는다.

단순 무작위 1회 생성과 best-of-N 무작위 탐색을 구분한다. 탐색에는 예비 설정으로 100·1,000·10,000회 평가 예산을 주고 품질·제어·시간 곡선을 보고한다. 직접 생성은 1회 결과와 같은 시간 내 생성 가능한 수를 보고한다. 실패·재시도·후처리도 예산에 포함한다. 탐색까지 포함한 연구 범위가 필요한 경우에만 도입하며 최초 필수 비교군은 아니다.

## 10 실험 입력과 반복 조건

### 핵심 생성 실험

| 항목 | 고정 조건 |
|---|---|
| 종 입력 | 카탈로그 12종의 ExampleCounts: 주 분류 48, 보조 20, 나머지 각 3, 합계 80 |
| 시드 | 종별 100개; 독립 묶음 10개 × 묶음당 10개 |
| 성장 설정 | M=12,28,56 각각; 구매 모드의 순수 생성기를 직접 진행 |
| 카운트 투입 | 첫 Advance 전에 80개 카운트를 설정하고 전체 단계에서 고정 |
| 단계 | 수치 검사는 j=0..M 전체, 정지 화면은 0, ceil(M/3), ceil(M/2), ceil(3M/4), M |
| 기본 표본 수 | M당 1,200개, 3개 M 합계 방식당 3,600개 성장 궤적 |
| 4개 핵심 방식 | Full, Fixed, NoActivityTraits, NoMorphRandom: 총 14,400개 궤적 |

이 실험은 완성 형상과 성장 구조를 통제해서 비교하기 위한 것이다. 서비스로 80회 완료를 먼저 처리한 뒤 미션 모드가 성장하지 않았다고 가정하지 않는다. 미션 모드와 실제 사용 이력은 별도 실험이다.

합성 ID는 `synthetic-eval-owner-{batch}`와 `synthetic-eval-plant-{index}` 형식으로 지정하고 전체 manifest를 고정한다. 같은 입력 번호를 모든 방식에 짝지어 제공하되 서로 다른 RNG 구현이 같은 난수열을 만든다고 가정하지 않는다. 파일럿과 본 실험의 ID 집합은 겹치지 않게 한다.

Mesh1 비교는 Full의 유효 Recipe를 재사용하며 추가 독립 식물로 세지 않는다. 외부 방식은 확정된 공통 3형태 × 100시드 = 방식당 300개 성숙 출력으로 시작한다. 성장 지원 방식만 동일 M 및 정규화 단계로 확장한다. L-system의 재작성 횟수와 앱 구매 횟수를 동일하다고 가정하지 말고 단계 대응을 사전에 정의한다.

### 경계와 편중 입력

M=28, 입력당 10시드로 다음을 추가한다.

- 6개 단일 분류에 각각 80회를 배정: 60개 궤적.
- 균형 카운트 `[14,14,13,13,13,13]`의 6개 순환 이동: 60개 궤적.
- 종 ID를 사전순 정렬해 인접 두 종씩 묶은 6쌍의 대표 카운트를 α=0.05,0.10,...,0.95로 혼합: 114개 입력 × 10시드 = 1,140개 궤적. 정수화는 내림 후 소수 잔여가 큰 순서로 합계 80까지 배정하고 동률은 분류 인덱스 순서로 처리한다.

합계는 방식당 1,260개 추가 궤적이다. 경계 입력의 종 전이와 거부율을 따로 보고하고 대표 입력 결과와 섞어 평균만 제시하지 않는다. 활동 반응 실험의 δ 입력은 6절의 규칙으로 별도 manifest를 만든다.

### 서비스와 앱의 이력 실험

독립 서비스에서는 6절의 모든 M과 두 모드를 검사한다. 대표 프로필 비율 w는 ExampleCounts/80으로 정의한다. t번째까지의 카운트 c_t에서 `(t+1)w_k-c_tk`가 최대인 분류를 다음 활동으로 고른다. 동률은 분류 인덱스 순서로 고정한다. 합성 일일 주기는 3개 인정 활동마다 바꾸고 미션 ID는 유효한 별도 합성 ID를 사용한다. 서비스 정상 궤적은 설정·프로필당 10시드로 시작하며, 실패 주입은 별도 테스트 행렬로 집계한다.

정상 궤적과 함께 중복 완료, 하루 상한 초과, 저장 실패 주입, 분화 전후 활동 전환, 완료 후 추가 활동을 분리한다. 같은 최종 카운트의 앞부분·뒷부분 순서를 바꾼 이력도 포함한다. 구매 모드는 분화 전 최소 카운트 조건을 충족하도록 일정을 명시하고 충분한 합성 영양제를 공급한다. 비용·보상 검증에서는 실제 정책을 우회하지 않는다.

앱 실험에는 실제 TryCategory가 인식하는 미션 ID와 완료 상태·회차를 사용한다. 구매 간 인정 활동 0·3·6·12개 시나리오를 만들며, 3개를 넘는 경우 여러 일일 주기로 분산한다. 앱에 존재하는 미션 목록에서 분류별로 선택한 시나리오를 고정하며 존재하지 않는 분류를 임의 ID로 채우지 않는다. 실제 개인정보는 사용하지 않는다.

앱의 종 빈도, 기본 프로필 포함/제외 시의 반사실적 차이, 4→12 단계의 외형 변화, 저장 재실행·취소 복원을 보고한다. 기본 프로필을 제거한 실험은 별도 진단이며 실제 앱 조건과 합쳐서 보고하지 않는다.

## 11 통계 분석과 공정성

- 주 비교는 Full 대 NoMorphRandom의 종 내부 시각적 중복률, Full 대 NoActivityTraits의 활동 효과, 동일 Recipe의 Mesh2 대 Mesh1 선호로 사전 지정한다. 품질·시간·성장 불변 조건은 함께 보고하는 필수 결과다.
- 10개 시드 묶음의 결과를 먼저 계산하고 12종은 동일 가중치로 평균한다. 단계와 같은 식물의 다중 뷰는 독립 표본으로 세지 않는다.
- 짝지은 방식 차이에 대해 묶음 단위 bootstrap 10,000회로 95% 신뢰구간을 계산한다. 종별 결과는 해당 종의 묶음을 재표집한다. 동일 시드 묶음의 입력·단계는 함께 이동시킨다. 재표집 RNG 시드도 기록한다.
- 다양성 거리의 모든 개체 쌍을 독립 관측치로 검정하지 않는다. 묶음별 거리·중복률을 기본 통계량으로 사용하고, 전체 100개 집합의 결과는 기술 통계로 병기한다. 표본 수 변화의 영향을 막기 위해 모든 방식의 요청 수를 동일하게 한다.
- 참가자 설문은 참가자와 자극 식물의 반복 관측을 반영하는 혼합효과 모형 또는 두 수준 재표집을 사용한다. 이진 선호와 서열 척도를 동일한 연속 정규 자료로 무조건 처리하지 않는다.
- 사용자 선호의 재표집은 참가자와 자극 식물의 교차 의존성을 반영한다. 한 참가자의 여러 응답, 한 식물의 여러 평가자·각도·단계를 독립 표본으로 늘리지 않는다. 참가자만 재표집한 신뢰구간이라면 결론이 제시한 식물 집합에 조건부라는 한계를 명시한다.
- 실패가 0건인 표본에서도 모집단 실패율이 정확히 0이라고 주장하지 않는다. 독립 식물 단위의 이항 실패율에는 Wilson 또는 정확 이항 구간을 보고하고, 같은 식물의 반복 단계가 섞인 자료에는 식물 단위 집계 또는 군집을 반영한 방법을 사용한다. 모든 값이 같은 bootstrap 표본의 0폭 구간을 무오류 보장의 근거로 쓰지 않는다.
- 다중 가설 검정에는 사전 지정한 주 비교 묶음에 Holm 보정을 적용한다. p값뿐 아니라 짝차이, 효과 크기와 신뢰구간을 보고한다. 실패한 가설도 동일하게 남긴다.
- 내부 검증기를 그대로 호출한 합격만으로 품질을 증명하지 않는다. 별도 평가 코드가 실제 메시의 bounds·삼각형·부착을 다시 측정하고, 수동 결함 표본과 불일치를 검토한다.

외부 방식은 문법·모델 제작에 사용한 시간, 교정 표본 수, 매개변수 탐색 예산을 기록한다. 평가 집합으로 반복 조정한 뒤 최종 성능만 제시하지 않는다. 과제·지원 종·메시 예산이 다른 실험을 한 순위표로 합치지 않는다.

## 12 예비 실험과 실행 순서

1. 구현·문서 버전, baseline 변경점, 외부 코드 commit·라이선스를 고정한다. 원본 비교 구현의 실행 가능성과 모델 출력을 확인한다.
2. 별도 합성 시드로 방식별 소규모 표본을 만들어 기관 어댑터와 평가 코드의 오류를 점검한다. 숫자 허용치, 특징 범위, 카메라와 시간 초과 기준을 확정한다.
3. 교정용 사람 판단으로 중복 거리 임계값을 정하고 별도 교정 검증 집합에서 확인한다. 렌더링 조건과 동일 개체 회전 대조를 함께 점검한다.
4. 공통 외부 식물 과제, 주요 지표, 시드 목록, 통계 절차와 실용적 성능 예산을 manifest에 확정한다. 이후 변경은 이유와 영향 범위를 새 버전으로 기록한다.
5. 내부 생성·경계·활동·서비스 실험을 실행한 뒤, 확정된 외부 비교를 실행한다. 오류는 시드를 바꾸어 숨기지 않는다.
6. 목표 기기 성능과 실제 앱 연결을 검사하고, 별도의 본 사람 평가를 수행한다.
7. 모든 실패와 N/A를 포함한 표·분포·대표 표본을 공개 가능한 형태로 정리한다. 대표 이미지는 미리 정한 ID 또는 중앙값 사례를 사용하고 좋은 결과만 고르지 않는다.

예비 단계에서 확정할 항목은 τfeature·τsilhouette, 특징 범위, εf, 심각한 결함 판정표, 지원 외부 형태, 생성 시간 제한, 실용 성능 예산, 본 사람 평가 표본 수다. 수치 조건 통과율의 설계 목표는 100%지만 유한한 표본의 100%가 모든 입력에 대한 보장은 아니다. 다양성과 선호에는 사후 합격선을 만들지 않고 비교 효과와 불확실성을 보고한다.

## 13 기록 형식과 산출물

비공개 원자료와 캡처는 ignored `artifacts/plant-evaluation/`에 보관한다. 공개용 합성 입력 manifest, 평가 코드, 집계 결과만 개인정보 검토와 저장소 검사를 거쳐 버전 관리한다. 외부 PDF·코드·텍스처를 출처와 이용 조건 확인 없이 복사해 배포하지 않는다.
