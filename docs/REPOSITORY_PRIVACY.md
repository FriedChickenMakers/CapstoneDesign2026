# 저장소 개인정보·비밀정보 점검

현재 파일에서 개인정보와 비밀정보를 제거하고, 검증한 변경을 커밋한 뒤 현재
작업 브랜치의 upstream에 일반 push한다. 이 절차는 `AGENTS.md`에 상시 지침으로
기록되어 있다. 별도 요청 없이 기존 Git history를 수정하거나 force push하지 않는다.

## 실행

Python 3와 Gitleaks가 필요하다. Gitleaks는 PATH에 설치하거나 `GITLEAKS_BIN`으로
지정한다. 이번 점검은 공식 Gitleaks v8.30.1 배포 파일을 공식 체크섬과 대조한 뒤
사용했다. 이 작업공간의 실행 파일은 Git에서 제외된
`artifacts/privacy-tools/gitleaks`에 있다. 다른 환경에서는 공식
[Gitleaks 배포 페이지](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1)에서
해당 환경용 실행 파일과 체크섬을 받아 검증한다. 인증정보를 다운로드 명령이나
문서에 직접 넣지 않는다.

```bash
export GITLEAKS_BIN="$PWD/artifacts/privacy-tools/gitleaks"
python3 scripts/check-repo-privacy.py
git diff --check
# 검토한 파일만 명시하여 git add 후:
python3 scripts/check-repo-privacy.py --staged
# 적절한 기능 검증 후 commit, 현재 브랜치에 일반 push, 원격 HEAD 일치 확인
```

기본 검사는 추적 파일과 ignore되지 않은 새 파일을 검사한다. `--staged`는 작업
파일 대신 index의 실제 내용을 검사하므로, stage 이후 파일을 수정한 경우에도
커밋될 내용을 확인한다. Gitleaks와 저장소 전용 규칙을 함께 사용하며 누락된 검사
도구나 실행 오류는 실패로 처리한다. 출력에는 발견 위치와 분류만 표시하고 원문
비밀값은 표시하지 않는다. 검사 중 만든 복사본과 상세 결과는 임시 디렉터리에만
두고 종료 시 정리한다.

## 사람이 함께 확인할 항목

- 비밀번호, 토큰, 인증 URL, 서명 키와 로컬 계정 설정은 환경변수나 외부 비밀
  저장소로 분리한다. 실제 기기 주소·serial은 문서에 적지 않고 `ADB_SERIAL`을 쓴다.
- 건강 수치, 센서 원본, 참여 기록, 자유 입력, 앱 저장 데이터, 로그와 기기 화면은
  `artifacts/` 또는 저장소 밖의 비공개 위치에 둔다. 문서에는 비식별 요약이나
  명시적인 합성 예시만 남긴다. ignore된 파일도 강제로 추가하면 공개될 수 있다.
- 이미지, 바이너리 메타데이터, 문장 속 이름과 사생활 정보는 정규식만으로
  확인할 수 없다. 변경 파일과 outgoing commit을 직접 검토한다.
- 공개된 폰트·라이브러리의 저작권 및 라이선스 표기는 유지한다. 팀 내부 문서의
  비공개 URL 대신 안정적인 내부 출처 ID와 자료명을 사용한다.
- 실제 유효한 인증정보가 발견되면 제거와 별도로 폐기·교체 필요성을 알린다.
  현재 파일 삭제만으로 기존 인증정보가 무효화되지는 않는다.
- 기기 설정 복구 journal과 조사용 원본 backup은 삭제하지 않는다. 비공개로
  보관하면서 기존 복구·보존 절차를 따른다.

## 2026-10-08 점검

전체 추적 파일을 대상으로 비밀정보 검사와 코드·문서·설정 검토를 수행했다.
기존 원시 로그와 기기 백업은 ignore된 `artifacts/`에 있고 추적되지 않는다.
현재 파일에서 유효한 인증정보를 발견하지 못했으며 다음 항목을 정리했다.

- 문서의 실제 무선 ADB 주소와 내부 Notion 페이지 식별자를 변수·출처 ID로 대체.
- 기기별 정확한 센서 시각·방향·가속도 수치를 제거하고 수집 품질 요약 유지.
- 수집 스크립트의 serial 메타데이터를 가림 처리.
- 소스 archive를 Git에서 관리할 수 있는 파일로 제한하여 ignore된 비공개
  파일과 symlink 대상이 섞이지 않도록 수정.
- 비밀 키·기기 원본 데이터 ignore 규칙과 반복 가능한 검사 명령 추가.

기존 history와 비공개 조사 원본은 보존했다. 자동 검사의 통과는 모든 종류의
개인정보 부재를 보장하지 않으므로 이후 변경에도 위 수동 검토를 반복한다.

검증: Gitleaks v8.30.1 및 저장소 규칙으로 공개 대상 591개 파일 검사 통과,
검사 도구 회귀 테스트 15개 통과, MBCT 콘텐츠 검증 683개 항목 통과. 격리된
임시 저장소에서 가짜 토큰 탐지·원문 출력 억제, index와 작업 파일의 차이,
강제 추가한 비공개 파일 차단, 도구 실패 시 중단을 확인했다. 소스 archive는
ignore 파일·symlink 제외와 호출 디렉터리에 관계없는 프로젝트 검사를 확인했다.
