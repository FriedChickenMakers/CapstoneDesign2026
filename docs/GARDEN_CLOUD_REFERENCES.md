# 정원 하늘과 안개 참고

2026-10-12 수정. 사용자가 요청한 형태는 섬 주변의 반투명 안개·연기다. 이전 적운 윤곽과 세 개의 수평 이동 줄은 이 구현에서 제거했다. 사진이나 외부 텍스처를 앱 자산으로 복제하지 않았으며, 밀도 텍스처는 코드가 생성하는 원본 데이터다.

## 공식 참고 자료와 적용 범위

- [Unity의 3D 텍스처 소개](https://docs.unity.com/en-us/engine/6000.0/manual/materials-and-shaders/textures/class-texture3d/introduction): 안개·연기처럼 공간에 퍼진 밀도를 3차원 좌표로 샘플링하는 용도다. 정원은 작은 주기적 밀도 볼륨을 사용한다.
- [Unity Local Volumetric Fog](https://docs.unity.cn/Packages/com.unity.render-pipelines.high-definition%4013.1/manual/Local-Volumetric-Fog.html): 국소 밀도와 이동하는 3D 마스크라는 원리를 참고한다. 프로젝트는 URP를 유지하며 HDRP의 체적 광선 적분 기능을 도입한 것은 아니다.
- [Unity Particle System Noise](https://docs.unity3d.com/6000.3/Documentation/Manual/PartSysNoiseModule.html): 낮은 주파수의 부드러운 난류와 제한된 octave 비용을 참고한다. 정원은 합성 캡처와 실행 시 같은 위치를 재현하도록, 시간에 따른 작은 curl 변위를 직접 계산한다.
- [Unity Skybox](https://docs.unity3d.com/6000.3/Documentation/Manual/skyboxes-using.html): 하늘 방향은 세계 좌표에 고정한다. 태양과 달을 화면의 특정 위치에 계속 노출시키는 보정은 사용하지 않는다.

## 하늘 방향

Sky shader는 native skybox의 세계 방향과 `SolarDirection`의 내적으로 태양·달 원반을 그린다. 카메라 yaw/pitch에 따라 일반 하늘처럼 이동하고, 뒤를 보거나 시야 밖을 보면 원반이 보이지 않는다. 화면 UV, 화면 경계 clamp, 카메라 오른쪽 방향을 화면 좌표로 재매핑하던 경로는 제거했다. 방향광 역시 같은 방향을 쓰며 낮은 태양의 높이를 임의로 올리지 않는다.

Unity의 직교 카메라 skybox는 정사각형 각도 범위를 렌더 대상으로 펼친다. 이 때문에 정사각형 캡처에서는 원이지만 세로·가로 화면에서는 원반이 타원으로 변하는 결함을 실제 렌더로 재현했다. 직교 경로에 한해 하늘 방향을 카메라 공간으로 회전하고 수평 광선에 최종 표시 비율을 적용한 다음 세계 방향으로 복원한다. 별도의 원반 위치나 화면 고정 좌표를 사용하지 않는다. 비율은 RT 크기가 아니라 `camera.aspect`다. 동일한 RT를 다른 비율의 `RawImage`에 표시하는 카드도 올바르게 보정한다.

최종 표시 비율은 해당 정원 카메라의 `beginCameraRendering`에서 전용 sky material 값으로 전달한다. 콜백은 재료의 숫자 하나만 바꾸며 렌더·RT 교체·카메라 투영 변경을 하지 않는다. 초기화와 재활성화의 구독은 중복되지 않고 비활성화·제거 시 해제한다.

시각 변경 이벤트는 재료와 조명을 갱신하고 다음 `LateUpdate`에 렌더를 예약한다. Canvas 콜백에서 렌더에 재진입하지 않는다. 정원 시각 설정은 건강 기록·활동 날짜·알림 시간과 독립적이다.

## 안개 표현과 비용

입자 24개를 섬 주변과 아래의 서로 다른 3차원 위치에 흩어 놓는다. 위치와 이동은 카메라 좌표를 사용하지 않으므로 시점을 회전해도 안개가 함께 재배치되지 않는다. 각 입자는 작고 느린 curl 변위로 상하·전후로 움직이며 위치를 반복 경계에서 갑자기 감지 않는다.

밀도는 선형 공간의 세계 좌표에서 세 번 샘플링한다. 적운 덩어리의 도형·평평한 바닥·일러스트 윤곽을 만들지 않으며, 넓게 깃털처럼 사라지는 입자 가장자리 안에서 밀도 자체가 빈 곳과 흐린 부분을 만든다. 섬 상부 중앙의 밀도를 줄여 식물과 장식의 가독성을 지킨다. 낮은 밝은 흰 안개, 노을은 옅은 분홍빛, 밤은 어두운 푸른 안개를 사용한다. 밤의 불투명도를 별도로 줄여 화면을 밝은 막으로 덮지 않는다.

상한은 24개 빌보드, 32³ RGBA32 볼륨 텍스처 1개(128 KiB), 프래그먼트당 3회 밀도 읽기, 기존 10 Hz 정원 갱신이다. 텍스처는 생성 시 한 번 만들고 종료 시 해제한다. 체적 ray marching, 입자별 라이트, 구름 그림자 맵은 사용하지 않는다. 이는 3차원 위치와 밀도장을 사용하는 파티클 안개이며 물리 기반 체적 유체 시뮬레이션은 아니다.

구름 RGB와 알파는 서로 다른 혼합 계수를 쓴다. RGB용 `SrcAlpha`를 알파에도 쓰면 하늘의 알파가 낮아져 UI `RawImage` 합성 시 밝은 UI 배경이 밤 안개에 비칠 수 있다. 알파는 `One, OneMinusSrcAlpha`로 혼합해 정원 렌더의 불투명도를 유지한다.

## 검증

전용 `GardenAtmosphereOrbitCapture`는 실제 Vulkan 렌더로 확인한다. 최종 `atmosphere-world-final/validation.txt`에서 태양은 좌우 시선 변화에 맞춰 이동하고 ±90°·180°에서 사라졌으며, 360° 복귀 이미지 차이는 0이었다. 달도 반대 방향을 볼 때 사라졌다. Off-axis orthographic 투영에서도 하늘이 유지되고, 해 뜰 때·낮·해 질 때·밤의 방향광이 원반 방향과 일치했다.

같은 최종 검사에서 24개 입자는 카메라를 회전해도 세계 위치가 같고 60초 후 모두 3차원으로 이동했다. 안개 renderer를 켜고 끈 900×900 이미지 비교에서 낮은 31만 픽셀, 밤은 34.8만 픽셀이 RGB 중 적어도 한 채널에서 3/255 이상 변했다. 최대 차이는 낮 19/255, 밤 33/255였다. 입자 개수만 확인해 보이지 않는 안개를 통과시키지 않도록, 캡처 검사는 최소 출력 차이와 범위를 함께 확인한다. 투명 안개를 합성한 뒤에도 모든 캡처의 렌더 알파는 불투명하게 유지됐다.

같은 Unity 실행의 `integration/validation.txt`에서는 기존 대기 환경 회귀 10개도 통과했다. 평균 밤/낮 밝기는 32.61/187.19로 약 17%였고, 그림자를 끈 이미지와 비교해 39,169개 정원 픽셀에서 그림자의 어두워짐을 확인했다.

후속 원반 투영 회귀는 `sky-shape-final-pass/shape-validation.txt`의 20개 경우를 통과했다. 태양·달을 화면 중심에서 보는 세로 1200×2000, 가로 2000×1200, 정사각형 900×900의 표준·off-axis 직교 렌더 12개에서 가로/세로 비율이 모두 1.00이었다. 640×480 공유 RT를 900×350 또는 350×900에 표시하는 카드 4개도 비율 1.00이었다. 실제 홈 합성 4개는 960×1600·1600×960 RT를 사용했으며, 섬에 가리지 않도록 광축에서 20° 떨어뜨린 원반의 정상적인 구면 투영과 일치했다. 홈 원본을 Vision으로 확인했고, 동일 실행의 `orbit/validation.txt`에서 기존 방향·소실·360° 복귀·광원·안개 회귀도 유지됐다. Editor 하네스는 해상도 변경 뒤 UI 렌더와 레이아웃을 두 번 안정시킨 다음 측정한다.

낮·노을·밤 홈과 회전한 정원을 Vision으로 확인했다. 안개는 섬 주변과 아래에 흐릿한 불규칙 밀도로 보이며, 이전 평행한 줄이나 적운의 단단한 윤곽 없이 중앙 식물과 UI를 읽을 수 있다. 하늘의 원반은 정상적인 세계 방향을 따르므로 기본 내려다보는 카메라에서는 시야 밖에 있을 수 있다. 원본 합성 캡처는 무시된 `artifacts/evolution-20261012/`에만 보관한다. 이 근거는 Editor 결과이며, Android 기기 성능과 배터리 소모를 대신 주장하지 않는다.
