# 활동 추천·걷기 달성 알림

2026-10-12 구현. 제공된 기획 PDF의 **알림 제공 시각과 클릭 시각 차이를 이용한 개인화**를 로컬 규칙으로 연결했다. 건강 기록의 해석이나 의학적 진단을 알림 문구에 사용하지 않는다.

## 사용자 동작

설정의 **활동 추천 알림**은 하루 한 번의 추천을 켜거나 끈다. 기본 시간은 현지 시각 20:00이며 사용자가 시간을 바꿀 수 있다. 이 토글은 걷기 목표 달성 알림과 구분된다. 기기의 앱 알림 설정에서는 전체 알림 또는 개별 채널을 관리할 수 있다.

추천은 아직 마치지 않은 활동이 있으면 이어 하기를, 없으면 오늘의 작은 실천을 제안한다. 당일 완료가 있으면 추천을 보내지 않으며 이미 표시된 추천도 지운다. 여기서 당일은 **현지 달력 날짜**다. 보상 정책의 04:00 일일 회차와 구분하여, 새벽에 완료한 활동도 그 날짜의 추천을 억제한다. 알림을 누르면 오늘의 활동으로 이동한다.

걷기는 검증된 실제 걸음이 저장된 목표에 도달하면 달성 알림을 보낸다. 별도의 직접 완료 버튼을 눌러야 목표 달성으로 인정되는 구조가 아니다. 알림을 누르면 해당 활동의 완료 기록 또는 진행 화면으로 이동한다. 이미 종료된 참여는 기록 화면으로 연다. 개발용 가상 걸음은 일반 개인화 목표의 자동 완료에 사용하지 않는다.

## 시간 적응과 중복 방지

- 추천 시간은 08:00–21:00 안에서 선택한다. 예약 시각 이후 최대 3시간, 늦어도 21:59까지만 늦은 추천을 허용한다. 놓친 알림을 심야에 몰아서 보내지 않는다.
- 실제 추천 알림을 누른 경우만 학습한다. 일반 앱 실행은 학습 자료가 아니다. 같은 날 6시간 안의 클릭만 반영하고, 같은 알림을 여러 번 눌러도 한 번만 반영한다.
- 클릭 시각 쪽으로 차이의 25%를 이동하되, 한 번에 최대 15분만 바뀐다. 유효한 클릭 3회 이후부터 학습 시간을 사용한다. 사용자가 시간을 바꾸면 학습을 초기화하며 적응 기능을 끌 수도 있다.
- 추천을 보낸 날짜와 완료한 날짜를 로컬에 저장한다. 시계가 과거로 돌아가거나 서쪽 시간대로 이동해 이전 날짜가 되어도 같은 기간의 추천을 다시 보내지 않는다. 다음 예약은 현지 달력 기준으로 계산하여 DST 23/25시간 날짜를 처리한다.
- `ReminderSyncCache`는 JNI의 `AVAILABLE` 응답 후에만 동기화 결과를 기억한다. 브리지 미초기화·저장 실패·예외에는 다음 폴링에서 같은 내용을 다시 시도한다.

## 걷기 개인화와 완료 저장

신규 걷기 목표는 최근 14일의 완료된 날짜별 걸음 기록 중 최소 5개 유효 날짜의 중앙값을 사용한다. 최소 5,000, 최대 10,000걸음이며 짧은 최근 수면 기록에는 목표를 낮춘다. 조회 구간과 목표를 시작 시 고정한다. 결측·오래된 기록·미지원·권한 거절은 측정된 0과 구분한다. 세부 규칙과 공식 API 근거는 [Health Connect 개인화 기록](HEALTH_CONNECT_FINDINGS.md#2026-10-12-수면활동량으로-걷기-목표-조절)에 있다.

신규 목표는 **시작한 현지 날짜의 총걸음**이며 시작 전 그날 걸음도 포함한다. 다음 날짜의 걸음을 합산하지 않는다. 이전 저장본의 세션은 원래의 시작 후 300걸음을 유지한다.

네이티브 작업자는 목표 달성을 확인하면 앱 전용 저장소에 세션 ID·고정 조회 구간·목표·관측 걸음·출처·확인 시각을 갖는 달성 증거를 먼저 저장한다. 정원 저장 파일은 Unity가 단독으로 관리한다. 앱이 다시 활성화되면 증거를 검증하고 `TryCompleteWalkingGoal`로 완료 상태와 보상을 하나의 저장 트랜잭션으로 커밋한다. 그러므로 앱이 닫혀 있을 때에도 달성 알림은 올 수 있고, 정원의 보상 저장은 다음 앱 활성화 때 확정된다.

완료 저장이 실패하면 증거를 지우지 않고 다시 시도한다. 저장된 실제 걸음으로도 재시도하므로 새 건강 동기화나 알림 권한을 기다리지 않는다. 같은 일일 미션, 중복 증거 또는 재실행은 보상을 추가 지급하지 않는다. 완료 후 진행 화면의 세션 선택과 뒤로가기 기록을 정리하여 완료한 미션으로 잘못 복귀하지 않는다. 선택 회고를 작성 중인 화면에서는 자동 완료를 미룬다. 홈이나 설정으로 이동한 뒤 자동 완료되면 작성한 기분과 메모를 보상과 함께 원자적으로 저장한다. 저장 실패 시 초안을 유지하며, 중복 완료가 이미 저장한 회고를 덮어쓰지 않는다.

자동 보상 저장 후 `AcknowledgeMissionAchievement`는 네이티브 작업과 달성 증거를 정리하되 이미 표시한 알림은 유지한다. 사용자가 알림을 누르면 저장된 완료 기록을 열 수 있다. 명시적 참여 종료의 취소는 표시 알림까지 지운다. 이전 세션의 확인 또는 취소가 새 세션의 작업을 지우지 않는다.

입력 검증은 요청 ID뿐 아니라 조회 구간·집계 방식·목표·출처·확인 시각까지 확인한다. 디버그 모드 전환 중 도착한 이전 조회, 이미 종료된 세션의 결과, 바뀐 목표의 이전 증거는 새 목표에 적용하지 않는다. `WalkingAchievementPolicy`는 네이티브 작업자의 진행 중 조회에도 같은 조건을 적용한다.

## Android 실행과 권한

추천과 걷기 확인은 WorkManager의 15분 주기 작업을 사용한다. 이는 정각 알람이 아니며 Doze·배터리 최적화·제조사 정책·워치에서 건강 기록이 도착하는 시점에 따라 늦어질 수 있다. WorkManager가 재부팅 뒤 작업을 복구하며 실행 때마다 현재 시간대를 확인한다. 강제 중지 상태에서는 Android가 백그라운드 실행을 막을 수 있다.

Android 13 이상에서는 `POST_NOTIFICATIONS`가 필요하다. 권한이나 채널이 꺼져 있으면 반복해서 대화상자를 띄우지 않는다. 설정에서 권한 화면을 열 수 있다. 걷기 백그라운드 확인에는 걸음 읽기 및 해당 기기에서 지원되는 Health Connect 백그라운드 읽기 권한이 필요하다. 지원되지 않거나 허용되지 않은 경우 앱이 열렸을 때의 실제 조회로 완료한다. 이미 저장한 달성 증거는 건강 데이터를 다시 읽지 않고도 알림을 재시도할 수 있다.

알림 진입점은 비공개 Activity를 직접 여는 PendingIntent다. 서비스·브로드캐스트를 거쳐 Activity를 띄우는 알림 trampoline을 사용하지 않는다. 추천 및 달성 알림은 잠금 화면에서 내용을 비공개로 표시한다.

일반 활동 알림은 가속도나 심박 센서 서비스를 시작하지 않는다. 사용자가 별도로 실행하는 수집 실험의 Android 필수 foreground-service 알림은 해당 실험 기능의 상태 표시이며 활동 추천 알림과 다르다.

모든 자동 테스트의 입력은 합성 데이터다. 실제 건강 값·기기 주소·개인 메모·원본 기기 캡처는 이 문서나 저장소에 포함하지 않는다.

A7 검증은 제품과 다른 application ID에서 실행했으며 건강 읽기 권한을 부여하지 않았다. 실제 건강 기록의 백그라운드 도착 시간, 장기간 알림 전달률 또는 사용자별 적응 효과를 이 합성 테스트로 입증했다고 해석하지 않는다.

통합 Unity 검증은 31/31 통과했으며 활동 패널을 떠난 뒤 걷기 자동 완료가 회고를 보존하는 실패·재시도 사례를 포함한다. 완료 확인(ACK) 후 표시 알림 유지 등 7항목을 추가한 34항목 합성 APK도 빌드했지만, A7 연결이 설치 중 끊겨 새 ACK 경로의 실기기 재실행은 대기 중이다. 위 27항목 실측 결과를 34항목 통과로 확대해서 해석하지 않는다. 최종 제품 APK 빌드는 통과했다.
