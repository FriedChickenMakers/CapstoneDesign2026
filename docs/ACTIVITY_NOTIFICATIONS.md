# 활동 추천·걷기 달성 알림

2026-10-12 최초 구현, 2026-10-15 시간 적응·발송 복구 개선. 제공된 기획 PDF의 **알림 제공 시각과 클릭 시각 차이를 이용한 개인화**를 로컬 규칙으로 연결했다. 건강 기록의 해석이나 의학적 진단을 알림 문구에 사용하지 않는다.

## 사용자 동작

설정의 **활동 추천 알림**은 일일 예약 회차당 최대 한 번의 추천을 켜거나 끈다. 기본 시간은 현지 시각 20:00이다. **시간 설정 → 알림 시간 직접 선택**에서 Android 기본 시간 선택기로 00:00–23:59의 시·분을 고를 수 있다. 야간 근무 등 새벽 이용 시간도 선택·학습할 수 있다. 이 토글은 걷기 목표 달성 알림과 구분된다. 기기의 앱 알림 설정에서는 전체 알림 또는 개별 채널을 관리할 수 있다.

추천은 아직 마치지 않은 활동이 있으면 이어 하기를, 없으면 오늘의 작은 실천을 제안한다. 당일 완료가 있으면 추천을 보내지 않으며 이미 표시된 추천도 지운다. 여기서 당일은 **현지 달력 날짜**다. 보상 정책의 04:00 일일 회차와 구분하여, 새벽에 완료한 활동도 그 날짜의 추천을 억제한다. 알림을 누르면 오늘의 활동으로 이동한다.

걷기는 검증된 실제 걸음이 저장된 목표에 도달하면 달성 알림을 보낸다. 별도의 직접 완료 버튼을 눌러야 목표 달성으로 인정되는 구조가 아니다. 알림을 누르면 해당 활동의 완료 기록 또는 진행 화면으로 이동한다. 이미 종료된 참여는 기록 화면으로 연다. 개발용 가상 걸음은 일반 개인화 목표의 자동 완료에 사용하지 않는다.

## 시간 적응

목표는 모든 사람의 알림을 하나의 고정 시각으로 수렴시키는 것이 아니라, 실제 반응 지연을 이용자의 일상적인 편차 수준까지 줄이는 것이다. 일정한 이용 시간이 드러나지 않거나 이미 즉시 반응하는 사람의 알림은 불필요하게 이동하지 않는다. 5개 합성 페르소나와 기존 정책의 비교 방법·결과는 [알림 개인화 평가](ADAPTIVE_NOTIFICATION_EVALUATION.md)에 별도로 정리한다.

- 실제로 표시한 추천 알림을 누른 경우만 학습한다. 일반 앱 실행은 학습 자료가 아니다. 예정 시각 대신 **실제 제공 시각부터 클릭까지의 delta**를 사용하므로, Android가 작업을 늦게 실행한 시간을 사용자 반응 지연으로 합산하지 않는다.
- 제공 후 0–24시간의 클릭을 허용하며 자정을 지나도 유효하다. 미래 제공 시각, 시계 후퇴로 음수가 된 지연, 24시간을 넘긴 오래된 클릭은 제외한다. 같은 알림의 중복 클릭과 현재 발송 기록에 대응하지 않는 오래된 클릭은 다시 학습하지 않는다.
- 최근 최대 28개 클릭의 현지 제공 분·클릭 분·지연 분만 학습 이력으로 보관한다. 학습 이력에는 날짜나 건강 값·메모를 넣지 않는다. 별도로 최근 발송·클릭 식별 시각과 예약 회차는 중복 방지·발송 복구를 위해 앱 전용 저장소에 남긴다.
- 10분 이내의 빠른 반응만으로 특정 생활 시간대를 추정하지 않는다. 10분을 초과한 관측 중 최소 3개가 일관된 시간대를 형성해야 이동을 시작한다. 24시간을 원형으로 다뤄 23:50과 00:10을 정오로 평균내지 않으며, 서로 떨어진 두 휴식 시간을 그 사이의 바쁜 시간으로 합치지 않는다.
- 최대 2시간 폭의 밀집 구간을 찾아 클릭 시각의 20–80백분위 범위와 그 폭(`spreadMinutes`)을 계산한다. 관측 3개 이상이면서 지연 관측의 35% 이상이 모이지 않으면 신뢰할 시간대가 없는 것으로 보고 기존 시각을 유지한다.
- 최근 3회 반응 지연의 중앙값이 `max(10분, min(spread, 90분))` 이내면 현재 알림 시각을 유지한다. 그보다 길면 구간 시작 5분 전을 향해 한 번에 최대 2시간 이동한다. 추정은 새 클릭을 수락할 때만 실행하며 설정 화면 조회만으로 시간이 계속 이동하지 않는다.
- 네이티브 설정 결과는 학습 중(`collecting`), 빠른 반응 유지(`responsive`), 구간 불명확(`uncertain`), 편차 내 안정(`stable`), 시간 조정 중(`adapting`) 상태와 관측 수·시간 구간·spread를 제공한다. 구간은 사용 가능성을 추정한 값이며 의학적 상태나 장기 예측을 뜻하지 않는다.
- 시간 선택기에서 직접 시간을 확정하면 이전과 같은 선호 시각을 골라도 학습을 초기화하고 그 시각부터 다시 시작한다. 알림 또는 적응 기능의 토글만 바꾸면 누적 이력은 유지한다. 설정 변경·MOCK 전환 전에 발송한 알림을 나중에 눌러 새 학습 상태에 섞는 것은 차단한다.
- 기존 설치본 업데이트에서는 기존 학습 시각을 보존하되 과거의 집계 클릭 수를 새 관측으로 꾸미지 않는다. 새 이력은 0개부터 쌓고, 적응 기능이 꺼져 있으면 사용자가 지정한 시간을 사용한다.

## 예약 회차·발송 복구·중복 방지

- 예약 시각 이후 최대 3시간까지 늦은 실행을 허용한다. 예를 들어 23:30 예약이 00:15에 실행되면 전날의 예약 회차로 기록한다. 고정된 22시 이후 차단은 없으며, 새벽에도 사용자가 선택하거나 학습한 시간에 따른다.
- 예약 회차(`postedDay`)와 실제 제공 시각(`postedAt`)을 구분한다. 같은 예약 회차를 다시 발송하지 않고 실제 발송 사이에는 최소 12시간을 둬 시간대·학습 시각 변경 직후 연속 발송을 막는다. 늦은 전날 알림과 당일 알림이 같은 달력 날짜에 올 수 있지만 두 알림도 이 최소 간격을 지킨다.
- 완료 날짜가 현재 현지 날짜 또는 예약 회차 날짜에 해당하면 추천을 억제한다. 전날 완료했던 활동의 늦은 알림을 자정 이후 다시 보내지 않으며, 시계가 과거로 돌아가거나 서쪽 시간대로 이동해 이전 날짜가 되어도 이미 처리한 회차를 반복하지 않는다. 다음 예약은 현지 달력의 날짜와 선택한 시·분을 다시 조합하여 DST의 23/25시간 날짜 및 존재하지 않는 새벽 시각 보정 이후를 처리한다.
- 발송은 **미확정 예약 저장 → Android `notify()` 호출 → 발송 기록 확정** 순서다. `notify()` 실패를 발송 완료로 저장하지 않으며 Worker가 재시도한다. 미확정 예약이 남으면 Android의 표시 알림에 담긴 회차·제공 시각·설정 세대 값을 대조해 실제 전달 여부를 복구한다. 확정 저장이 실패해도 같은 프로세스의 수락 기록 또는 재시작 뒤 표시 알림을 확인하여 같은 알림을 곧바로 다시 울리지 않는다.
- 클릭은 전달 증거이므로, `notify()` 이후 확정 전에 앱이 종료되었다면 클릭 진입 시에도 미확정 기록을 확정할 수 있다. 앱 저장과 Android 알림은 하나의 원자적 트랜잭션이 아니므로, 미확정 상태에서 프로세스가 종료되고 표시 알림까지 사라진 극단적인 경우의 정확히 한 번 전달을 보장하지는 않는다.
- 알림 비활성 또는 MOCK 전환 시 작업·표시 알림·미확정 예약을 정리하며 이전 알림의 클릭을 새 학습에 반영하지 않는다. 권한 차단은 발송 완료로 기록하지 않아 권한 복구 뒤 유효한 예약 창에서 재시도할 수 있다.
- 전날 추천을 알림함에 남겨 두었어도 다음 예약 회차는 소리·진동 효과를 요청할 수 있다. 같은 알림 ID를 재사용하되 `setOnlyAlertOnce(false)`로 새 회차의 갱신 효과를 막지 않는다. 걷기 달성 알림은 참여별 태그와 중복 방지를 유지한다.
- `ReminderSyncCache`는 JNI의 `AVAILABLE` 응답 후에만 동기화 결과를 기억한다. 브리지 미초기화·저장 실패·예외에는 다음 폴링에서 같은 내용을 다시 시도한다.

## 걷기 개인화와 완료 저장

신규 걷기 목표는 최근 14일의 완료된 날짜별 걸음 기록 중 최소 5개 유효 날짜의 중앙값을 사용한다. 활동량 기준 목표 범위는 5,000–10,000걸음이며, 짧은 최근 수면 기록이 있으면 여기서 20% 낮추고 500걸음 단위로 내림한다. 예를 들어 기본 5,000걸음은 4,000걸음이 된다. 조회 구간과 목표를 시작 시 고정한다. 결측·오래된 기록·미지원·권한 거절은 측정된 0과 구분한다. 세부 규칙과 공식 API 근거는 [Health Connect 개인화 기록](HEALTH_CONNECT_FINDINGS.md#2026-10-12-수면활동량으로-걷기-목표-조절)에 있다.

활동 탭 진입·앱 복귀·걷기 선택 및 시작 직전에 개인화 기준의 날짜와 최신성을 확인한다. 오래된 기준은 건강 기록을 다시 조회하며, 이미 진행 중인 조회는 함께 기다린다. 선택 화면의 시작만 최대 15초 대기하고 실패·시간 초과 뒤에는 기본 목표로 진행할 수 있다. 실패한 조회는 120초 동안 반복하지 않는다. 대기 중에는 간단한 상태만 확인하고 결과가 바뀌면 전체 기록을 읽는다. 새 결과는 선택 화면의 목표·설명·시작 버튼만 갱신하며, 이미 시작한 목표·조회 날짜 및 다른 실습의 입력을 바꾸지 않는다.

신규 목표는 **시작한 현지 날짜의 총걸음**이며 시작 전 그날 걸음도 포함한다. 다음 날짜의 걸음을 합산하지 않는다. 이전 저장본의 세션은 원래의 시작 후 300걸음을 유지한다.

네이티브 작업자는 목표 달성을 확인하면 앱 전용 저장소에 세션 ID·고정 조회 구간·목표·관측 걸음·출처·확인 시각을 갖는 달성 증거를 먼저 저장한다. 정원 저장 파일은 Unity가 단독으로 관리한다. 앱이 다시 활성화되면 증거를 검증하고 `TryCompleteWalkingGoal`로 완료 상태와 보상을 하나의 저장 트랜잭션으로 커밋한다. 그러므로 앱이 닫혀 있을 때에도 달성 알림은 올 수 있고, 정원의 보상 저장은 다음 앱 활성화 때 확정된다.

완료 저장이 실패하면 증거를 지우지 않고 다시 시도한다. 저장된 실제 걸음으로도 재시도하므로 새 건강 동기화나 알림 권한을 기다리지 않는다. 같은 일일 미션, 중복 증거 또는 재실행은 보상을 추가 지급하지 않는다. 완료 후 진행 화면의 세션 선택과 뒤로가기 기록을 정리하여 완료한 미션으로 잘못 복귀하지 않는다. 선택 회고를 작성 중인 화면에서는 자동 완료를 미룬다. 홈이나 설정으로 이동한 뒤 자동 완료되면 작성한 기분과 메모를 보상과 함께 원자적으로 저장한다. 저장 실패 시 초안을 유지하며, 중복 완료가 이미 저장한 회고를 덮어쓰지 않는다.

자동 보상 저장 후 `AcknowledgeMissionAchievement`는 네이티브 작업과 달성 증거를 정리하되 이미 표시한 알림은 유지한다. 사용자가 알림을 누르면 저장된 완료 기록을 열 수 있다. 명시적 참여 종료의 취소는 표시 알림까지 지운다. 이전 세션의 확인 또는 취소가 새 세션의 작업을 지우지 않는다.

입력 검증은 요청 ID뿐 아니라 조회 구간·집계 방식·목표·출처·확인 시각까지 확인한다. 디버그 모드 전환 중 도착한 이전 조회, 이미 종료된 세션의 결과, 바뀐 목표의 이전 증거는 새 목표에 적용하지 않는다. `WalkingAchievementPolicy`는 네이티브 작업자의 진행 중 조회에도 같은 조건을 적용한다.

## Android 실행과 권한

추천과 걷기 확인은 WorkManager의 15분 주기 작업을 사용한다. 이는 정각 알람이 아니며 Doze·배터리 최적화·제조사 정책·워치에서 건강 기록이 도착하는 시점에 따라 늦어질 수 있다. [Android 공식 문서](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)도 최소 15분 간격과 시스템 최적화에 따른 지연을 명시한다. WorkManager가 재부팅 뒤 작업을 복구하며 실행 때마다 현재 시간대를 확인한다. 강제 중지 상태에서는 Android가 백그라운드 실행을 막을 수 있다.

Android 13 이상에서는 `POST_NOTIFICATIONS`가 필요하다. 권한이나 채널이 꺼져 있으면 반복해서 대화상자를 띄우지 않는다. 설정에서 권한 화면을 열 수 있다. 걷기 백그라운드 확인에는 걸음 읽기 및 해당 기기에서 지원되는 Health Connect 백그라운드 읽기 권한이 필요하다. 지원되지 않거나 허용되지 않은 경우 앱이 열렸을 때의 실제 조회로 완료한다. 이미 저장한 달성 증거는 건강 데이터를 다시 읽지 않고도 알림을 재시도할 수 있다.

알림이 표시되었다는 사실과 소리·진동이 발생했다는 사실은 구분한다. 기기의 소리 모드, 방해 금지, 채널 설정 및 알림 접근 권한을 가진 서비스의 효과 억제 등에 따라 표시된 알림도 조용할 수 있다. 진동 모드에서는 Android가 소리 채널에 대체 진동을 적용할 수 있으므로 채널의 진동 플래그만으로 무반응의 원인을 단정하지 않는다. 앱 업데이트는 기존 채널 ID를 유지하며 이미 만들어진 채널이나 사용자의 시스템 설정을 강제로 바꾸지 않는다. 소리·진동 설정은 기기의 앱 알림 설정에서 확인한다. 날짜 간 효과 억제를 막는 위 수정은 이러한 시스템 억제까지 해제하는 변경이 아니다.

알림 진입점은 비공개 Activity를 직접 여는 PendingIntent다. 서비스·브로드캐스트를 거쳐 Activity를 띄우는 알림 trampoline을 사용하지 않는다. 추천 및 달성 알림은 잠금 화면에서 내용을 비공개로 표시한다.

일반 활동 알림은 가속도나 심박 센서 서비스를 시작하지 않는다. 사용자가 별도로 실행하는 수집 실험의 Android 필수 foreground-service 알림은 해당 실험 기능의 상태 표시이며 활동 추천 알림과 다르다.
