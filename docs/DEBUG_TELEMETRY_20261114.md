# 디버그 모드와 확장 측정 (2026-11-14 KST)

설정 목록 맨 아래 **디버그 모드** 스위치로 진입한다. 최초 진입은 소유자가 지정한 비밀번호가 필요하다. 앱에는 검증 해시만 포함하며 입력값은 저장하거나 전송하지 않는다. 같은 설치에서 인증을 기억하므로 다음 진입에는 재입력하지 않는다. 앱 삭제/앱 데이터 삭제 후에는 다시 인증한다. 앱 내 전체 초기화는 인증 여부만 보존한다. 이는 발표 도구의 로컬 접근 제한이며 서버 인증 수단은 아니다.

진입할 때마다 **QA 데이터로 수집 = ON**이다. 메뉴 안에서 자유롭게 OFF/ON으로 바꿀 수 있다. 디버그 종료 시 QA도 OFF이다. 일반 설치는 디버그와 QA 모두 OFF로 시작한다. 앱이 종료돼도 현재 디버그/QA 선택은 유지되며, 디버그를 껐다가 다시 진입하면 QA는 ON으로 초기화된다. 수집 동의는 별도 조건이다.

P/M 미션 시연, 정원의 시간, 가상 걷기, 날짜 넘기기, 코인 추가, 전체 초기화, 기존 서비스/진단 도구를 이 메뉴로 모았다. 홈의 무잠금 시연 진입 버튼은 제거했다. 배포용 비개발 APK에서도 인증 후 도구를 사용할 수 있다. P/M 시연은 별도 저장 상태를 사용하고 종료하면 원래 정원 상태를 복원하지만, 동의한 측정 이벤트는 당시 QA 선택으로 기록한다.

## 추가 수집 항목

| 범주 | 필드와 용도 |
| --- | --- |
| 분류 | 이벤트 생성 시 classified/qa/debug를 고정. 업로드·재시도·재실행 시 덮어쓰지 않음 |
| 미션 | 내용 버전, 기본/추가 역할, 진입 경로(course/recommendation/direct/review/alternative/demo), 선택·시작·완료·종료 |
| 시간 | 확정된 단계의 실제 활성 타이머 초, 추천 초, 단계 번호, 일반/너무 길어요/종료, 종료 사유. 일시정지 시간과 벽시계 경과를 수행 시간으로 세지 않음 |
| 연결 | 방문 ID, 실제 클릭에서 전달된 알림 ID. 알림과 방문·미션을 직접 연결할 수 있을 때만 저장 |
| 전송 | 서버 최초 수신 UTC, 대기 이벤트 수/최장 대기 시간, 누적 실패·재시도 횟수, 마지막 오류 범주, 마지막 성공 UTC |
| QA 화면 | QA ON일 때만 화면 ID, 크기/safe area/UI 배율, 제한된 버튼 ID·좌표·가시성, OS API, 빌드 소스 식별 해시 |

화면 진단은 미션/설정/정원 시간 화면의 명명된 버튼을 대상으로 한다. 안정된 레이아웃만, 화면 인스턴스당 최대 12회/스냅샷당 최대 16개를 보낸다. 일반 스크롤 밖의 콘텐츠는 잘림으로 세지 않는다. 문구·입력 내용·사진·스크린샷·원시 건강값은 보내지 않는다. 좌표 진단은 시각적 디자인 검수 전체를 대체하지 못한다.

QA ON에서 생성한 기록을 나중에 OFF 상태로 전송해도 QA로 남는다. OFF 기록도 반대로 바뀌지 않는다. 이전 앱의 저장 상태와 큐는 QA 여부를 추정하지 않고 **legacy(분류 불명)**로 둔다. 과거 기록에 실제 타이머 시간이나 UI 정보를 소급 생성하지 않는다. 서버는 이전 schema_version=1과 새 버전 2를 함께 수용한다. 수신 시각은 실제 신규 수신분부터 확보하며 기존 DB 행에는 과거 시각을 만들어 넣지 않는다.

## 분석과 발표

`server/analyze_measurements.py` CLI 기본 분석군은 participant이다. `--cohort qa`, `legacy`, `all`을 명시해 별도 분석할 수 있다. 동일 알림/추천/미션 흐름에서 분류가 바뀌면 해당 흐름은 단일 분석군의 분모와 완료 집계에서 제외하고 제외 수를 보고한다. 서버 정책 학습에서도 QA 행동 이벤트를 제외한다. 전송 상태는 선택된 분석군이 속한 수집 단위 전체의 최신 상태이므로 참여자 전용 오류율로 해석하지 않는다.

발표에는 ① 앱→큐→서버 수집 동작, ② 추천 노출→선택→시작→완료, ③ 추천 시간 대비 실제 수행 시간과 단축 선택, ④ 알림 클릭→방문→미션, ⑤ QA와 참여자 분리 및 화면 잘림 검출을 기능 검증 근거로 제시할 수 있다. 단일 설치의 기록은 사례/동작 검증이며 효과·임상 개선·사용자 집단의 선호 증거가 아니다. 데이터가 누적돼도 관찰 비교에는 선택 편향과 관찰 기간/업로드 누락을 함께 표시한다.

## 검증 범위

순수 C# 도메인, Unity 격리 UI, Android Robolectric 큐/전송, Python 서버 호환성 검사를 사용한다. 실제 사용자 저장·기기에는 쓰지 않는다. 설치용 APK의 컴파일/서명/업데이트 호환 확인과 실제 기기에서의 키보드·화면 꺼짐·네트워크 단절 QA는 구분한다. APK 설치 후 새 이벤트를 발생시키기 전에는 확장 필드의 실기기 수신을 확인했다고 말할 수 없다.
