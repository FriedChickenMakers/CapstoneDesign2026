# 주간 식물 성장과 감정 기록 연결 개선 계획

작성일: 2026-11-04. 상태: 구현 전 계획안. 작업 브랜치: `codex/procedural-plant-generation`. 기준 코드: `main`의 `b7332ee`.

활동을 마칠 때마다 변화를 확인하고, 완성한 식물을 통해 자신의 기록을 다시 읽을 수 있도록 정원을 개선한다. 식물 한 개의 성장 목표를 21회로 정하고 하루 최대 3회 활동 완료를 인정한다. 감정 기록은 선택이며, 저장한 기록 하나에 기억 잎 하나를 연결한다. 완성한 식물은 보관하고 다음 식물을 키운다.

## 1 확정된 방향과 이번 범위

사용자가 선택한 성장 규칙은 다음과 같다.

- 기본 활동·자유 활동·복습의 완료를 합쳐 하루 최대 3회 성장한다.
- 21회를 채우기 전에는 같은 식물을 유지한다. 7일이 지나도 미완성 식물을 교체하거나 진행을 초기화하지 않는다.
- 감정 기록을 생략해도 같은 성장 기회를 얻는다. 감정의 내용이나 긍정성으로 보상을 차등 지급하지 않는다.
- 감정 기록은 잎이나 꽃잎 등 식물 구성요소와 일대일로 연결하고, 선택하면 원래 기록을 읽는다.
- 로우폴리 표현을 개선하고, 생성 규칙·다양성·성능·L-system 비교에 대한 검증 근거를 마련한다.

여기서 **주간 식물은 하루 3회 참여하면 약 일주일에 완성할 수 있는 식물**이다. 달력 주차, 코스 주차, 식물의 순번은 별도 값이다. 코스의 권장 주당 신규 활동은 6개이므로, 21회는 새 코스 과제 21개를 요구한다는 뜻이 아니다. 8주 코스를 끝내면 반드시 식물 8개를 얻는다는 뜻도 아니다.

이번 구현 계획의 중심은 성장 전환과 기록 연결이다. 카메라 미션 분류, 로컬 CV 모델, 사진 확인, 추가 보상은 후속 범위로 둔다. 사진 판정이 일반 성장이나 기록 저장의 필수 조건이 되도록 연결하지 않는다.

## 3 활동 완료와 식물 성장 규칙

### 성장 인정과 중복 처리

새 정책 `Activity21V1`은 유효한 활동 세션 완료 1건을 성장 기회 1회로 처리한다. 새로 완료한 기본 활동, 추천·자유 활동, 복습을 포함한다. 단순 선택·시작·일시정지·참여 종료와 개발용 가상 걸음 정산은 포함하지 않는다. 걷기는 기존 완료 조건을 만족해 세션 완료가 저장되는 시점에 같은 규칙을 적용한다.

중복 판단 단위는 미션 종류가 아니라 **완료 세션 ID**다. 같은 완료 요청의 재전송·앱 재실행은 한 번만 처리한다. 같은 활동을 별도 세션으로 다시 수행한 복습은 일일 한도 안에서 성장할 수 있다. 실제 실습 여부를 사진이나 생체 수치로 추가 판정하는 기능은 여기서 도입하지 않는다.

```text
하루 성장 횟수 D = 해당 회차에 저장된 성장 인정 건수
성장 가능 = 유효한 새 완료 세션이며 D < 3
식물 진행도 j = 해당 식물의 성장 인정 건수, 0 <= j <= 21
표시 성장률 g = j / 21
```

일일 회차는 기존 현지 04:00 갱신과 날짜 high-water 정책을 재사용하는 기본안이다. 완료 시점 회차를 트랜잭션 안에서 확정한다. 코스 변경·식물 교체·앱 재실행으로 한도를 초기화하지 않는다. 시계 후퇴·시간대 이동에도 이미 소비한 회차를 다시 지급하지 않는다.

하루 네 번째 이후 완료는 활동과 기록을 정상 저장하되 성장 한도에 도달했음을 처리 결과에 남긴다. 그 세션을 다음 날 다시 제출해 성장하지 못하도록 `DailyLimitReached` 결과도 영구적으로 식별한다. 감정 기록의 저장과 기억 잎 생성에는 이 성장 한도를 적용하지 않는다.

### 완성과 다음 식물

21번째 인정으로 현재 식물을 완성하고 완성 시각을 저장한다. 완성한 모습을 먼저 감상할 수 있도록 즉시 화면에서 치우지 않는다. 다음 성장 가능한 활동을 완료할 때 새 인스턴스를 만들고 그 활동을 새 식물의 1회차로 기록한다. 생성·완료·현재 식물 포인터 변경은 함께 저장한다.

남은 일일 성장 횟수는 식물 교체 이후에도 공유한다. 한동안 쉬어도 성장이 퇴행하거나 미참여 횟수가 쌓이지 않는다. 완성 식물은 식물함에서 순번·성장 기간·연결 기록 수로 찾는다. 첫 버전은 선택한 식물 하나를 자세히 표시하고, 식물함 전체를 동시에 고해상도 렌더링하지 않는다.

### 영양제 경제

새 21회 식물은 활동 완료로 자동 성장하며 성장 때 영양제를 차감하지 않는 안으로 구현한다. 기존 완료 보상과 영양제 잔액·환경 구매는 유지하고, 복습에 영양제를 추가 지급하지 않는다. 영양제와 성장 횟수를 두 개의 지갑처럼 동기화하지 않는다.

새 식물에는 기존 `영양제 10개로 성장` 구매 버튼을 제공하지 않는다. 기존 구매 이력은 조회용으로 보존한다. 남은 영양제의 신규 소비처나 상점 밸런스는 별도 제품 결정이며, 이번 전환을 이유로 잔액을 변환·회수하지 않는다.

## 4 21회 안에서 보이는 성장

현재 생성기의 분화 시점 `ceil(M / 3)`를 사용하면 M=21에서 7회차에 종이 확정된다. 인정 활동 최소 6회 조건도 충족한다. 새 식물에는 호환용 가상 카운트 `[4,0,0,0,0,2]`를 넣지 않고 실제 성장 인정 활동의 6분류 카운트만 사용한다. 한도 밖 완료는 기록을 남기지만 해당 식물의 종류·형질 입력을 추가하지 않는 기본안이다.

| 인정 횟수 | 시각 목표 | 유지할 계약 |
| --- | --- | --- |
| 0 | 씨앗. 기록이 있으면 작은 기록 가지를 함께 볼 수 있음 | 활동 성장 횟수를 기록 수로 대체하지 않음 |
| 1~3 | 씨앗 열림, 새싹, 떡잎과 짧은 줄기 | 첫 완료부터 눈에 보이는 변화 |
| 4~6 | 줄기·잎의 부피와 지지 구조 발달 | 공통 유년 형태를 유지하고 종을 확정하지 않음 |
| 7 | 종 확정과 종별 실루엣, 첫 봉오리 | 시드·종·전체 구조 목표를 저장 |
| 8~11 | 가지와 봉오리 발달, 줄기 길이 성장 종료 | 11회차 이후 줄기 길이 증가 없음 |
| 12~15 | 꽃이 열리고 색면·부피가 확장 | 이미 있는 기관의 정체성과 부착 관계 보존 |
| 16~20 | 꽃·잎의 풍성함과 종별 마무리 | 모든 종에 열매를 강제하지 않음 |
| 21 | 완성 형태와 완성 안내 | 이후 활동으로 이 식물의 성장 단계를 초과하지 않음 |

이는 시각 제작 목표다. 현재 곡선에 M=21만 넣으면 여러 단계가 비슷하게 보일 수 있으므로 실제 렌더링으로 조정한다. 생성 버전과 메시 버전을 구분해 기존 Recipe의 모양을 보존한다. 매 성장의 변화를 단순 전체 확대에만 의존하지 않고, 잎의 펼침·가지 부피·봉오리·개화로 분산한다.

정원 전체 보기와 가까이 보기에서 `0, 1, 3, 6, 7, 11, 15, 18, 21`을 같은 카메라로 비교한다. 감정 기록 0개인 식물도 완성 형태가 충분해야 한다. 전환 애니메이션은 저장 성공 후 재생하고, 움직임 줄이기 설정에서는 즉시 전환한다.

## 5 감정 기록 하나와 기억 잎 하나

### 기록 단위와 참조

첫 구현은 모든 종에서 **기억 잎**을 공통 선택 단위로 사용한다. 꽃잎 연결은 이후 종별 디자인에서 추가한다. 감정 없는 장식 잎·꽃도 존재할 수 있으므로 전체 잎 수와 감정 기록 수가 같을 필요는 없다. 일대일 조건은 `살아 있는 기록 참조 ↔ 기억 기관`에 적용한다.

| 원본 | 한 기록의 식별 | 기억 잎 생성 시점 |
| --- | --- | --- |
| 활동 후 감정·메모 | `SessionReflection + SessionId` | 사용자가 선택 기록을 저장한 완료 트랜잭션 |
| 독립 경험 기록 | `Experience + ExperienceId` | 경험 기록의 저장 확인 시점 |
| 실습 중 답변·그림·음성 등 | 해당 세션의 상세 내용 | 자동으로 각각 감정 기록으로 세지 않음 |

감정이나 메모가 비어 있는 완료는 기억 잎을 만들지 않는다. `잘 모르겠어요`처럼 사용자가 명시적으로 고른 응답은 기록이다. 작성 중 초안과 자동 임시 저장은 새 기억 잎을 만들지 않는다. 같은 기록을 수정해도 기관 ID와 연결을 유지하고, 텍스트 내용을 종·크기·희귀도 계산에 사용하지 않는다.

식물 Recipe에는 감정 본문을 복사하지 않는다. `RecordRef`의 종류와 ID로 기존 세션/경험 기록을 조회한다. 완료된 활동의 세부 기록은 기존 `ShowRecord` 계열 화면을 재사용한다. 표시할 날짜는 기록의 실제 저장 시각과 당시 시간대 정보를 사용하며, 저장된 적 없는 날짜를 활동명이나 성장 순서에서 추측하지 않는다.

### 식물과 기관에 배정하는 방법

성장 인정 세션의 감정 기록은 그 성장 영수증의 식물에 연결한다. 나중에 감정을 추가하거나 수정해도 새 활성 식물로 옮기지 않는다. 성장 한도 밖 세션은 완료 당시의 식물 ID를 저장해 연결한다. 독립 경험은 저장 화면에 연결할 식물을 보여 주고 확정하며, 이후 자동 재배정하지 않는다.

첫 기록이 첫 활동보다 빠르면 성장 0인 식물과 작은 기록 가지를 만든다. 기록을 남겼다는 이유로 성장 횟수나 영양제를 올리지 않는다. 완성 후에도 사용자가 그 식물에 기록을 남기는 것은 허용하되 성장 Recipe와 기록 기관의 추가는 별도로 관리한다.

기억 잎에는 `OrganId`, `PlantInstanceId`, `RecordRef`, `CreatedUtc`, `AnchorId`, `SlotIndex`, 생성/스타일 버전을 저장한다. `OrganId`는 메시 배열 순서와 무관한 영구 식별자다. 기록 추가·종 분화·메시 재생성·저장 복원·카메라 회전 때문에 다른 기록을 가리키면 안 된다.

종 확정 전 기록 잎은 공통 기록 가지의 슬롯을 사용한다. 종 확정 후에도 기존 슬롯과 정체성을 유지하고 새로 생기는 잎부터 종별 형태를 적용한다. 기존 기억 잎을 새 종의 일반 잎 배열에 순서대로 다시 배정하지 않는다.

### 기록이 21개보다 많은 경우

21은 성장 횟수이며 기록 개수의 제한이 아니다. 독립 기록과 성장 한도 밖 기록도 있으므로 기록 수가 21보다 많아질 수 있다. 기록을 버리거나 한 잎에 여러 기록을 덮어쓰지 않는다.

기본안은 기록 가지를 21개 기관 단위로 나누고, 자세히 보기에서 가지 페이지를 선택하는 방식이다. 모든 기관은 저장하되 한 번에 보이는 가지의 기하와 선택 영역만 생성한다. 전체 정원에는 대표 가지와 기록 수를 표시한다. 이 표시 방식은 21·42·210개 합성 기록으로 가독성과 성능을 확인한 후 확정한다.

### 수정과 삭제

기록 수정은 원본에 반영하고 연결을 유지한다. 삭제 시 원본과 기관의 기록 연결을 같은 저장에서 제거한다. 해당 잎을 연결 없는 장식으로 유지해 식물의 성장이나 영양제를 회수하지 않는 기본안이다. 삭제한 본문이 복제 필드·썸네일·로그에 남지 않도록 하고 백업의 보존/삭제 정책도 함께 적용한다.

현재 개발용 `ResetMissionHistory`는 세션과 경험 기록을 지우면서 정원을 남긴다. 이 경로도 기록 참조를 정리하고 일일 성장 한도·이미 처리한 완료의 중복 방지 상태는 유지하도록 확장한다. 개별 기록 편집/삭제 UI가 아직 없는 경로에는 함께 구현하거나 기능 제공 범위를 명시한다.

## 6 식물을 눌러 기록을 여는 동작

정원에서 식물을 선택하면 가까이 보기로 전환한다. 기억 잎을 누르면 날짜·활동·감정 요약을 열고, 사용자가 상세 보기를 선택하면 원본 기록 화면으로 이동한다. 돌아오면 같은 식물·회전·확대·가지 페이지를 복원한다. 기록 목록에서도 같은 기록에 접근할 수 있어야 한다.

기본 렌더링은 합쳐진 메시를 유지하고, 기록 보기에서 보이는 기억 기관에만 간단한 선택용 콜라이더 또는 화면 좌표 선택 영역을 둔다. 작은 잎의 선택 영역은 실제 잎보다 넓게 제공한다. 겹친 후보는 가까운 기관과 화면 거리를 함께 비교하고 모호하면 선택 목록을 보여 준다. 잎마다 별도 Material과 고해상도 MeshCollider를 상시 생성하지 않는다.

`PlantMeshData`에는 기관별 기하 범위와 선택 앵커를 함께 반환하도록 확장한다. 정확한 삼각형 선택이 필요한 경우에는 현재 메시의 삼각형→OrganId 매핑을 사용한다. Unity의 `RaycastHit.triangleIndex`는 MeshCollider 충돌에서만 유효하므로, 간단한 선택용 콜라이더에서는 해당 컴포넌트가 가진 OrganId를 사용한다. [Unity 공식 문서](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/raycasthit/triangleindex)

드래그 회전·두 손가락 확대와 탭을 구분하고, UI 위의 입력은 정원 선택에 전달하지 않는다. RenderTexture 안의 정원에서는 화면 좌표를 실제 표시 사각형·카메라 좌표로 변환한다. 가려진 뒤쪽 잎, 작은 화면, 안전 영역, 좌우 회전과 확대 상태를 시험한다. 일반 홈에서는 감정 본문을 항상 노출하지 않는다.

## 7 로우폴리 디자인 개선 방향

현재 메시도 면마다 같은 법선을 사용하므로 flat shading은 이미 적용되어 있다. 개선의 핵심은 삼각형 수를 무조건 줄이는 것이 아니라, 작은 화면에서 형태와 면의 부피가 읽히도록 만드는 것이다.

1. 캐모마일·라벤더·종꽃의 같은 시드와 성장 단계로 현재형, 넓고 두꺼운 잎 중심형, 둥글고 풍성한 실루엣형을 비교한다.
2. 줄기는 너무 가늘고 긴 비율을 줄이고, 잎과 꽃잎은 몇 개의 큰 면·절제된 두께·넓은 색면으로 표현한다. 캐모마일의 잘게 갈라진 잎은 종의 특징을 남기면서 묶음 단위로 단순화한다.
3. 기억 잎은 누르기 쉬운 크기와 간격을 확보한다. 기록 유무는 작은 강조로 알려 주며, 불편한 감정을 시든 잎·어두운 식물·낮은 등급으로 표시하지 않는다.
4. 낮·밤과 정원 전체/가까이 보기에서 같은 모델을 비교한다. 조명 변경 효과와 메시 개선 효과를 별도로 확인한다.

첫 시각 검토는 대표 3종의 7·14·21회 성장과 기록 0·3·21개에 집중한다. 방향을 선택한 후 12종으로 확대한다. 새 스타일은 새 버전 식물에 적용하고, 기존 보관 식물의 모양을 조용히 재생성하지 않는다. 식물 생성 결과로 만든 실제 Unity 렌더링을 비교 자료로 사용한다.

## 8 데이터 구조와 저장 이행

다음 명칭은 신규 타입의 설계안이다. 기존 파일 구조에 맞춰 분리하되 `GardenStateService`의 단일 저장 주체를 유지한다.

| 구조 | 핵심 필드와 책임 |
| --- | --- |
| `PlantCollectionState` | 활성 인스턴스 ID, 다음 순번, 정책 버전, 식물 목록 |
| `PlantInstanceState` | 인스턴스 ID, 순번, 목표 21, 현재 단계, 생성/완성 시각, Recipe, 기록 기관 목록 |
| `PlantGrowthDecision` | 세션 ID, 적용 회차, 식물 ID, 인정/한도도달 결과, 전후 단계, 정책 버전 |
| `MemoryOrganState` | 영구 기관 ID, 기록 종류/ID, 식물 ID, 앵커/슬롯, 스타일 버전 |
| `DailyPlantProgress` | 날짜 high-water와 전역 일일 인정 횟수. 식물/코스 변경으로 초기화되지 않음 |

새 구조는 schema 2로 이행하는 안을 우선한다. 구 schema 1의 검증·체크섬 확인 후 변환하고, 새 전체 저장이 성공했을 때만 전환한다. 기존 APK가 새 구조를 무시한 채 다시 저장하는 것을 허용하지 않으며 다운그레이드는 별도 복구 경로로 다룬다.

- 기존 단일 식물은 외형과 성장값 그대로 `LegacyPurchase` 보관 개체로 이관한다. 새 21회 식물로 환산하거나 기존 기관을 과거 감정 기록에 자동 연결하지 않는다.
- 기존 `GrowthHistory`의 명시적인 세션 연결은 유지한다. 예전 활동·영양제·보상 영수증·코스 진행·환경·동물·개인화 상태를 변경하지 않는다.
- 전환 전에 완료된 세션을 순회하며 성장 보상을 소급 지급하지 않는다. 전환 뒤 새 완료 처리만 신규 성장 판단에 들어간다. 이전 버전에서 시작한 미완료 세션의 완료도 그 경계 테스트에 포함한다.
- 완료 세션, 기존 보상/진도, 성장 판단, Recipe, 선택 기록, 기억 기관, 완성/다음 식물 포인터를 하나의 후보 상태에 반영한다. 어느 단계라도 실패하면 전부 이전 상태를 유지한다.
- 기존 `PlantGrowthService`의 독립 지갑을 앱에 추가하지 않는다. `PlantGenerator`의 순수 생성 기능과 성장 계산만 재사용한다.
- 기존 저장의 깊은 복사, 파일 잠금, 손상 시 중단, LIVE/MOCK/REPLAY 분리, IL2CPP 보존 목록을 새 타입까지 확장한다.

## 10 검증과 비교 실험

### 계약 검증과 증거의 구분

proof는 다음 세 종류로 나눈다. 같은 입력·시드·버전의 재현성, 단조 성장, 일대일 연결, 원자적 저장은 규칙과 자동 검사로 검증한다. 다양성·자연스러움·성장 인지는 실제 출력과 사람 평가로 측정한다. 속도·메모리·배터리 영향은 실행 환경별 측정값으로 보고한다. 유한한 테스트 통과나 해시 시드의 차이가 모든 식물의 시각적 유일성을 보장하지 않는다.

| 필수 사례 | 검증할 결과 |
| --- | --- |
| 하루 0·1·3·4회, 7일·14일·긴 휴식 | 하루 최대 3, 21에서 완성, 미참여 패널티 없음 |
| 같은 세션 재전송, 별도 복습 세션 | 전자는 한 번, 후자는 일일 한도 안에서 인정 |
| 21번째 성장 뒤 같은 날 새 식물 | 기존 일일 한도를 공유하며 식물 순번과 영수증 중복 없음 |
| 기록 0·1·21·42·210개 | 기록 0개도 완성, 모든 저장 기록과 고유 기관의 연결 유지 |
| 같은 날짜 여러 기록, 수정·삭제·기록 초기화 | 날짜로 덮어쓰지 않음, 기관 추가 중복·잘못된 참조 없음 |
| 완성 뒤 늦은 회고·독립 기록 | 대상 식물이 의도대로 유지되고 성장 횟수는 증가하지 않음 |
| 모든 저장 단계 실패와 재실행 | 완료·돈·성장·기록이 함께 성공하거나 함께 유지됨 |
| schema 1·구 Recipe·기존 구매 연결 | 기존 외형·잔액·코스·기록 보존, 소급 성장 없음 |
| 12종·모든 단계·회전/확대·작은 화면 | 기관 부착·선택 대상·원본 기록의 대응 유지 |

### 다양성과 L-system 비교

[기존 평가 계획](PLANT_GENERATION_EVALUATION_PLAN.md)의 품질·다양성·제어 가능성·성장 일관성·재현성·성능 틀을 이어간다. [PCG Benchmark](https://github.com/amidos2006/pcg_benchmark)는 품질·다양성·제어 가능성을 공통 평가 축으로 제공한다. 식물용 거리와 판정 기준은 별도로 정의한다.

외부 비교는 [L-Py](https://github.com/openalea/lpy)를 사용하는 매개변수·확률적 L-system을 우선 파일럿으로 삼는다. L-Py는 식물 모델을 만드는 프레임워크이므로 비교 대상의 문법·모델·버전을 함께 고정해야 한다. 공통 과제는 방사형 꽃·꽃이삭·종꽃 3개에서 시작하고, 설치·출력 가능성을 확인한 뒤 본 실험으로 확대한다. 우리 방식도 절차적 생성이므로 비교 이름은 `L-system 구현과 활동 기반 형태 규칙 생성기의 비교`로 한다.

내부 비교군은 현행 기준, 새 전체 방식, 활동 형질 반영 제거, 형태 난수 제거, 고정 템플릿으로 구성한다. 메시 개선은 동일한 구조/Recipe를 서로 다른 메시 스타일로 그리는 별도 실험으로 분리한다. 기록 기관 수·배치를 통일한 비교와 기록 기능 자체의 사용성 평가도 분리한다.

본 실험의 초기 설계는 **12종 × 100시드 × 22단계(0~21)**다. 방식당 독립 식물은 1,200개이고 단계 관측은 26,400개다. 단계나 여러 카메라 뷰를 독립 식물 수로 세지 않는다. 외부 비교는 공통 형태 3개 × 100시드의 300개부터 시작한다. 조정용 시드와 본 측정 시드를 분리하고, 표본 확대 전에 실행 비용을 확인한다.

| 평가 | 측정안 |
| --- | --- |
| 품질 | 전체 생성 시도 중 메시 유효성·공간·기관 부착·예산을 모두 통과한 비율. 거부/실패도 분모에 포함 |
| 종 내부 다양성 | 같은 활동 입력의 시드 변화에 따른 정규화 구조 거리와 여러 방향 실루엣 거리, 중복률 |
| 활동 반영 | 같은 시드·활동 총량에서 6분류 비율만 변경한 짝 비교. 종이 바뀐 결과와 같은 종 내부 반응을 구분 |
| 성장 일관성 | 0~21 단조 진행, 7회차 이후 종 고정, 줄기 길이 제한, 기관 ID/부착·기록 연결 보존 |
| 기록 접근 | 목표 날짜/기록 찾기 성공률, 소요 시간, 잘못된 잎 선택률, 목록 경로와 비교 |
| 재현성 | 재생성·저장 복원 후 논리 Recipe와 기관 참조의 일치. GPU 픽셀 해시 일치를 모든 기기에 요구하지 않음 |
| 성능 | 생성·메시 변환·선택 영역 갱신·저장 각각의 p50/p95, 메모리·할당·삼각형·draw call·프레임 시간 |
| 지각적 품질 | 방법 이름을 가린 로우폴리 선호·종 구별·단계 변화 인지. 참여자 단위 결과와 불확실성 보고 |

외부 방식과는 카메라·조명·배경·공간·삼각형 예산·조정 시간을 맞춘다. 구조 비교는 같은 잎/꽃 메시를 공유하고, 전체 파이프라인 비교는 각 방식의 메시를 쓰되 결과를 별도로 보고한다. 활동 입력이나 기록 기능이 없는 방식은 해당 항목을 N/A로 처리한다. Unity C#과 Python L-Py의 실행시간 차이는 언어·구현·입출력 비용이 포함된 결과이며 알고리즘 자체의 복잡도 증명으로 표현하지 않는다.

성능 파일럿은 식물 1·8·32개를 저장한 상태와 표시 기록 0·3·21개, 전체 기록 42·210개를 포함한다. 자세히 표시하는 식물은 우선 1개로 제한한다. 현재 8,000 triangle 한도를 출발점으로 **기본 식물과 현재 보이는 기록 기관을 합친 예산**을 측정한다. 초과 시 기록을 삭제하지 않고 표시 페이지·메시 밀도를 조정한다. 단말별 시간 목표와 중복 거리 임계값은 파일럿 후 본 실험 전에 고정한다.

합성 입력·버전·시드·기록 수·실패·실행 환경을 manifest와 CSV로 남긴다. 실제 감정 본문·개인 기록·기기 식별자·원본 캡처는 공개 자료에 넣지 않는다. 식물 생성 평가, 기록 탐색 사용성, 앱 참여 지속성은 서로 다른 결과로 보고한다.
