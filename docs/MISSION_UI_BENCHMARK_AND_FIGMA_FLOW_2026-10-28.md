# 2주 MVP 미션 UI 벤치마크와 Figma 화면 흐름

작성일: 2026-10-28. 대상은 `codex/individual-mission-ui` 브랜치의 **2주 과정 12개 미션**이다. 이 문서는 조사 결과와 화면 기획이며, 개별 미션 UI가 구현되었거나 사용성 검증을 마쳤다는 뜻은 아니다. 4·8주 과정의 저장·진도는 유지하되 이번 디자인의 우선 대상은 2주다.

## 1. 기준과 조사 방법

- 현재 2주 코스의 순서·제목·단계는 [MbctContent.cs](../Assets/Scripts/Runtime/MbctContent.cs)와 [LocalGardenState.cs](../Assets/Scripts/Runtime/LocalGardenState.cs)를 따른다. 신규 미션은 하루 최대 1개, 달력 주당 최대 6개다. 놓친 날에 만료나 벌점은 없다. 기간 선택·보상·성장 정책은 [2·4·8주 활동과 성장 기록](COURSE_PROGRAMS_AND_GROWTH_RECORDS.md)을 따른다.
- 현재 Unity 화면은 공통 단계 안내와 선택 입력으로 12개를 표시한다. 이 문서의 네 가지 **화면 틀과 미션별 구성은 제안**이며, 현행 구현으로 혼동하지 않는다. 공통 제목·스크롤 본문·하단 조작부, 초안 보존, 저장 실패 처리는 [활동 화면 검토](ACTIVITY_UI_REVIEW_2026-10-12.md)와 [병행 개발 인수인계](MISSION_PARALLEL_HANDOFF_2026-10-27.md)를 보존한다.
- 경쟁 앱은 2026-10-28에 공식 제품 페이지, 앱 스토어의 게시자 설명·화면, 공식 도움말로 조사했다. **설치 후 실제 사용성 시험은 하지 않았다.** 화면에서 보이는 요소와 설명 문서의 동작을 구분한다. 공개 자료로 확인되지 않은 완료 단계, 추천 알고리즘, 효과는 추정하지 않는다. Forest는 집중 타이머, 마음정원은 자기 대화·웰니스 앱으로 우리 MBCT 원리 참고 활동과 목적이 다르다.

### 벤치마크에서 도출한 UX 원칙

1. **발견:** 홈은 ‘오늘의 미션’ 한 개를 우선 보여준다. 전체 코스와 완료 미션 복습은 다음 위계에 둔다. 선택할 목록이 길어도 시작 경로는 짧아야 한다. Forest·Finch의 단일 행동, Headspace의 Today/Explore 구분을 결합한 **우리 설계 판단**이다.
2. **시작 전 이해:** 카드/소개에 제목, 한 문장 목적, 예상 시간, 준비물·대체 방법을 둔다. ‘왜/무엇을/얼마나’가 보이면 시작을 결정하기 쉽다. 시간은 안내일 뿐 타이머 성과가 아니다.
3. **수행:** 한 화면에는 현재 행동 한 가지만 둔다. 상단은 `현재 단계 / 전체 단계`, 본문은 한 문장의 행동과 필요할 때만 선택지·선택적 입력, 하단은 주 행동 하나를 강조한다. 단계별 공통 뼈대에 미션 고유의 선택·그림·예시를 끼운다.
4. **자율성:** `잠시 쉬기`, `이전`, 불편한 부위·입력 `건너뛰기`, `오늘은 여기까지`를 구분한다. 쉬기는 초안을 보존하고 재개할 수 있다. 참여 종료에는 완료 보상이 없다. 기록·기분·음성·센서 입력을 완료 조건으로 만들지 않는다.
5. **완료·회상:** 완료한 사실과 정원 자원을 연결하되 의미를 정확히 쓴다. **새 미션 완료는 영양제 5개 적립**이고, 식물 성장은 영양제 10개를 사용해 사용자가 별도로 확정한다. 복습에는 추가 적립이 없다. 완료 직후 메모는 선택이고 기록에서 나중에 다시 볼 수 있다.

## 3. 12개 미션에 적용할 네 가지 화면 틀

아래 분류는 사용자에게 선택시키는 새 코스 메뉴가 아니다. 12개 미션은 정해진 순서로 나타나고, 제작자가 같은 레이아웃을 재사용하며 **실습 내용만 미션별로 다르게** 만드는 구조다. 첫 주는 1–6, 둘째 주는 7–12다. `선택지`와 `직접 입력`은 기존 콘텐츠에 있는 경우에도 건너뛸 수 있다.

| --- | --- | --- | --- |
| A. 감각·주의 안내 | 1·2·3·6·7 | 단계마다 큰 안내 문장, 현재 단계, 편안한 자세·대체 감각 안내 | 1의 소재 선택, 3의 불편한 부위 건너뛰기, 2의 호흡 대신 발·소리 선택 |
| B. 선택 후 실습 | 4·5 | 먼저 활동 방법을 고르고 다음 화면에서 감각을 관찰 | 익숙한 행동 선택/직접 입력, 앉아 움직이기/걷기 선택 |

## 4. 화면 구조와 상태: Figma 파이프라인 입력

Figma에서는 다음 **프레임·컴포넌트·분기**를 만들면 12장의 서로 다른 정적 화면을 그리는 대신 재사용성과 예외 경로를 함께 확인할 수 있다. 프레임 이름은 제안 ID이며 Unity 클래스명이 아니다.

| 프레임 | 필수 요소 | 다음 연결 |
| --- | --- | --- |
| `F00 과정 선택` | 2·4·8주 중 선택, 2주 12회 요약, 진행 보존 설명 | 선택 확정 → `F01`; 기존 선택자는 `F01`부터 |
| `F01 오늘` | 오늘의 미션 **1개**를 제목·짧은 목적·예상 시간·진도 `n/12`와 함께 강조. 코스 목록·복습은 보조 진입 | 시작 → `F02`; 코스 목록/복습 → 해당 목록. 신규 미션을 시작할 수 없는 날은 다음 가능 시점과 복습을 안내 |
| `F02 미션 소개` | 목적, 준비물, 대체 방법, 예상 시간, `시작` 주 버튼, `선택 취소` 보조 동작 | 시작 → 해당 `F03` 틀의 첫 단계; 취소 → `F01` |
| `F03A–D 실습 단계` | 공통 상단 단계수·짧은 제목, 스크롤 본문, 단계별 1개 행동, 하단 `다음/실습 마치기`. 네 틀의 미션별 선택지·예시·입력을 변형으로 둠 | 다음 단계 → 같은 틀의 다음 상태; 마지막 → `F04`; 쉬기 → `X01`; 선택 입력 건너뛰기 → 다음 단계 |
| `F04 선택적 돌아보기` | 기분·메모는 선택임을 명시, `이 기록으로 완료`와 `기록 건너뛰고 완료` | 둘 다 `F05`; 저장 실패는 현재 입력과 화면 유지 |
| `F05 완료` | 완료 미션명, 이번 신규 완료의 `영양제 +5` 또는 복습의 `추가 보상 없음`, 정원·기록·다음 미션 안내 | 정원 → `F06`; 기록 → 완료 기록; 홈 → `F01` |
| `F06 정원` | 현재 잔액, 식물 성장 가능 여부. `영양제 10개 사용`과 성장 확정은 별도 선택 | 성장 미리보기/확정 또는 홈. 미션 완료만으로 식물이 자랐다고 표현하지 않음 |
| `X01 쉬기` | 현재 단계 저장, `이어서 하기`, `오늘은 여기까지`와 보상 차이 | 재개 → 원래 `F03`; 참여 종료 → 기록/홈, 완료 처리 없음 |
| `X02 대체·건너뛰기` | 호흡·몸·움직임 대체 안내, 선택 입력 건너뛰기 | 같은 단계의 안전한 대체 또는 다음 단계. 원래 답을 지우는 동작은 기존 저장 정책 확인 |
| `X03 저장 실패` | 짧은 오류, 초안 보존, 재시도 | 성공 시 원래 경로; 실패 중에는 완료·종료·화면 이탈을 확정하지 않음 |

**화면 연결 요약:** `F00 → F01 → F02 → F03(A/B/C/D) → F04 → F05 → F06`. `F03 ↔ X01`, `F03 → X02 → F03`, 저장 명령 실패 시 `X03 → 원래 프레임`을 더한다. `F01 → 완료 미션 복습 → F02`는 별도 진입선이며 완료 후 `F05`에서 보상을 추가하지 않는다. 코스 기간 변경은 진행 중·일시정지·선택 중 세션이 없을 때만 연다.

### Figma 컴포넌트 계약

- 공통: `MissionCard`(오늘/완료/잠김), `MissionIntro`, `StepHeader`, `StepBody`, `BottomAction`, `PauseSheet`, `CompletionSummary`.
- 단계 변형: `SensoryPrompt`, `ChoiceAndObserve`, `SituationSplit`, `CarePlan`. 변형별로 `안내만`, `선택 칩`, `직접 입력`, `예시`, `대체 안내` 상태를 가진다. 레이아웃은 같아도 **12개의 안내 문구·선택·대체·완료 맥락은 각각 명시**한다.
- 진행 표시: 단계와 코스 `n/12`를 분리한다. 단계 건너뛰기나 잠시 쉬기는 실패/낙오로 색칠하지 않는다. 활동 중에는 보상 수치를 반복 노출하지 않는다.
- 문구 원칙: 명령이나 평가 대신 “살펴봐요/괜찮아요/원하면”을 사용한다. 회복·치료 효과, 감정 진단, 행동 실행의 자동 확인을 암시하지 않는다. 한 화면의 안내는 짧게 시작하고 긴 도움말은 펼쳐 본다.

## 5. 디자인 검토 기준과 구현 인계

| 검토 장면 | 통과 기준 |
| --- | --- |
| 처음 시작 | 사용자가 `오늘의 미션`, 목적, 예상 시간, 시작 버튼을 한 화면에서 찾을 수 있다. 전체 12개 목록을 읽어야만 시작할 필요가 없다. |
| 불편한 실습 | 2번 호흡은 발/소리, 3번 몸은 부위 건너뛰기, 5번 움직임은 앉아서 하기를 찾을 수 있다. 쉬기와 참여 종료의 결과가 다르게 설명된다. |
| 선택 입력 | 8번 예시 답과 10번 계획을 적지 않아도 단계를 넘기고 완료할 수 있다. 저장 실패 시 적던 문장이 남는다. |
| 완료·정원 | 신규 완료는 영양제 5개 적립으로, 복습은 추가 적립 없음으로 보인다. 정원 성장에는 별도의 10개 사용 확인이 있다. |
| 재방문 | 기록에서 미션과 선택적 회고를 보고 11번에서 선호 실습 복습으로 이동할 수 있다. 복습은 새 코스 진도를 앞당기지 않는다. |
| 화면 품질 | 긴 한국어 문구, 글자 확대, 작은 세로 화면, 키보드 열린 입력 화면에서 하단 주 행동과 본문이 가려지지 않는다. 뒤로가기·탭 이동·앱 전환 뒤 초안과 현재 단계가 유지된다. |

디자인 검토는 `F01–F06`의 기본 경로뿐 아니라 `X01–X03`, 입력 없음, 복습, 당일 새 미션 제한 상태를 포함한다. 실제 Unity 구현 전에는 현재 공통 상태 모델과 보상 서비스를 그대로 사용하고, 미션별 표현만 확장하는 계약을 확인한다. Figma 프로토타입 이후 대표 미션 1·3·5·8·10·12와 쉬기/건너뛰기/저장 실패를 직접 눌러 보며 문구와 분기를 수정한다. 현재 문서만으로 실기기 접근성·키보드·저장 동작이 검증된 것은 아니다.

## 6. 남은 디자인 결정

- 정원 피드백의 시각 표현: 미션 완료 때는 **영양제 적립**을 보여주고, 식물 변화는 성장 구매 이후에만 연출한다. Forest의 실시간 나무 성장처럼 보이는 애니메이션을 미션 중 적용할 경우 실제 보상 규칙과 구분해야 한다.
- 11번 선호 실습과 복습 버튼의 위치: 완료 화면 또는 기록에서 쉽게 찾되, 아직 열리지 않은 새 코스를 건너뛰는 것으로 보이지 않게 한다.
- 음성 안내·녹음·감정 기반 추천은 현재 2주 미션 UI의 필수 범위에 넣지 않는다. 나중에 도입하더라도 선택 기능과 명확한 개인정보 안내가 필요하다.
