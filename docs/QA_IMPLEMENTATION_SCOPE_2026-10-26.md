## 구현 원칙

- 2·4주를 48회 압축판으로 만들지 않는다. 활동 안내는 의학적 치료를 대신하거나 짧은 코스의 치료 동등성을 주장하지 않는다.
- 코스 전환 시 이전 기록·진도·재화를 보존한다. 진행 중 활동 처리와 일일 보상 제한을 명시한다.
- 개인화 모델의 첫 목표는 추가 활동의 시작/완료 가능성과 알림 반응을 관측·비교하는 것이다. 생체정보로 우울/스트레스를 판정하는 모델은 범위 밖이다.
- 자유서술 일기와 원본 건강·센서 기록은 서버 이벤트에 넣지 않는다. 별도 동의와 연결 설정 없이 업로드하지 않는다.
- 로컬 서버 개발·통합 테스트와 실제 운영 배포/시험 참여자 관측을 구분한다. 합성 자료의 통과는 실제 사용자 효과 증거가 아니다.
- 식물 생성 거리 지표, L-System 비교, 임상/장기 효과와 고도화 웨어러블 추론은 기존 연구 계획에서 구체화한다.
- 일부 서버 운영 설정이나 기기 연결이 막혀도 코스, UI, 로컬 도메인, 평가 실행기 작업을 계속한다.

## 추가 점검 목록

기존 감사에서 확인한 다음 항목은 누락 없이 추적하되 확정 범위와 구현 결과를 혼동하지 않는다: 성숙 식물 이후 씨앗/수집 순환, 환경·동물 도감의 실제 상호작용, 활동 내 알림 선호와 실제 설정의 연결, 로컬 기록 삭제/초기화, 지원 기기의 건강 데이터 경로, 가상 시각의 낮/밤 음악 전환, 접근성·성능·복구 시나리오.

## 검증 및 배포

새 변경은 단위/계약 검증 → Unity 편집기/Play 검증 → A7 설치·시각 검증 순으로 근거를 남긴다. 기기 원본 설정을 보존·복구하고, 설치 전 기존 데이터를 백업한다. 원시 기록·스크린샷·장치 식별자·복구 일지는 무시되는 `artifacts/`에만 둔다. 완료한 논리 단위는 작업 트리와 스테이징 개인정보 검사 후 현재 작업 브랜치에 커밋·push하고 원격 HEAD를 확인한다.

## 2026-10-27 구현 근거

- 2·4주를 독립된 주력 선택지로 구현했다. 활동·보상·진도·저장 이행 정책은 [코스와 성장 기록](COURSE_PROGRAMS_AND_GROWTH_RECORDS.md)을 따른다. 하루 전환 직후 완료에도 완료 시점의 일일 한도와 보상·진도를 하나의 저장으로 반영한다.
- Wanted Sans와 LINE Seed KR, 주 버튼의 덩굴 가장자리는 [글꼴 출처](UI_FONT_ATTRIBUTION.md)에 기록했다. 기존 글자 크기와 터치 영역을 유지한다.
- 성장 연결/주간·누적 기록/배운 활동 추천과 선호·시간 설정이 구현되어 있다. 명시적으로 선택한 활동만 성장에 연결하며, 추천 설정은 순차 코스의 순서를 바꾸지 않는다.
- 선택적 서버 참여는 기본 꺼짐이고 운영자 연결 설정이 있어야 노출된다. 실제 UnityWebRequest의 로컬 API 전송·철회·삭제를 검증했다. 운영 TLS 서버 배포, 알림 이벤트 생산자의 전체 연결, 실제 참여자 기반 모델 개선은 완료로 주장하지 않는다.
- 자동 검증의 실행 근거와 남은 수동/실기기 범위는 [자동화와 검증 범위](QA_AUTOMATION_AND_COVERAGE.md)를 따른다. 합성 입력의 통과는 임상 효과나 모든 기능의 자동 검증을 의미하지 않는다.
