# MBCT UI 개선과 응답 속도 검증

2026-10-03. 기존 디자인 데모를 통합한 화면의 겹침, 감정 선택, 자유 선택·8주 코스 응답 속도, 강조와 아이콘을 개선했다.

## 화면과 감정 선택

- 음식·일상 행동 선택지와 직접 입력, 실습 안내와 하단 이동 버튼, 완료 기록과 건강 정보의 겹침을 해결했다. 정원 배치·성장 미리보기의 설명도 상태 영역 아래로 내리고, 이 화면에서는 코스 진행선을 숨긴다.
- 감정 선택은 디자인 데모의 `PrototypeMoodFace` 얼굴 다섯 개를 재사용한다. 원본 값은 ‘기뻐요·차분해요·평온해요·조금 지쳐요·울적해요’이며, 좁은 카드의 네 번째 표시만 ‘지쳐요’로 줄였다. 저장값은 원본을 유지한다. 같은 얼굴을 다시 누르면 선택을 해제하고 직접 입력 시 일치하지 않는 얼굴 강조를 해제한다.
- 추천 시작 버튼은 녹색으로, 현재 회차·선택지는 옅은 배경으로 구분한다. 완료는 체크, 다음 활동은 화살표, 미해금은 자물쇠로 표시한다. 메인 디자인의 잎·기록 아이콘은 메뉴와 관련 안내에만 사용한다.
- 감정 선택을 위해 새 이모지 폰트나 외부 이미지 파일을 요구하지 않는다. 기존 디자인의 벡터 얼굴을 렌더링한다.

## 속도 개선

자유 선택 화면의 48개 활동 필터가 상태 스냅샷을 반복 호출했고, 매번 전체 상태를 XML로 직렬화·역직렬화했다. 코스 목록도 각 행에서 상태를 다시 읽었다. 기록이 늘수록 메인 스레드가 이 복사 작업에 묶여 화면 반응이 늦어졌다.

두 화면은 화면 생성마다 상태를 정확히 한 번 읽는다. 상태 복사는 모든 가변 목록과 내부 기록을 독립 복사하며, 저장 파일의 XML 형식·검증·원자적 저장과 잠금은 유지한다. 실습 답변만 바뀌었을 때 정원 오브젝트를 다시 만들지 않는다. 개발 빌드의 `MBCT_UI` 로그는 생성 시간과 스냅샷 횟수를 남긴다.

같은 48개 완료 세션의 합성 데이터로 비교했다. 개발 환경의 3회 필터 실행은 기존 반복 XML 복사 411.8ms에서 수정 후 단일 메모리 복사 1.3ms로 줄었다. 이 수치는 개발 환경의 CPU 작업 측정이며 A7 화면 전환 시간과 구분한다.

## 검증 종료 상태

A7 실제 LIVE 저장 파일은 검증 전후 바이트 단위로 동일했다. 이번 작업에서 만든 MOCK 테스트 폴더와 임시 fixture만 자료 보관 후 제거하고, 최종 APK를 유지한 채 LIVE 정원 화면으로 복귀했다. 최종 로그의 런타임 예외 검사도 통과했다. 얼굴 선택·기록 저장 확인 뒤 발견한 정원 미리보기 겹침을 수정해 APK를 갱신했고, 최종 설치본에서 동일 48세션 fixture로 위 속도 비교와 미리보기 확인을 다시 수행했다.
