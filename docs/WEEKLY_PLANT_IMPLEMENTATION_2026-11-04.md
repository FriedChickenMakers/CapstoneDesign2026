# 21회 식물 성장과 기억 잎 구현·검증

2026-11-04, `codex/procedural-plant-generation`. [계획안](WEEKLY_PLANT_AND_MEMORY_PLAN_2026-11-04.md)의 앱 기능과 내부 평가를 구현했다. 사용자의 추가 결정에 따라 외부 L-Py 비교는 후속 단계로 둔다. 카메라/CV 검증은 이번 범위에 포함하지 않는다.

후속 수정: 사용자의 실제 렌더링 검토를 반영한 [꽃 가림 개선과 메시 버전 5](FLOWER_SPACING_2026-11-04.md). 아래 버전 4 측정은 최초 구현 당시의 결과로 보존한다.

최신 외형: 해바라기 참고 이미지의 두께와 굴곡을 반영한 [입체감 개선과 메시 버전 6](PLANT_VOLUME_2026-11-04.md).

## 앱에서 달라진 동작

- 기본·자유·복습 활동을 완료하면 하루 최대 3회 성장한다. 일일 경계는 기존 현지 새벽 4시 정책이다. 감정 기록은 선택이며 영양제를 성장 비용으로 쓰지 않는다.
- 식물 한 개는 21회에 완성된다. 일주일이 지나도 미완성 식물을 유지한다. 완성한 모습은 그대로 보여 주고, 다음 성장 가능한 활동에서 다음 식물을 시작한다. 같은 날 식물이 바뀌어도 일일 한도는 공유한다.
- 감정/한 줄 기록을 저장한 활동에는 기억 잎 하나를 연결한다. 성장 한도 밖 활동도 기록과 잎을 남길 수 있다. 뒤늦게 감정을 추가하면 원래 활동에 배정된 식물에 연결한다.
- 독립 경험 기록은 마지막 확인 화면에서 연결할 식물을 선택한다. 완성한 이전 식물에도 저장할 수 있다. 기록은 성장 횟수나 보상 금액을 바꾸지 않는다.
- 홈의 `성장 n / 21 · 식물함` 또는 정원 가꾸기/내 과정의 식물함에서 다른 식물과 기억 목록을 연다. 정원을 가까이 본 상태에서 기억 잎을 누르면 해당 날짜의 기록을 연다. 전체 보기에서는 먼저 식물을 눌러 가까이 본다.
- 기록을 보고 돌아오면 선택 식물·기록 가지·회전·확대를 유지한다. 작은 잎의 선택 범위를 넓히고, 겹치는 후보는 목록으로 고른다. 드래그와 두 손가락 입력은 탭으로 처리하지 않는다.
- 21개를 넘는 기억도 모두 저장한다. 한 번에 21개 잎을 표시하는 기록 가지 페이지와 목록으로 접근한다. 식물함은 페이지당 4개 식물을 표시한다.
- 기록 수정은 원본과 연결된 잎을 유지한다. 삭제는 해당 기록 연결을 끊고 잎을 장식으로 남긴다. 활동 완료·성장·영양제는 회수하지 않는다. 활동 기록 삭제 버튼은 감정/한 줄 기록을 지우며 수행 이력 자체는 남긴다.

## 저장 및 생성 계약

`WeeklyPlantState.cs`가 식물 목록, 성장 판단, 기록 참조를 관리한다. `CompleteFocusSession`, 이전 `CompleteSession`, `SaveExperience`의 후보 상태에 식물 변경까지 포함하고 저장 성공 후 공개한다. 같은 완료 세션은 한 번만 처리하며, 일일 한도 때문에 거절된 완료도 저장한다. 코스 변경·다음 식물·앱 재실행·기록 초기화로 한도를 다시 얻지 않는다.

schema 1은 먼저 기존 검증을 통과한 뒤 schema 2로 이관한다. 이전 단일 식물은 기존 Recipe와 외형 버전 그대로 보관하고 새 씨앗을 시작한다. 이전 활동을 소급 성장시키거나 과거 기록을 자동 연결하지 않는다. 기존 구매 이력·환경·영양제·코스 진행은 유지한다. 새 schema를 지원하지 않는 이전 앱으로의 다운그레이드는 제공하지 않는다.

기억 기관은 `식물 ID / memory / 슬롯`이라는 영구 식별자를 가진다. 원본 종류·ID·생성 시각·당시 UTC 오프셋·슬롯·스타일 버전을 저장하고 본문은 복제하지 않는다. 식물 ID는 소속 객체에서, 앵커는 고정 슬롯 규칙에서 결정하므로 계획안의 중복 필드를 따로 저장하지 않는다. 일일 성장 횟수도 성장 판단 목록에서 도출한다.

삭제·수정 시 개인정보 변경 버전을 증가시키고 이전 자동 `.bak`을 제거한 뒤 새 파일을 원자적으로 교체한다. 이 제거가 실패하면 현재 파일은 교체하지 않는다. 삭제한 경험 ID의 해시를 보관해 늦게 도착한 저장 재시도가 기록을 되살리지 않게 한다. 개발용 기록 초기화도 기억 연결을 정리하되 성장 중복 방지와 일일 한도는 유지한다. 사용자가 별도로 만든 외부 백업의 삭제까지 수행하는 기능은 아니다.

생성 입력은 실제 성장 인정 활동의 6분류 누계이다. 7회차에서 종을 확정하고, 이후 시드·기관 목표·부착 관계를 유지한다. 감정 본문·긍정성·기록 수는 종이나 희귀도 입력으로 쓰지 않는다. 기존 생성기 계약 검사와 새 상태 검사를 분리해 검증한다.

## 로우폴리와 선택 기하

새 식물은 메시 버전 4를 사용한다. 넓은 잎과 꽃잎, 굵어진 줄기, 단순화한 갈라진 잎, 세로 비율 0.78의 형태를 적용했다. 1~6회에도 유년 잎이 펼쳐진다. 메시 버전 3은 넓은 면만 적용한 내부 비교군이며, 기존 1·2 버전의 형태는 유지한다. 꽃·잎 확대는 기존 공간 경계를 넘지 않도록 제한한다.

기억 잎은 모든 종에 공통인 밑동의 작은 기록 가지에 배치한다. 세 잎씩 일곱 층으로 나누고 황금각으로 방향을 분산한다. 종 분화 때 기존 기억 잎이 옮겨지지 않는다. 첫 구현에서는 종별 기억 잎·꽃잎 선택을 추가하지 않았다.

기본 식물과 현재 기록 가지는 한 메시/한 재질을 사용한다. `PlantOrganGeometry`가 기관 ID와 삼각형 범위를 연결하며, RawImage 좌표를 카메라 광선으로 변환해 실제 메시를 선택한다. 뒤에 가려진 잎은 직접 선택하지 않는다. 목록은 항상 대체 접근 경로로 제공한다. 성장이 저장된 뒤 짧은 확대 애니메이션을 재생하며 움직임 줄이기 설정을 따른다.

### 내부 생성·다양성 파일럿

12종 × 종당 100시드 × 0~21단계 × 메시 버전 2·3·4 = **79,200개 관측**. 스타일마다 독립 식물 1,200개이고 단계·카메라를 독립 표본으로 세지 않는다. 활동 이력 대신 고정 종별 예시 분류를 넣어 형상 비교를 분리했으며 모든 관측에서 기억 잎 21개를 함께 생성했다. .NET 10.0.12 / X64 데스크톱 CPU 측정이다.

각 종·스타일의 완성 메시 100개에서 정확히 일치하는 정점 배열 해시 중복은 없었다. 높이·굵기·줄기 수·잎 수·꽃 수·퍼짐 각을 정규화한 벡터의 종별 평균 쌍 거리도 기록했다. 이 값은 구조적 변화의 근거이며 사람이 보기에 모두 다르거나 어느 방식보다 아름답다는 증거는 아니다. 내부 스타일은 같은 구조 Recipe를 공유하므로 구조 거리도 같다.

기록 0·3·21·42·210개 파일럿에서 표시 잎은 최대 21개였다. 21/42/210개 조건의 최대 삼각형은 동일하게 3,372개이며 메시 시간 95백분위는 각각 2.915/3.039/2.986 ms였다. 특정 합성 식물의 반복 측정이므로 전체 종의 최악값을 뜻하지 않는다.

## 재현 방법과 남은 평가

순수 C# 검사에는 .NET SDK 또는 Unity Mono가 필요하다. 성능 평가 프로그램은 .NET 8 이상이 필요하다.

```text
python3 scripts/test-weekly-plants.py
python3 scripts/test-weekly-plants.py FocusMissionStateTests AllMissionFlowTests MbctTests LocalGardenStateTests GardenPlantAppearanceTests
python3 scripts/test-procedural-plants.py
```

`CAPSTONE_PLANT_EVALUATION_OUT`을 무시된 `artifacts/` 하위 폴더로 지정하고 `python3 scripts/test-weekly-plants.py WeeklyPlantEvaluation WeeklyPlantStorageEvaluation`을 실행하면 CSV와 JSON을 만든다. `CAPSTONE_PLANT_SEEDS` 기본값은 100이다. Unity에서는 `CapstoneDesign.EditorTools.WeeklyPlantValidation.Run`을 그래픽을 켠 batch mode로 실행한다. `CAPSTONE_ARTIFACTS`로 캡처 위치를 지정할 수 있다.

기존 Unix QA 실행기에도 `weekly-plants` unit 검사와 `weekly-plants-ui` visual 검사를 등록했다. Windows에서는 위 개별 Python 명령과 Unity 진입점을 사용한다. 현재 공통 QA 실행기는 POSIX 파일 권한 API를 사용하므로 Windows 전체 실행은 검증 통과로 취급하지 않았다.

이번 로컬 결과는 `artifacts/weekly-plants-20261104/evaluation/` 및 `validation/`에 있다. 캡처·CSV·로그·합성 저장 파일은 커밋하지 않는다. Focus 파일 저장 검사 재실행 중 Windows 파일 교체 오류가 한 번 있었고, 상태 변경 없이 실패를 반환했다. 같은 코드로 다시 실행한 최종 검사는 통과했다.

후속 평가: 사용자 결정에 따라 **L-Py 외부 비교는 미실행**이다. 같은 자원 예산·시드 수·카메라·조명·조정 시간으로 별도 수행한다. Android FPS/할당/메모리/배터리, 다양한 화면 크기의 터치 정확도, 로우폴리 선호와 종·성장 단계 구별 과제도 별도 결과가 필요하다. AI 컨셉 이미지는 미술 방향 참고이며 실제 구현의 측정 자료는 Unity 렌더링이다.
