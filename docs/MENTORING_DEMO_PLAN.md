# 멘토링·중간발표 데모 계획

## 현재 시연 절차 — 2026-10-10 소스 기준

목표는 **짧은 마음챙김 활동 → 기록·보상 → 정원 변화**와 건강 기록 연동을 3~5분 안에 보여주는 것이다. 임상 효과, 실시간 워치 측정, 장기간 수집 안정성이나 제품 출시 준비를 입증하는 시연은 아니다. 아래 절차가 현재 기준이며, 문서 후반의 2026-09-29 M15 대본과 보상 수치는 당시 검증 이력이다.

### 현재 동작과 시작 조건

- MBCT는 8주·48개 활동이다. 새 추천 활동은 하루 1개, 달력 주당 최대 6개이며 순서대로 진행한다. 이미 배운 활동은 다시 할 수 있지만 복습에는 추가 보상이 없다.
- 현재 기본 완료 보상은 영양제 **5개**, 캐모마일 성장 비용은 **10개**다. 시연 시작 잔액은 **5개 이상**으로 준비한다. 가장 이해하기 쉬운 예는 `5 → 활동 완료 10 → 성장 확정 0`이다. 이는 기존 정책을 설명하는 예이며 새 보상 조정이 아니다.
- 성장 전 씨앗이나 새싹 상태, 오늘 아직 새 추천 활동을 완료하지 않은 상태, 이번 주 제한에 걸리지 않은 상태를 준비한다. 시작할 활동과 진행 중인 초안을 미리 확인한다. 이미 꽃이 핀 정원과 큰 잔액에서는 변화가 덜 드러난다.
- 새 저장본을 단순히 MOCK으로 실행하는 것만으로 시작 잔액 5개가 만들어지지는 않는다. 아래 개발자 준비 도구로 분리된 합성 상태를 마련하고, 실제 발표 기기에서 버튼·잔액·시작 화면을 리허설한다.

### 3~5분 진행표

| 시간 | 조작 | 청중에게 보여줄 내용 |
| --- | --- | --- |
| 0:00~0:25 | 홈에서 성장 전 정원과 잔액 확인 | 활동 참여가 정원에 연결되는 구조. 합성 상태라면 먼저 ‘시연용 예시 데이터’라고 밝힌다. |
| 0:25~1:45 | **오늘의 활동 → 추천 활동 안내 → 시작**, 짧은 첫 활동의 소재 선택과 단계 이동 | 8주 코스의 실제 안내·선택 입력. 기록은 선택 사항이며 실습 권장 시간은 완료 조건이 아님을 설명한다. |
| 1:45~2:15 | **실습 마치기**, 감정 선택 또는 **기록 건너뛰고 완료** | 새 활동 완료 보상 5개와 기록 저장. 같은 활동 복습으로는 보상이 늘지 않는다. |
| 2:15~3:00 | **정원으로 → 정원 가꾸기 → 캐모마일 성장 · 10 영양제 → 확정** | 미리보기 단계에는 차감하지 않고 확정 시 10개를 사용하며 정원이 변한다. |
| 3:00~3:40 | **오늘의 활동 → 참여 기록과 나의 계획**에서 방금 기록 확인 | 완료 내역을 다시 볼 수 있다. 시간 여유가 있을 때 경험 기록·계획을 짧게 소개한다. |
| 3:40~4:30 | 실제 데이터 기기의 **설정 → 심박 차트 보기** 또는 준비된 실기기 영상 | Health Connect에 동기화된 기록, 조회 시각과 출처를 보여준다. LIVE와 합성 시연을 전환한다면 전환을 명시한다. |
| 4:30~5:00 | 홈으로 복귀하며 범위 설명 | 구현된 기능과 남은 장기 검증·성능 개선을 구분한다. |

3분 발표라면 경험 기록·계획과 건강 차트는 준비 영상 또는 질의응답으로 넘긴다. 실제 기기 저장본을 시연 중 교체하거나 설정에서 긴 진단 내용을 읽는 순서는 피한다. Android Back은 페이지/탭 이동에 사용하고, 입력 중에는 첫 Back이 키보드만 닫는 동작을 리허설한다.

### 반복 리허설용 합성 상태와 기존 도구

- 앱은 `garden-live`, `garden-mock`, `garden-replay`의 저장 경로를 구분한다. **LIVE 저장본 초기화·잔액 수정·시스템 날짜 변경으로 반복 시연하지 않는다.** 개발자가 시연 전용 MOCK 저장본을 준비하고 각 회차 후 그 합성 상태만 복원한다. 이미 있는 MOCK/REPLAY 자료도 무조건 덮어쓰거나 삭제하지 않는다.
- `scripts/test-local-loop-play.sh`는 새 `CAPSTONE_SMOKE_SAVE_ROOT`를 요구하며 Editor의 fresh/restore 검증을 실행한다. `LocalLoopPlaySmoke.cs`에는 합성 참여 보상 5개를 먼저 만들고 MBCT 완료 후 10개로 성장 구매하는 검증 흐름이 있다. **자동 검증 도구이지 발표용 초기화 버튼이나 기기 상태 배포 도구는 아니다.** 반복 실행에는 매번 새 격리 경로를 사용한다.
- `scripts/preview-local-loop.sh`와 `TabConsistencyCapture`는 주입된 합성 저장/시각으로 화면 자료를 만드는 기존 도구다. 발표 기기의 반복용 상태 파일 배치는 별도 개발자 준비 작업이며, 현재 UI에 ‘데모 초기화’ 또는 임의 잔액 입력 버튼이 있다고 가정하지 않는다.
- 개발 실행 옵션 `platformInputMode=MOCK|REPLAY|LIVE`와 REPLAY용 `platformReplayPath`가 있다. REPLAY는 앱에서 읽을 수 있는 snapshot JSONL이 필요하다. 단순히 모드를 바꿨다고 모든 단계의 초기 상태가 재설정되지는 않는다. `scripts/test-a7.sh`에는 `logcat -c`가 있으므로 기록 보존이 필요한 발표 준비에서 그대로 실행하지 않는다.
- 실기기 준비 전 private 센서 기록·preferences·외부 정원 저장을 백업한다. APK는 인플레이스 업데이트하고 앱 데이터를 지우지 않는다. ADB 사용 시 명시적 serial과 원래 화면 꺼짐/밝기 기록·복구 절차를 따른다. 일일 수집기 실행은 오래된 파일을 정리할 수 있으므로 백업은 앱 실행보다 먼저 한다.

### 발표 직전 확인

- **연결·권한:** 실제 건강 데이터는 별도 LIVE 기기/화면에서 Health Connect 접근 권한, 공급 앱 동기화, 마지막 측정 시각을 확인한다. MOCK·REPLAY·가상 걸음은 실제 워치 측정으로 소개하지 않는다. Samsung Health 출처만으로 워치 측정임을 확정하지 않는다.
- **충전·수집:** 충전 상태와 수집 상태/마지막 저장/중단 사유를 확인한다. 가속도 수집은 심박 차트와 별도이며 발표에 필수는 아니다. 이미 저전력으로 멈춘 수집기가 충전 연결만으로 다시 시작됐다고 가정하지 않는다. 필요한 경우에만 상태를 확인하며 수집을 명시적으로 시작한다.
- **리허설:** 새 완료 가능 여부, 시작 잔액, 성장 전 상태, 폰트·탭 표시, Back과 키보드, 미러링 화면을 확인한다. 화면이 표시된 뒤 다음 버튼을 누르며 빠르게 연타하지 않는다.
- **대체 자료:** 동일 순서의 1~2분 백업 영상과 건강 차트 화면을 준비한다. 합성 영상은 예시 데이터로 표시하고 개인 메모·식별정보가 나오지 않도록 확인한다. 동기화 지연 시 현장에서 새 측정값이 나올 때까지 기다리지 않는다.

### M15의 현재 위치와 역사 대본 구분

현재 코드에는 **오늘의 활동 → 배운 활동 다시 하기 → 걸음 기록과 걷기**로 M15에 진입하는 경로가 있다. 별도 걷기/연동 기능 소개가 필요할 때만 보조 시연으로 사용한다. 아래 역사 대본의 ‘자유 선택 → M15 걷기’, ‘Trial Off’, 완료 보상 10개를 현재 MBCT 주 시연 절차로 읽지 않는다. 현재 기본 완료 보상은 5개이며 가상 걸음 보상과 실제 건강 기록은 별개다. 일일/주간 제한이나 보상 정책을 발표 편의를 위해 바꾸지 않는다.

## 역사 기록 — 멘토링 데모 단기 계획 (2026-09-29)

상태: 구현·로컬 검증 및 S24 핵심 흐름 실기기 확인 완료. 내일 야외에서 실제 걷기와 화면 꺼짐 상태의 Health Connect 동기화는 추가 확인이 필요하다. 목표는 멘토링 참고용 동작 데모이며 릴리즈 준비나 보상 밸런스 승인이 아니다.

`LocalGardenState` 도메인에 디버그 걷기 구간, 실제 걸음 최고 관측값과 가상 걸음 합산, 10걸음 단위 영양제 적립, 모드 ON/OFF, M15 진행 및 알림 완료 마커를 반영했다. 기존 schema-1 XML에서 새 디버그 구간 필드가 빠져 있어도 읽을 수 있다. `scripts/test-local-state.sh`는 318개 synthetic 상태 검증을 통과했다. Unity APK와 MOCK 미리보기를 확인했고, S24에서 앱 복귀 시 Health Connect 조회·보상 알림·M15 완료·정원 구매를 확인했다.

### 당시 목표와 확정된 동작

- 일반 모드의 M15 걷기 목표는 300걸음이다. Health Connect 동기화가 늦어도 직접 완료할 수 있고, 기존 완료 보상 영양제 10개는 하루 회차당 한 번 유지한다.
- 개발 빌드의 디버그 모드는 기본 OFF이다. ON 이후 실제 걸음과 설정 화면의 `가상 걸음 +1`을 합산해 10걸음마다 영양제 1개를 미션과 관계없이 지급한다. M15 완료 보상 10개는 추가로 유지한다. 디버그 모드의 M15 표시 목표는 10걸음이다.
- M15 목표에 도달했으나 직접 완료하지 않은 경우 `미션 보상을 받을 수 있어요` 알림을 세션당 한 번 보낸다. 디버그 영양제 자동 적립 때마다 알리지 않는다.
- 일반 앱 실행에서 48시간 가속도 실험을 자동 시작하지 않는다. 기존 자동 실험은 종료하고 그래프 이력은 보존한다. 명시적으로 실험을 켠 경우 Android 필수 foreground-service 알림과 함께 수집한다.

### 당시 구현

1. **구현·S24 앱 복귀 조회 확인.** 전체 출처 Health Connect 걸음을 M15 시작 및 디버그 모드 시작 시각부터 각각 구간 집계한다. 조회 상태와 시각을 표시하고, 조회 실패 또는 `NO_DATA`를 실제 0걸음으로 단정하거나 보상 근거로 쓰지 않는다. 앱 복귀·화면 진입·수동 새로고침 시 조회한다. Samsung-only 데이터가 없더라도 전체 출처 값을 사용할 수 있다. 야외에서 실제 10걸음 이상 걷고 동기화되는 시점은 아직 확인하지 않았다.
2. **도메인 완료.** 게임 상태의 단일 writer에 디버그 모드 구간, 실제 걸음 최고 관측값, 가상 걸음, 지급한 10걸음 단위를 저장한다. 지급 단위와 잔액은 한 번에 저장하며 실제 걸음 재관측과 앱 재실행 뒤 재지급하지 않는다. OFF 뒤에도 켜져 있던 구간의 미동기화 실제 걸음은 종료 시각까지 다시 조회해 정산한다. 이 최종 조회는 반드시 `[StartedUtc, EndedUtc]` 구간만 요청해 OFF 이후 걸음을 제외해야 한다. 켜기 전 걸음은 소급하지 않는다.
3. **구현·S24 화면 확인 완료.** 설정에 모드 토글, 모드 ON 때만 `+1` 버튼, 실제/가상/합계/다음 보상 진행 표시를 추가했다. M15 바로가기와 일반 300·디버그 10걸음 진행 표시를 추가했다. 가상 걸음은 Health Connect에 쓰지 않는다.
4. **구현·S24 전경 알림 확인 완료.** 보상 준비 알림은 일반 알림 채널에 표시하고 탭하면 앱을 연다. 도메인은 M15 세션별 알림 마커를 원자적으로 한 번만 커밋한다. M15 완료·포기 시 대기 작업과 알림을 취소한다. 백그라운드 판정은 지원/권한이 있을 때 15분 주기의 WorkManager + Health Connect 읽기로 수행하고, 나머지는 앱 복귀 조회로 보완한다. Kotlin은 건강 조회·알림만 담당하며 영양제 저장본은 수정하지 않는다. S24에서 백그라운드 건강 데이터 읽기 권한은 미허용 상태여서 화면을 끈 채 WorkManager로 알림이 생성되는 동작은 미검증이다.

### 당시 멘토링 시연 순서 — 현재 절차 아님

1. S24에는 최종 APK가 `adb install -r`로 설치돼 있다. 앱을 열고 설정에서 Health Connect 걸음 읽기와 알림 권한이 유지되는지 확인한다. 오늘 사용한 M15 회차는 이미 완료했으므로, 내일 일일 회차 갱신 이후 새 M15를 시작한다.
2. 설정에서 **Trial Off** 상태를 유지하고 **걸음 디버그 ON**을 켠다. 기본 백그라운드 가속도 수집은 필요하지 않다.
3. **오늘의 활동 → 자유 선택 → M15 걷기 → 시작**으로 들어간다. 목표 10걸음과 실제·가상 걸음 표시를 보여준다.
4. 밖에서 10걸음 이상 걷고 앱으로 돌아와 **걸음 다시 조회**를 누른다. Health Connect 동기화가 늦으면 설정의 **가상 걸음 +1**로 합계 10을 만들어 영양제 1개 적립을 보여준다. 가상 걸음은 Health Connect 데이터가 아니다.
5. M15 화면에서 **직접 완료 → 기록 건너뛰고 완료**를 눌러 별도 완료 보상 영양제 10개를 받는다. **영양제로 정원 가꾸기 → 기존 나무 성장 → 확정**으로 10개를 사용한다.
6. 여유가 있으면 최근 앱에서 앱을 제거한 뒤 다시 열어 진행과 잔액이 유지되는지, 걸음 조회가 다시 시작되는지 확인한다. 보상 준비 알림은 목표 달성 후 미완료 상태에서 세션당 한 번이며, Android 백그라운드 작업의 실행 시각은 보장되지 않는다.
