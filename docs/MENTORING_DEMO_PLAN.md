# 멘토링 데모 단기 계획 (2026-09-29)

상태: 구현·로컬 검증 및 S24 핵심 흐름 실기기 확인 완료. 내일 야외에서 실제 걷기와 화면 꺼짐 상태의 Health Connect 동기화는 추가 확인이 필요하다. 목표는 멘토링 참고용 동작 데모이며 릴리즈 준비나 보상 밸런스 승인이 아니다.

`LocalGardenState` 도메인에 디버그 걷기 구간, 실제 걸음 최고 관측값과 가상 걸음 합산, 10걸음 단위 영양제 적립, 모드 ON/OFF, M15 진행 및 알림 완료 마커를 반영했다. 기존 schema-1 XML에서 새 디버그 구간 필드가 빠져 있어도 읽을 수 있다. `scripts/test-local-state.sh`는 318개 synthetic 상태 검증을 통과했다. Unity APK와 MOCK 미리보기를 확인했고, S24에서 앱 복귀 시 Health Connect 조회·보상 알림·M15 완료·정원 구매를 확인했다.

## 목표와 확정된 동작

- 일반 모드의 M15 걷기 목표는 300걸음이다. Health Connect 동기화가 늦어도 직접 완료할 수 있고, 기존 완료 보상 영양제 10개는 하루 회차당 한 번 유지한다.
- 개발 빌드의 디버그 모드는 기본 OFF이다. ON 이후 실제 걸음과 설정 화면의 `가상 걸음 +1`을 합산해 10걸음마다 영양제 1개를 미션과 관계없이 지급한다. M15 완료 보상 10개는 추가로 유지한다. 디버그 모드의 M15 표시 목표는 10걸음이다.
- M15 목표에 도달했으나 직접 완료하지 않은 경우 `미션 보상을 받을 수 있어요` 알림을 세션당 한 번 보낸다. 디버그 영양제 자동 적립 때마다 알리지 않는다.
- 일반 앱 실행에서 48시간 가속도 실험을 자동 시작하지 않는다. 기존 자동 실험은 종료하고 그래프 이력은 보존한다. 명시적으로 실험을 켠 경우 Android 필수 foreground-service 알림과 함께 수집한다.

## 구현

1. **구현·S24 앱 복귀 조회 확인.** 전체 출처 Health Connect 걸음을 M15 시작 및 디버그 모드 시작 시각부터 각각 구간 집계한다. 조회 상태와 시각을 표시하고, 조회 실패 또는 `NO_DATA`를 실제 0걸음으로 단정하거나 보상 근거로 쓰지 않는다. 앱 복귀·화면 진입·수동 새로고침 시 조회한다. Samsung-only 데이터가 없더라도 전체 출처 값을 사용할 수 있다. 야외에서 실제 10걸음 이상 걷고 동기화되는 시점은 아직 확인하지 않았다.
2. **도메인 완료.** 게임 상태의 단일 writer에 디버그 모드 구간, 실제 걸음 최고 관측값, 가상 걸음, 지급한 10걸음 단위를 저장한다. 지급 단위와 잔액은 한 번에 저장하며 실제 걸음 재관측과 앱 재실행 뒤 재지급하지 않는다. OFF 뒤에도 켜져 있던 구간의 미동기화 실제 걸음은 종료 시각까지 다시 조회해 정산한다. 이 최종 조회는 반드시 `[StartedUtc, EndedUtc]` 구간만 요청해 OFF 이후 걸음을 제외해야 한다. 켜기 전 걸음은 소급하지 않는다.
3. **구현·S24 화면 확인 완료.** 설정에 모드 토글, 모드 ON 때만 `+1` 버튼, 실제/가상/합계/다음 보상 진행 표시를 추가했다. M15 바로가기와 일반 300·디버그 10걸음 진행 표시를 추가했다. 가상 걸음은 Health Connect에 쓰지 않는다.
4. **구현·S24 전경 알림 확인 완료.** 보상 준비 알림은 일반 알림 채널에 표시하고 탭하면 앱을 연다. 도메인은 M15 세션별 알림 마커를 원자적으로 한 번만 커밋한다. M15 완료·포기 시 대기 작업과 알림을 취소한다. 백그라운드 판정은 지원/권한이 있을 때 15분 주기의 WorkManager + Health Connect 읽기로 수행하고, 나머지는 앱 복귀 조회로 보완한다. Kotlin은 건강 조회·알림만 담당하며 영양제 저장본은 수정하지 않는다. S24에서 백그라운드 건강 데이터 읽기 권한은 미허용 상태여서 화면을 끈 채 WorkManager로 알림이 생성되는 동작은 미검증이다.

## 검증 및 제한

- 도메인 확인 완료: `scripts/test-local-state.sh` — 318개 synthetic 검증. 실제+가상 합산, 10걸음 적립, 반복 관측·재실행, 저장 실패 원자성, ON/OFF 뒤 종료 구간 재정산, 구버전 XML, M15 완료 보상 10개와 알림 마커 1회.
- Unity 로컬 미션 검증: `scripts/test-local-loop-unity.sh` — 15 통과, 0 실패. 추가 검증은 M15 가상 10걸음으로 영양제 1개, 직접 완료 후 총 11개, 정원 성장 구매 후 잔액 1개를 확인한다. `scripts/preview-local-loop.sh` — MOCK 화면 30장 생성. [M15 디버그 화면](../artifacts/local-loop/visual/m15-debug-900x1600.png)은 10걸음 목표·가상 7걸음을 보여준다.
- Unity Android 개발 APK 빌드 성공: [APK](../artifacts/mentoring-20260929/capstone-mockup.apk), [최종 빌드 로그](../artifacts/mentoring-20260929/unity-android-build-final.log). SHA-256 `976cf1e777219b69e6b6dccd7c18a0b399bad008f26ecefb17c6f6c042a370ea`. Android 플러그인은 별도 AGP 9.0.0 / Gradle 9.1.0 하네스에서 `assembleDebug` 통과했다.
- S24 실기기 확인(2026-09-29): `adb install -r`로 기존 데이터를 보존하고 설치했다. 설정에서 Health Connect 전체 출처 걸음과 Samsung Health 연동이 AVAILABLE로 표시됐다. 디버그 ON 후 가상 걸음을 10회 추가하자 실제 걸음과 합산되어 10걸음 단위 영양제가 지급됐다. M15 목표 도달 후 미완료 상태에서 보상 알림 한 건이 게시됐다. ‘최근 앱’에서 앱을 없앤 뒤 프로세스가 종료됐지만, 재실행 시 M15 진행과 영양제 잔액이 복원됐고 Health Connect 조회가 재개됐다. [목표 달성 화면](../artifacts/mentoring-20260929/s24/m15-after-recents.png), [완료 화면](../artifacts/mentoring-20260929/s24/m15-completed.png), [정원 구매 화면](../artifacts/mentoring-20260929/s24/garden-purchased.png). 직접 완료로 영양제 6→16개, 나무 성장 확정으로 16→6개를 확인했다. M15 알림은 완료 뒤 활성 알림·예약 저장본에서 제거됐다.
- 남은 확인: 내일 S24를 들고 실제로 걸어 Health Connect 반영 시점, 화면 꺼짐 상태 및 ‘최근 앱’ 제거 후의 주기적 백그라운드 읽기(해당 권한 허용 시), 장시간 배터리 소모를 관찰한다. 이번 짧은 실기기 점검으로 백그라운드 센서 수집이나 하루 배터리 지속시간을 검증한 것은 아니다. A7의 `+1`·알림 검증도 미실시다.
- 늦게 동기화된 걸음: OFF 뒤 닫힌 구간은 저장된 시작·종료 시각으로 순환 재조회한다. 자동 조회는 닫힌 구간 한 건을 5분마다 확인하고, 앱 복귀·수동 새로고침·OFF 직후에는 즉시 한 건을 확인한다. 구간이 많으면 한 바퀴에 `구간 수 × 5분`까지 걸릴 수 있다. Health Connect 조회 최대 구간은 30일이므로 30일을 넘겨 켜 둔 단일 디버그 구간은 후속 분할 조회가 필요하다.
- Health Connect 기기 걸음은 보통 분 단위로 기록되고 WorkManager의 주기 작업은 최소 15분이며 실행 시각이 정확하지 않다. 목표 직후 즉시 푸시를 보장하지 않는다. Android foreground service를 수동으로 시작하면 시스템상 알림을 숨길 수 없다.

## 멘토링 당일 시연 순서

1. S24에는 최종 APK가 `adb install -r`로 설치돼 있다. 앱을 열고 설정에서 Health Connect 걸음 읽기와 알림 권한이 유지되는지 확인한다. 오늘 사용한 M15 회차는 이미 완료했으므로, 내일 일일 회차 갱신 이후 새 M15를 시작한다.
2. 설정에서 **Trial Off** 상태를 유지하고 **걸음 디버그 ON**을 켠다. 기본 백그라운드 가속도 수집은 필요하지 않다.
3. **오늘의 활동 → 자유 선택 → M15 걷기 → 시작**으로 들어간다. 목표 10걸음과 실제·가상 걸음 표시를 보여준다.
4. 밖에서 10걸음 이상 걷고 앱으로 돌아와 **걸음 다시 조회**를 누른다. Health Connect 동기화가 늦으면 설정의 **가상 걸음 +1**로 합계 10을 만들어 영양제 1개 적립을 보여준다. 가상 걸음은 Health Connect 데이터가 아니다.
5. M15 화면에서 **직접 완료 → 기록 건너뛰고 완료**를 눌러 별도 완료 보상 영양제 10개를 받는다. **영양제로 정원 가꾸기 → 기존 나무 성장 → 확정**으로 10개를 사용한다.
6. 여유가 있으면 최근 앱에서 앱을 제거한 뒤 다시 열어 진행과 잔액이 유지되는지, 걸음 조회가 다시 시작되는지 확인한다. 보상 준비 알림은 목표 달성 후 미완료 상태에서 세션당 한 번이며, Android 백그라운드 작업의 실행 시각은 보장되지 않는다.
