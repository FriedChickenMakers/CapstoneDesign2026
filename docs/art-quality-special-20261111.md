## v01 검사 기대값 불일치 조사

`artifacts/mission-art-quality-20261111/v01/guided/report.json`의 7개 실패는 그림 크기에 관한 이전 검사식이었다. `git blame`으로 확인한 기존 커밋 `f4a8548`은 `WeekOneQuestDemo.GuidedFocusPractice.cs:154`에서 실습 중 하단 컨트롤 전체 높이 146을 확보하고 `KeepAnswersVisible`을 켠다. `BuildGuidedClock`의 타이머·돌아보기·너무 길어요 버튼 높이 합계가 146이다. 당시 검사 `AssertIcon`은 계속 P01/P03–P07에 86, P02에 100만 확보한다고 가정했다. 320×568·360×640의 기대값 차이 60/46은 각각 146−86/146−100과 일치한다. 390×844의 실패도 실습 화면 저장 실패 알림이 64 높이를 차지하는 상태에서 기존 검사 기대 280과 실제 236의 차이였다. 이번 그림 메쉬 변경이나 M 전용 `Stable*` 예약값 때문에 발생한 차이가 아니다.

`GuidedFocusValidation.cs`만 수정해 `Guided.PracticeHint`가 있는 실습 단계에서 146 높이와 화면 내 배치 계약을 확인한다. 그 외 단계의 86/100 예약값, 최대 280·최소 160 크기, 정상 안내 단계의 동일한 위치, 정중앙 피벗 검사는 유지한다. 실습에서는 `RevealRect` 없이 타이머·시작/일시정지·돌아보기·너무 길어요가 모두 마스크 안에 있고, 스크롤이 필요 없으며, 안내와 저장 실패/하단 탐색 영역을 침범하지 않는지 별도로 검사한다. 저장 실패와 재진입도 동일 검사를 수행한다. 런타임 레이아웃을 되돌리거나 모든 단계의 허용 크기를 낮추지 않았다. 수정 후 전체 실행 결과는 부모 작업의 v02 보고서로 확인해야 한다.
