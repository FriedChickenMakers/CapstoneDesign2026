# 로우폴리 식물의 입체감 개선

사용자가 제공한 해바라기 참고 이미지의 두툼한 꽃잎, 솟은 꽃 중심, 각진 잎을 메시 버전 6에 반영했다. 꽃 수와 성장 규칙은 유지하고, 실제 기하의 두께와 굴곡을 늘려 측면에서도 입체 형태가 보이게 한다.

## 형태와 배치

- 잎과 꽃잎은 두 개의 솟은 능선, 구부러진 끝, 닫힌 아랫면으로 구성한다. 한 장당 18개 삼각형이며 큰 면마다 독립된 법선을 사용한다. 기억 잎에도 같은 입체 형태를 적용한다.
- 꽃잎의 기울기와 시작 높이를 번갈아 바꾸어 꽃 전체가 얕은 그릇 형태로 벌어진다. 해바라기는 꽃잎의 폭도 넓혔다.
- 꽃 중심을 꽃의 방향에 맞춘 다면체로 만들었다. 특히 해바라기의 갈색 중심을 높이고 면별 색 변화를 더했다. 기존 정원 조명과 그림자를 그대로 받는다.
- 국화형 꽃과 장미의 바깥 기울기는 34~42도다. 앞서 만든 꽃 배치 탐색이 두꺼워진 완성 형태를 사용하며, 8방향 중 가림이 가장 큰 방향의 벌점을 높였다. 종별 꽃 수, 기존 꽃의 성장 중 배치 유지, 공간 제한을 함께 지킨다.
- 배치 캐시 키에 메시 버전을 포함해 이전 형태와 새 형태의 계산 결과가 섞이지 않는다. 렌더러의 메시 버전 1~5 경로는 유지한다.

방울형 꽃의 기존 닫힌 입체 외형은 유지했다. 종별 꽃 구조와 저장된 식물 형질은 바꾸지 않으며, 참고 이미지는 공통 조형 방향으로 사용했다.

## 저장 자료와 기록 연결

새 주간 식물은 메시 버전 6으로 시작한다. 기존 주간 식물의 버전 4와 5는 다음 상태 로드에서 6으로 이관한다. 이관 전에 실제 메시 생성을 검증하고, 저장 실패 시 기존 파일을 유지한다. 이전 영양제 구매 방식의 보관 식물은 이관 대상에서 제외한다.

시드, 성장 횟수, 꽃 수, 감정 기록, 기억 잎 ID와 연결은 보존한다. 잎의 삼각형 범위는 새 기하에 맞춰 다시 계산하므로 두꺼워진 잎도 동일한 원본 기록을 연다.

## 검증

`PlantVolumeTests` 1,127개 검증을 통과했다. 닫힌 잎의 일관된 면 방향과 양의 부피, 측면 두께, 버전별 캐시 격리, 버전 5 저장 자료의 이관 및 저장 실패 처리를 검사한다. 12종의 0~21단계에 기억 잎 21개를 붙인 합성 표본에서는 최대 6,726삼각형으로 8,000 제한을 지켰다.

기존 생성기 56,253개와 종 미리보기 15개, 주간 식물 644개, Focus 활동 1,676개, 외형 이관 115개 검증도 통과했다.

배치 검증은 12종 × 100시드의 1,200개 식물로 확장했다. 25,200번의 성장 갱신과 8방향의 9,600개 전후 쌍에서 22,807개 검증을 통과했다. 기본 메시 최대값은 5,958삼각형이었다. [이전과 같은 꽃끼리의 가림 측정](FLOWER_SPACING_2026-11-04.md)에서 평균은 버전 4의 17.28%, 버전 5의 0.65%, 버전 6의 1.71%였다. 두께와 굴곡이 늘면서 버전 5보다 가림이 조금 늘었다. 이 수치는 꽃송이만의 CPU 투영 측정이며 잎·줄기·그림자를 포함한 화면 전체 가림이나 미적 선호 점수는 아니다.

Windows X64 / .NET 10.0.12에서 캐시가 있는 메시 생성의 중앙값과 95백분위는 2.29 / 4.75 ms, 캐시를 비운 최초 배치 계산은 33.88 / 68.65 ms였다. 최초 배치와 재사용 비용을 구분한 CPU 파일럿이며 Android 프레임 성능 수치가 아니다.

Unity 6000.3.24f1에서 같은 시드·카메라·조명으로 이전 버전 5와 버전 6을 비교했다. 대표 3종의 전후와 4방향, 기억 잎을 포함한 12종, 9개 성장 단계 이미지를 만들었다. 실제 정원의 잎 선택→기록→복귀, 회전·확대 유지, 보관 식물의 기록에서 해당 식물로 돌아오는 동작도 통과했다.

## 재실행과 결과 위치

```text
python3 scripts/test-weekly-plants.py PlantVolumeTests FlowerLayoutTests
python3 scripts/test-weekly-plants.py WeeklyPlantTests FocusMissionStateTests GardenPlantAppearanceTests
python3 scripts/test-procedural-plants.py
```

공통 QA 항목은 `plant-volume`과 `plant-volume-ui`다. 실제 Unity 이미지 생성은 그래픽을 켜고 `CapstoneDesign.EditorTools.WeeklyPlantValidation.PlantVolume`을 실행한다. 출력 경로는 `CAPSTONE_ARTIFACTS`로 지정한다.

로컬 합성 결과는 무시된 `artifacts/plant-volume-20261104/`에 보관한다. `volume-before-after.png`의 왼쪽이 버전 5, 오른쪽이 버전 6이다. `volume-multiview.png`, `volume-all-species.png`, `volume-growth.png`, `weekly-integrated-home.png`에 다른 각도·종·성장·실제 정원 화면을 담았다. 참고 이미지와 렌더링 원본은 저장소에 게시하지 않는다. Android 실기기의 프레임 시간은 이번 검증에 포함하지 않는다.
