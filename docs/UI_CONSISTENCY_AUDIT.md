## 2026-10-08 후속: 하단 메뉴 중앙 정렬과 보조 설명 축소

사용자 피드백에 따라 하단 메뉴를 고정 왼쪽 좌표 대신 `HorizontalLayoutGroup`으로 배치했다. 아이콘과 실제 글자 폭을 하나의 묶음으로 가운데에 놓으며, 선택 시 굵어진 글자 폭도 레이아웃에 반영한다. 세 탭 모두 같은 규칙을 사용하고 글자·아이콘 크기는 유지한다.

- 설정 건강 기록 카드의 고정 안내, 상태, 별도 갱신 설명을 상태 한 행으로 합쳤다. 권한·연결·로딩·조회 실패·갱신 지연·예시/재생 모드는 구분하고 마지막 확인 시각은 상태에 짧게 붙인다.
- 설정의 페이지 소개, 권한 설명, 중복 진단 설명을 제거했다. 수집 상태와 마지막 저장 시각을 합치고, 예외적인 중단 사유와 수집 주기·48시간·화면 꺼짐·배터리 안내는 유지한다.
- 정상 요청 성공 후 추가 설명 행이 계속 남지 않도록 했다. 오류·권한·미지원 피드백과 진단 로그는 보존한다.
- 오늘의 활동 메뉴 4개의 반복 설명을 없애고, ‘배운 활동 다시 하기’, ‘참여 기록과 나의 계획’처럼 제목에서 목적을 알 수 있게 했다. 메뉴 높이와 간격을 줄였으며 추천 주차와 중요한 참여 가능 상태는 유지한다.

산출물: `artifacts/tab-polish-20261008/`. `final/visual/` 114장과 `settings-modes/visual/`의 LIVE/REPLAY 합성 상태 12장, 총 126장을 세 해상도로 촬영했다. 텍스트 넘침 검사는 모두 0건이다. 높이 오차 1단위만으로도 Legacy Text가 한 줄을 숨기는 사례를 Vision으로 발견해 추천 주차 영역을 보완하고 검사 허용 오차도 줄였다. Editor에서 강제로 보이는 AutoHide 스크롤바는 촬영 시 실제 Play의 표시 조건을 적용한다.

Astra가 최신 원본 8장과 변경 소스를 검토해 중앙 정렬과 설명 축소가 사용자 요청을 충족한다고 확인했다. Play 모드의 버튼 터치 대상 검사, fresh/restore 저장 복원도 통과했다(`play.log`). `preview.png`에서 수정된 오늘의 활동과 설정을 함께 볼 수 있다. 실기기 설치·촬영은 이번 후속 작업에 포함하지 않았다.

## 2026-10-08: 홈 기준으로 활동·설정 통일

홈과 기존 탭이 서로 다른 Canvas 기준 크기를 사용하여, 같은 크기로 지정한 글자도 활동·설정에서 작게 보였다. 활동·설정을 홈과 같은 720 기준 프레임 및 Noto Sans KR로 맞췄다. 제목 46, 주요 버튼·카드 제목 34, 설명 26–28을 사용하며 자동 글자 축소를 없앴다. 900×1950 렌더에서 세 탭의 제목은 모두 57.5픽셀이다.

- 홈의 실제 하단 탐색을 세 탭이 공유한다. 선택 색상·아이콘·높이와 제목의 시작 위치가 같다.
- 오늘의 활동은 홈의 배경·녹색 주 버튼·밝은 카드 스타일을 사용한다. 긴 코스 제목과 선택지는 두 줄을 수용하며, 참여 기록은 제목과 처리 상태를 분리한다.
- 설정은 건강 기록, 앱 연결 및 권한, 가속도 수집 카드로 구분한다. 상세 진단은 접어서 표시하고, 원래 권한·건강 조회·수집 제어 동작을 유지한다.
- 글자를 줄이는 대신 본문을 스크롤한다. 스크롤 표시와 고정 입력 라벨을 두어 긴 안내와 입력에서도 크기를 유지한다.
- PatternFly의 관련 설정 그룹화, Carbon의 공통 정렬·간격, Pajamas의 주 행동 위계를 참고했다. 웹 컴포넌트를 Unity에 추가하지 않았다. 참고 링크는 아래 기존 자료 목록에 있다.

산출물은 `artifacts/tab-consistency-20261008/`에 있다. `final/visual/`은 홈·활동·설정, 실습·중단·회고·완료, 빈 기록·누적 기록·심박 기록, 경험 입력·계획, 긴 문구, 5주차 목록, 접힌/펼친 진단 등 38상태 × 3해상도 = **114장**이다. 해상도는 900×1950, 900×1600, 1200×800이다. `final/text-overflow.csv`의 표시 영역 내 텍스트 높이 초과는 0건이다. `tabs-comparison.png`는 세 탭을 나란히 비교한다.

`guidance/visual/`은 48개 활동 선택 화면과 전체 147단계의 상단·하단을 같은 세 해상도로 촬영한 **1,026장**이다. 이 검사에서도 표시 영역 내 텍스트 높이 초과는 0건이다. 최종 대표 화면과 전체 안내를 합쳐 1,140장을 보존했다. 수치 검사는 라벨 자체의 잘림을 검사하며, 서로 다른 요소의 겹침 여부는 별도 Vision 검토로 확인했다.

완료 점검에서 공통 화면 배율의 영향을 받는 나머지 흐름도 Sol high가 `CaptureRemaining()`으로 추가 촬영했다. `remaining/visual/`의 **102장**은 구매 가능·잔액 부족·기존 배치·확정·저장 실패, 동물 발견, 경험 목록·긴 기록, 실습 답변, 건강 조회 오류 및 LIVE/REPLAY 설정 상태 34개 × 3해상도다. 텍스트 높이 초과는 0건이며 대표 원본을 Vision으로 확인했다. 최신 UI 촬영의 최종 합계는 **1,242장**이다. LIVE/REPLAY 자료는 Editor의 합성 상태이며 실제 기기 수집 증거가 아니다.

Vision 검토로 긴 선택지의 마지막 단어 누락과 기록 버튼의 맞닿음을 발견해 수정했다. 최종 PNG에서 두 줄 선택지, 긴 5주차 제목, 기록 간격, 설정 끝부분, 가로 화면, 스크롤 표시 이동을 다시 확인했다. `scroll-metrics.csv`도 상단/하단에서 내용 위치와 스크롤바 값이 각각 1/0으로 일치함을 기록한다.

이 자료는 분리된 MOCK 저장소를 사용하는 Unity Editor 렌더다. Android 네이티브 심박 차트·시스템 권한 창·소프트 키보드·기기 safe area는 이번 UI 수정에서 재검증하지 않았다. 설정의 차트 버튼 캡처는 Editor 미지원 피드백이며, 활동 기록의 심박 그래프는 정확한 활동 구간의 합성 기록이다. 실제 기기의 수집 데이터나 화면 설정은 이번 작업에서 변경하지 않았다.

기능 검증: Unity 편집 모드 23/23 통과, 최종 Play 모드 `fresh`와 `restore` 통과. 공유 하단 탐색, 화면 전환, 활동 완료·성장 구매·미리보기 복원, 재실행 후 저장 상태를 검증했다. 활동의 ‘추천 활동 안내’와 설정의 ‘심박 차트 보기’는 실제 화면 좌표에서 EventSystem의 최상위 터치 대상이 해당 버튼인지 확인해 통과했다. 상세 진단을 접은 상태의 비활성 텍스트 조회도 보완했다. 로그는 `local-loop-validation.log`, `local-loop-play-final.log`에 있다. 재실행은 `scripts/preview-tab-consistency.sh`; 전체 활동 안내는 `CapstoneDesign.EditorTools.TabConsistencyCapture.CaptureGuidance`를 실행한다.

Android IL2CPP 개발 APK 빌드도 성공했다. 결과는 `build/capstone-mockup.apk`, 빌드 로그는 `android-build.log`, 해시는 `build/sha256.txt`에 있다. 이번 수정본은 실제 기기에 설치하지 않았다.

### Astra 최종 검토

2026-10-08, 사용자 요청에 따라 GPT-6 Astra가 수정된 런타임 6개 파일, 촬영·Play 검증 코드와 결과, 원본 PNG 18장을 독립 검토했다. 홈·활동·설정의 세로/가로 화면, 긴 선택지·제목·입력 안내, 5주차, 누적 기록·회고·심박 기록, 접힌/펼친 설정, 마지막 주차 실습을 Vision으로 확인했다. 판정은 **문서에 명시한 Editor 검증 범위에서 blocking finding 없음**이다. 글자 크기·공통 탐색·설정 콜백 유지, 긴 문구와 기록 버튼의 간격을 확인했다.

검토는 원본 전체의 수동 검사가 아닌 대표 이미지 표본 검토다. Android 네이티브 차트·시스템 권한 창·키보드·물리 기기의 safe area는 검증하지 않았다. 편집 모드 검증의 수동 생명주기 호출에서 Unity `ShouldRunBehaviour()` assertion이 있으나, 실제 Play의 fresh/restore 실행에는 이에 대응하는 예외가 없음을 구분했다.

추가 촬영 후 Astra가 구매·성장·발견·기록·권한 거부·LIVE/REPLAY 설정의 원본 10장을 다시 검토했다. 독립 Vision 검토 표본은 총 **28장**이며, 새 blocking finding 없이 최종 통과 판정을 유지했다. 추가 작업은 Editor 촬영 코드와 문서뿐으로, 검토한 런타임 및 APK는 동일하다.

완료 점검에서 PNG 1,242개의 실제 파일과 PNG 해상도를 manifest와 대조했고, APK SHA-256 및 최신 런타임 변경 이후 빌드되었음을 확인했다. 이전 기기 작업의 화면 꺼짐·밝기 복구 기록도 모두 `restored=true`다.

## 촬영 범위와 증거

산출물 루트: `artifacts/ui-consistency-20261006/`.

- `before/local-loop/visual/`: 홈·성장 단계·활동·설정·방문자·심박 기록·권한 거부·미지원·조회 실패·저장 실패 23상태 × 3해상도 = 69장.
- `before/mbct/visual/`: MBCT·경험 기록·계획·돌아보기·완료·구매 미리보기 대표 22상태 × 3해상도 = 66장.
- `before/expanded/visual/`: 48개 활동의 전체 147단계, 활동 선택 화면, 8주 목록, 빈 목록, 상점·잔액 부족, 입력 모드 등 226상태 × 2해상도 = 452장.
- 대표 해상도는 900×1600, 900×1950, 1200×800. 전체 단계는 900×1600와 1200×800.
- 상태별 목록은 `before/expanded/capture-manifest.csv`, 실제 렌더러는 각 suite의 manifest 및 `environment.txt`에 기록한다.
- 수정 전 총 587장 중 설정 LIVE/REPLAY 4장은 Editor의 조기 반환 때문에 MOCK 표시가 갱신되지 않았다. 이 4장은 해당 모드의 유효한 증거로 사용하지 않는다. 수정 후에는 표시 갱신을 명시적으로 수행한다.
- 수정 후 `after/`의 주 촬영 세트는 615장(69 + 66 + 480)이다. 구매 가능·이미 보유·저장 실패, 직접 입력·감정 선택·경험 기록 단계 등 28장을 추가했다. 설정 수정 확인용 6장 재촬영 자료는 `after/targeted-settings/`에 별도 보존하고 최종 원본에도 반영했다.
- `contact-sheets/`는 화면들을 비교하는 검토용 모음이다. 원본 PNG는 각 suite의 `visual/`에 보존한다. `index.html`에서 615개 화면·해상도 조합을 검색하고 전후 비교할 수 있다.

MOCK 저장소와 합성 시각을 사용하는 Unity Editor 렌더다. 실제 사용자 저장 파일을 수정하지 않는다. ADB 연결 기기가 없어 Android 시스템 권한 창, 네이티브 심박 차트, 소프트 키보드·접근성 서비스와 기기별 safe area는 이번 실행에서 확인하지 않았다. LIVE/REPLAY 표시는 Editor의 공급자 상태 검증이며 실제 센서 작동 증거가 아니다. 임의 사용자 입력·모든 기기 조합까지 전수 검증했다는 의미가 아니다.

| 경험 종류 중 첫 두 항목이 선택 전부터 선택색으로 표시됨 | 네 항목을 같은 기본 상태로 표시한다. |

| 일반 활동 기록에 `PERMISSION_DENIED` 등 구현 코드만 노출됨 | 권한 확인·지원 여부·재조회 등 상태별 한국어 안내를 표시한다. 조회 미완료와 기록 없음의 구분은 유지한다. |
| 활동 완료 화면에서 다음 행동의 강조가 없음 | ‘정원으로’를 주 행동으로 표시한다. |

## 참고 자료의 적용 판단

- [PatternFly Page](https://www.patternfly.org/components/page/)의 본문 영역 구분과 [Form 지침](https://www.patternfly.org/components/forms/form/design-guidelines/)의 일관된 라벨·사라지지 않는 안내 원칙을 적용했다. 이 앱의 기존 하단 탐색과 모바일 구조를 유지한다.
- [Carbon 2x Grid](https://carbondesignsystem.com/elements/2x-grid/overview/)의 8단위 간격 원칙을 새 필드 내부 여백과 최대 본문 폭에 반영했다. 기존 전체 비율 레이아웃을 8px 고정 그리드로 재작성한 것은 아니다.
- [GitLab Pajamas Button](https://design.gitlab.com/components/button/)의 행동 위계와 바깥쪽 주 버튼 배치 원칙을 확인·취소와 완료 후 이동에 반영했다.
- 제공된 [Atlassian navigation layout](https://atlassian.design/components/navigation-system/layout/code)은 본문을 직접 가져오지 못했다. 공식 [Panel 사용 지침](https://atlassian.design/components/panel/usage)의 주 콘텐츠·보조 작업 영역 분리를 참고했으며 사이드 패널을 새로 추가하지 않았다.
- [Radix Accordion](https://www.radix-ui.com/primitives/docs/components/accordion)의 펼침·키보드 동작을 검토했다. 현재 Unity 앱에는 Recipe/Plugin 아코디언이 없어 직접 적용할 컴포넌트가 없다. 웹 라이브러리를 새로 도입하지 않았다.
