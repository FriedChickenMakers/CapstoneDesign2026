# 식물 사진첩 · 2026-11-05

> 이 문서는 사진첩 최초 구현 당시의 계약과 검증 기록이다. 이후 확정된
> [11월 7일 미션 코인과 식물 메모](ALL_MISSIONS_AND_COURSES_2026-10-29.md#2026년-11월-7일-미션-코인과-식물-메모)가 성장·재화 정책을 대체한다.

> 메모는 식물과 함께 사진첩에 보존된다. 빈 화분에서는 새 씨앗을 먼저 심어야 미션을 시작·재개할 수 있다.
> 정원에 남아 있는 완성 식물의 초과 성장과 과거에 보관한 성장은 새 식물에 적용한다.

## 확정한 범위와 진행 순서

이번 요청은 이전의 정원 다중 배치를 대체한다. 정원에는 성장 중인 식물을 최대 한 개 두고,
완성 식물을 **식물 사진첩**에 보관하면 정원에는 빈 화분만 남는다.
사용자가 `새 식물 키우기`를 누르면 별개의 새 씨앗을 무료로 시작한다.
진입점은 **내 과정 → 정원·건강 기록 바로 아래의 식물 사진첩**이다.
목록은 사진 썸네일, 상세는 저장 당시 식물을 회전·확대하는 읽기 전용 관람이다.
보관 식물은 화분 대신 잔디 위에서 보여 주며 정원과 같은 시간의 하늘을 사용한다.
시간에 따라 조명·하늘만 바뀌고 저장된 식물의 씨앗·외형·성장은 바뀌지 않는다.

1. 기존 단일 저장에 명시적 완료 상태와 개체별 사진 스냅샷을 추가한다.
2. 저장/실패/재시도/중복 명령 계약을 기존 원자 저장에 연결한다.
3. 목록·상세 UI와 필요할 때만 렌더하는 공용 미리보기 자원을 연결한다.
4. 합성 상태 단위 검사, Unity 컴파일·화면/입력 검증, 기존 관련 회귀를 실행한다.

성장 담당자가 별도로 1주·약 21미션/21단계 및 기간에 의한 조기 완성을 구현한다.
후속 사용자 결정으로 **최대 절차 성장 단계(`Recipe.Mature`)에 도달하면 반드시 완료**다.
낮은 단계에서도 기간 조건으로 `IsCompleted`를 설정하는 연결은 유지한다. 완료된 식물은
영양제로 더 성장시킬 수 없고, 성장 버튼은 안내와 함께 `사진첩으로 이동`으로 바뀐다.
이 변경은 1주·21단계 성장 정책을 구현하지 않는다. 다음 씨앗은 사진 저장 후 빈 정원에서
사용자가 버튼을 눌러 생성하며 자동 생성하거나 영양제를 차감하지 않는다.
정원 다중 배치·자유 배치·도감 복제·사진 삭제/내보내기 역시 이번 범위가 아니다.

## 데이터와 담당자 연결 계약

- 현재 식물의 `GardenPlantAppearance.IsCompleted`가 저장 가능한 완료 여부다.
  최대 단계 도달 시 자동으로 `true`가 저장된다. 이전 저장에 필드가 없거나 `false`여도
  최대 단계 식물은 열기 과정에서 완료 상태로 이관한다. 낮은 단계는 임의로 완료하지 않는다.
- 식물 종류는 `Recipe.SpeciesId`, 개체는 `Recipe.InstanceId`다. 기존 `garden-main`은
  그대로 보존한다. `StartNewPlant`는 새로운 영속 개체 ID를 부여한다.
  같은 종류여도 ID를 재사용하지 않으며 새 개체의 `IsCompleted`는 `false`로 시작한다.
- 성장 담당자는 조건 충족 시 `GardenStateService.SetPlantCompleted(instanceId, true)`를
  호출한다. 직접 파일 쓰기나 `Snapshot` 수정은 저장을 대신하지 않는다.
  이 호출은 현재 개체 ID를 검증하고 기존 상태 저장 트랜잭션으로 bool을 기록한다.
  최대 단계 식물을 `false`로 되돌릴 수 없다. 완료 여부는
  `GardenPlantVisuals.IsCompleted(state)`로 확인하며 완료 후 영양제 성장 명령을 거절한다.
- 현재 성장 레시피를 21단계로 바꾸는 작업은 `GardenPlantVisuals`의 기존 성장 매핑과
  검증도 함께 변경해야 한다. 사진첩은 단계 숫자를 하드코딩하지 않고 명시적 완료와 `Recipe.Mature`를 확인한다.
- `SavePlantPhoto(requestId, instanceId)`는 사용자의 명시적인 사진 저장 동작이다.
  미완성·다른 현재 개체를 거절하고, 최초 저장의 레시피·성장값·표시 배율·종 이름·시각을
  깊은 복사해 `GardenState.PlantPhotos`에 보존한다. 활동/감정 원문은 복제하지 않는다.
- 같은 개체는 사진 한 장만 보관한다. 재시도와 연속 누름으로 새 복사본을 만들거나
  이미 저장한 외형을 덮어쓰지 않는다. 같은 요청 ID를 다른 개체에 재사용하면 거절한다.
- 사진 추가와 현재 개체의 `IsArchived=true`를 한 번의 원자 저장으로 반영한다.
  현재 개체의 레시피는 이관·재시도 검증용으로 남지만 `HasCurrentPlant(state)`는 false이고
  정원에서는 식물 모델을 제거해 빈 화분만 렌더한다. 현재 존재 여부를 Recipe의 null로 판단하지 않는다.
- 기존 저장에서도 사진에 현재 개체 ID가 있으면 보관 상태로 이관한다. 저장 실패 시에는
  사진 추가와 정원 비우기 모두 커밋하지 않으며 기존 식물을 그대로 유지한다.
- `StartNewPlant(requestId, archivedPlantInstanceId)`는 예상한 보관 개체와 빈 정원을 확인한다.
  시작 명령 원장과 새 개체를 함께 저장한다. ID/seed는 설치 ID·보관 개체·요청 ID로 안정적으로
  생성하며 이전 개체와 다르다. 이전의 저장·시작 명령 재시도는 새 식물을 지우거나 다시 만들지 않는다.
- 새 개체는 `UsesIndividualGrowth/IndividualGrowth`로 독립적인 0단계부터 시작한다.
  기존 `LegacyGrowth`, `Plants`, 성장·미션·보상·재화 기록을 초기화하지 않는다.
  새 성장 기록에는 `PlantInstanceId`를 남기며 이전 활동의 키는 새 외형 집계에서 제외한다.

## 책임과 실패 처리

`GardenStateService`가 완료/저장 명령의 규칙과 원자 변경을 소유한다.
`StateCodec`은 사진과 명령 원장을 검증·깊은 복사한다. 기존 `FileStateStore`의
writer 잠금, 체크섬, 임시 파일 flush/교체, 백업 보존 계약을 그대로 사용한다.
별도 지갑·독립 식물 저장 파일·자동 백업 롤백을 만들지 않는다.

`WeekOneQuestDemo.PlantAlbum`은 탐색·사용자 입력·저장 결과를 표시한다.
실패하면 화면에서 재시도할 수 있고, 저장 성공 전에는 저장 완료로 표시하지 않는다.
미션 기록 초기화에도 사진첩과 완료 상태는 정원 상태로 보존한다.

`GardenPlantPhotoView`는 저장본의 복사본만 렌더한다. 기존 정원 카메라를 변경하지 않고
사진첩 전체가 공용 offscreen 카메라 한 개를 필요할 때만 사용한다. 썸네일은 최대
256px, 상세는 최대 768px이며, 식물마다 카메라나 계속 살아 있는 메시를 만들지 않는다.
화면 이탈 시 이미지와 공용 메시·재질·렌더 자원을 해제한다. 화면은 2열/페이지 단위로
나누어 보관량이 늘어도 한 번에 만드는 이미지 수를 제한한다.
잔디는 식물의 난수와 독립적인 공용 메시다. `GardenSkyEnvironment.EvaluateTime`과
`ConfigureSkyMaterial`을 정원과 공유하고, `GardenVisualClock`의 설정/현재 시간을 따른다.
시간이 바뀌면 보이는 이미지의 조명과 하늘을 다시 렌더하며 식물 메시를 재생성하지 않는다.

이후 사진첩 기본 시점을 8도로 조정하여 잔디와 하늘을 함께 보이게 했으며,
`editor-10/report.json`에서 사진첩/자원 13개 검사군과 클릭/레이캐스트 59회를 다시 통과했다.
이번 재검사는 관련 13개 검사군만 실행했고, 기존 회귀 및 Release 컴파일 결과는 `editor-09`에 있다.

360×640 및 390×844의 빈 상태·저장 실패·목록·상세·13개 사진 페이지 전환을
캡처하고 확인했다. 두 손가락 확대 후 한 손가락 회전, 작은 RawImage 영역,
화면 이탈 시 자원 해제, 렌더 텍스처 유실 후 재생성, 정원 렌더 상태 복원을 검사했다.
보관 후 빈 상태·새 개체 시작의 실제 버튼 진입/실패/재시도, 낮·밤 잔디와 하늘,
낮은 단계 식물의 최대 상향 회전+최대 축소 화면도 확인했다. 잔디 아래로 내려가던
시점 하한과 하단에 지면 끝이 보이던 범위를 보정했다.

초기 검사에서 발견한 EditMode 자원 정리를 보완했다. 기존 LocalLoop 검사도 이미 열린
MockupMain 씬을 재사용하던 fixture를 별도 preview scene으로 고쳤다. 초기 실패 결과는
`editor-01`~`editor-03`에 남겨 두었고 최종 통과 결과로 덮어쓰지 않았다.
새 순환 검사의 `editor-07`은 숨긴 활동 패널로 직접 진입한 시험 경로와 기존 카메라를
이름만으로 찾는 전역 검색 때문에 3개 검사군이 실패했다. 실제 내비게이션으로 고친 뒤
`editor-08`, `editor-09`는 통과했다. 검사 시작 전에 남아 있던 비활성 Editor 카메라 1개를
보고서에 따로 기록했으며, 이번 실행 중 새 카메라가 최대 1개이고 종료 후 남지 않음을
실제 Unity 객체 ID로 검사했다. 과거 잔재는 이번 구현에서 발생한 것으로 단정하지 않는다.

`play-06/play-report.json`은 실제 MockupMain의 첫 실행과 이후 두 번의 재시작에서 68개 단언,
26회 클릭/레이캐스트를 통과했고 런타임 오류는 0개다. 마지막 성장의 실제 파일 저장 실패를
주입한 뒤 재시도해 완료와 한 번의 10개 차감을 확인했다. 사진 저장 후 사진 4개·빈 화분·
영양제 90개·기록이 첫 재실행에서 정확히 복원됐다. 정원의 `새 식물 키우기` 버튼에서 실제
파일 쓰기를 실패시킨 뒤 재시도하여 별개의 새 씨앗을 무료 생성했다. 새 식물의 첫 성장만
진행하고 10개를 차감했으며, 두 번째 재실행 후 사진 4개·새 개체/씨앗·성장 0.1·영양제 80개·
과거 기록이 일치했다. 관람·확대·정원 복귀에도 저장 상태와 원래 카메라 출력이 유지됐다.
종료 시 사진첩 메시·렌더 텍스처·공용 카메라가 해제되고 시험 환경 변수가 원복됐다.
이번 실행은 새로운 `play-06/synthetic-save`를 사용했다. 편집용 기즈모가 씨앗을 가리지
않도록 검증 중에만 GameView의 원래 표시 설정을 보존하고 숨겼으며, 종료 시 두 설정의
복원도 확인했다(`gizmosRestored=true`). 새 씨앗이 보이는 실제 캡처를 다시 확인했다.
앞선 `play-05`도 기능 검증은 통과했지만 씨앗 캡처에 Editor 기즈모가 표시되어 별도로 남겼다.

`play-04`는 두 번째 실행의 버튼 검색 대상을 Presenter가 붙은 Canvas로 잘못 지정해
중단됐다. 실제 버튼이 있는 별도 `homeCanvas`를 찾도록 검증 코드를 수정했다.

`play-01`에서는 기능 단언이 통과했지만 기존 정원 텍스트의 빠른 Awake가 TMP 자체
CanvasRenderer 캐시 초기화 전에 외곽선을 설정하는 예외가 발생했다. 그 경로를 최소 수정하고
Play 검사에 전체 실행 중 오류/예외 수집을 추가했다. 이후 검사는 오류 수집을 계속 유지한다.
Play 도중 사진첩 검사를 위해 실제 사용자 저장을 열거나 바꾸지 않았으며 씬 파일도 변경하지 않았다.

### 후속 요청: 설정에서 시험 영양제 추가

`설정 → 테스트 도구 → 정원 테스트 → 영양제 100개 추가`를 추가했다. 명시적인
클릭마다 100개를 기존 `GardenStateService.Change`로 저장하며 보유량과 성공/실패를
표시한다. 식물·사진·성장·미션·보상 원장은 바뀌지 않는다. 정기 표시 갱신은 scalar 잔액을
읽어 저장 전체를 복제하지 않는다. UI, 컨트롤러, 지급 함수 모두 Editor/개발 빌드 전용이다.

`scripts/test-local-state.ps1`로 출시 구성 325개, 개발 구성 348개 단언을 통과했다.
실패 후 재시도, 클릭당 정확히 100개, 오버플로 방지, 파일 재열기와 다른 저장 데이터 보존을
검사했다. 로그는 `artifacts/nutrient-test-tools-20261105/unit/local-state-01.log`다.
Focus 통합의 새 검사군은 360×640/390×844에서 실제 버튼과 실패/성공 표시·재진입을
검사했다. 두 화면의 `settings-test-nutrients-*.png`를 직접 확인했다. 출시용 실제 어셈블리에서
설정 콜백뿐 아니라 컨트롤러와 서비스의 `AddTestNutrients`도 없는 것을 확인했다.

### 남은 연결과 한계

완성 조건에 관한 추가 사용자 결정은 없다. 최대 단계는 자동 완료하며, 성장 담당자는
최대 단계에 도달하지 않은 식물이 기간/미션 조건으로 완성될 때
`SetPlantCompleted(currentInstanceId, true)`를 호출한다. 현재 12단계 성장 매핑은
유지되며, 사진 저장본 검증은 21단계 등 유효한 레시피도 받아들인다.
다음 식물은 사진에 보관한 뒤 사용자가 무료 시작 버튼으로 생성한다. 추가 결정은 없다.

전체 EditMode 테스트 모음, 실제 열린 씬을 재사용하는 DemoPolish 하네스, Android APK 설치·실기기 터치 및 GPU/메모리 성능 검사는
실행하지 않았다. 연결 기기의 데이터와 설정은 접근하지 않았다. Editor 측 프레임 시간은
Android 성능 근거로 사용하지 않는다. 구버전 앱은 새 사진 필드를 알지 못하므로 새 저장을
구버전 앱에서 다시 저장하는 다운그레이드 호환은 보장하지 않는다.
야간의 작은 새싹 썸네일은 낮보다 대비가 낮다. 상세 화면에서 회전·확대해 관람할 수 있다.
